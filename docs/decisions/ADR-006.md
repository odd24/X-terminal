# ADR-006 串口底层候选与控制线边界

- 日期：2026-11-03（Asia/Shanghai）
- 状态：PROPOSED（未做驱动收发/控制线实测）
- 关联：P05/P10、R03/R12

## 候选与决定

| 候选 | 本步证据 | 许可/成本 |
|---|---|---|
| serialport 4.10.1 | Windows MSVC 构建、原生枚举通过；底层字节处理 5 项逻辑测试 | MPL-2.0，分发时按许可处理所修改文件；阻塞 I/O 需隔离工作线程 |
| tokio-serial/mio-serial | 未做本机原型 | 异步集成候选，Windows 取消/驱动行为仍需测 |
| 直接 Win32 COM API | 已通过候选源码了解 DCB/开关路径，未自建实现 | 可更精细控制，需自行维护错误、句柄和取消逻辑 |

先用 serialport 建立最小候选，关闭 Linux libudev 默认特性（本期目标 Windows），不将阻塞 I/O 放入未来 UI 或 Tokio 主事件循环。独立服务与有界队列将在 P07 后整合。

## 已知行为与约束

只允许显式 COM 数字标识，不接受任意设备/管道路径；波特率正数，最终是否支持由驱动决定。数据位 5/6/7/8、校验 None/Odd/Even、停止位 1/2、流控 None/Software/Hardware 是当前库枚举范围；Mark/Space、1.5 停止位未支持，P10 按设备需求决定原生扩展，不能声称全组合支持。

DTR 必须显式选择，RTS 在硬件流控时由驱动管理，其他情况必须显式给出状态。源码发现 Windows `COMPort::open` 对首次 DTR 设置采用 best-effort 并忽略错误；本候选追加一次同状态设置，只有调用成功才报告打开就绪。但 CreateFile/DCB/驱动打开期间是否产生脉冲尚未实测，不能承诺不会复位设备。运行中控制失败直接返回，不静默成功。

读/写每块最多 64 KiB；读取 0/超时表示 Idle，不编造远程退出码。写入返回驱动接受的字节计数；部分失败不回放整块、不等价于设备已执行。Interrupted 重试有上限。HEX 输入严格校验，原始字节与 CR/LF 不变；文本编码、换行选择/节奏与日志是 P10/P11 工作。

## 验证与回退

枚举发现一个 CH340 端口，但未指定它的用途和参数，因此未打开。无虚拟串口对，未安装驱动或系统服务；测试中的内存字节流不是 COM 环回。P05 保持 BLOCKED，真实驱动/设备验收未通过。

后续用指定的虚拟对/设备验证字节校验、流控、RTS/DTR/Break、占用、拔插、COM 号变化和取消读。候选不可用时替换适配实现并新增 ADR，不删除 SERIAL。revert P05 提交可移除本候选，无真实设备动作。
