# ADR-030 统一服务日志捕获与显式控制

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（捕获/启停阶段；历史读取/导出继续P11.4）
- 关联：P11.4、R12/R13/R15/R16、ADR-028/029、D04/D04.1

## 捕获入口

候选为桌面轮询导出、服务定时读取保留窗口、统一输出入口推送。选择第三者：前两者可能漏掉已覆盖字节并依赖消费者调度。Sessions可选挂接一个OutputCapture，只有CONNECTED可开始；在当前服务锁内取编码与原始/文本下一游标后立即挂接，不跨await、不回填历史。回调只做有界复制/try_send，不写盘；日志失败不让append失败，不反压传输。32排队+1在途及文件线程上限沿用ADR-029。

每个4096字节原始事件及对应派生TextEvent同时送往捕获器；源缺口同样记录，终态仅一次最终flush。CLOSING继续串口排空，断开/失败/移除/换代自动解除捕获；读保留输出、GUI清屏或重载不生成新日志。人工停止只切断后续捕获，已排队前缀继续落盘，不强制flush连接的解码状态，不影响后续终端输入/输出。另一份旧日志的Stop不得解除新capture_id。

窗口按服务输出游标划分，不承诺等于物理串口接收时刻。中途开始可能缺失字符/ANSI前缀，UI必须显示范围；数据/文本/screen/独立exec任务/认证/审计不混流。当前只记录终端输出，exec和操作来源审计仍由后续对应步骤实现。

## 控制、身份与容量

新增严格logging/start/list/status/stop命令族，全族只允许active Desktop，Observer即使有该连接read票据也不能管理或枚举日志。调用者只提供ConnectionRef/request_id/限额/log_id，不接受路径、编码或自赋角色。Start只接受当前CONNECTED代次，相同request_id和参数返回原log_id及当前状态，冲突拒绝；重连不会继承捕获，重试旧Start不会新建文件。Status/Stop核对日志自身完整ConnectionRef，历史标识不重定向新代次或新记录。

日志根从持有配置目录所有权的服务工作线程取得，在阻塞线程上创建受管理terminal-logs并逐级pin/枚举；目录故障拒绝启动，不覆盖配置。持久UUID目录最多64，本次服务日志注册/Start回执也最多64；统计目录时合并尚在OPENING、还未创建目录的注册项，防止并发越界。满额拒绝新增，不擅自清理历史；历史浏览/显式整理、受限读取/导出和长期回执治理继续P11.4后续阶段，不能把本次内存列表冒充重启后的完整日志目录。

停止成功仅表示已关捕获入口，OPENING/STOPPING/FAILED与worker_finished/durable分别显示；文件同步完成不代表设备命令成功。natural_end仅表示收到服务输出最终flush（也可能由连接FAILED收尾），不是正常远程退出或成功码。source_gap_bytes统计已接受的源缺口标记，拒绝记录另计；发生文件故障时仍需按ADR-029解释最后写入范围，不能称整场连接完整。

## 桌面与生命周期

Tauri增加专用logging_request，复用独立配置IPC通道，避免目录准备占用终端/输入通道。面板默认关闭，监测状态仍按当前ConnectionRef查询；关闭面板和重载不停止记录，切换标签过滤旧状态，按钮操作冻结目标。高级限额仅作用于下一次Start，实际日志限额另显示。复用现有公共控件/字体/CSS，不新增页面配色；全局布局/主题/DPI/字体的完整T22/T23仍留P12。

服务退出先停传输、再解除残余捕获，在事件循环外join文件线程；异常文件驱动挂起仍不假称完成，桌面Job/退出策略沿用既有边界，崩溃文件恢复由P24继续。只读历史/导出和新旧schema兼容仍开放；本开发IPC扩展需服务/桌面/桥接同构建。
