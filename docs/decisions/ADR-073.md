# ADR-073 串口小读取的有界连续尾块合并

- 日期：2026-11-09（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P10.1；依据首次真实UART源缺口与纯软件复现，延续ADR-024。

COM89/1500000首次只接收中，普通服务报告源缺口。进一步用合成Port连续返回8329次单字节读取，消费者尚未轮询，旧16项sync_channel只保留16字节、丢8313字节；这证明分片粒度可令现有64KiB预算几乎闲置，不证明现场所有缺口仅有此原因。服务10ms轮询节拍不改，不用真实日志作测试样本。

候选扩大项数或无界队列会改变资源边界，排除；阻塞生产者等待消费可能使OS缓冲和关闭/控制调度饥饿，排除；单独增加待发送缓冲/定时flush需要额外容量和终态同步，暂不采用。选择把输出队列与Status归于原短Mutex：VecDeque最多16块，每块分配4096字节；生产者只向字节offset连续的未消费尾块追加至4096，再建剩余块。消费者仍最多额外持有1个待返回块，读栈4096和命令FIFO不变；队列载荷分配上限65536字节，元数据另计，不称整个进程仅64KiB。

普通read和节奏发送期间的receive pump共用同一入队函数；每次最多处理4096字节，不等待凑满或消费者腾位。未满尾块已可立即读取，结束/取消/join不需要另一次flush，已排队字节仍可先读再Closed。满队列可仅保留本次前缀，剩余计入dropped_bytes；后续字节不能越过offset缺口合并。入队、read_bytes/dropped_bytes和空队列检查仍在同锁内，保留精确Gap/FIFO与终态，不吞掉真实过载。不改变身份、权限、协议、DTR/RTS或自动发送/重连规则。

代价：单个小块最多预分配4096字节；原始输出事件粒度可合并，不能把事件数当驱动read次数，服务采集时间也不是逐字节板端时间。测试须覆盖单字节突发、10ms消费者、固定容量/部分溢出/恢复、两条接收路径、准确数据/缺口与取消join。实际构建和串口专项后必须恢复普通服务；真实板端复验单列，零缺口短样本不推导所有负载无损。回退用新增revert，不迁移/删除用户配置或日志。
