# ADR-024 串口阻塞 I/O 隔离与有界原始输出

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（软件工作线程；服务/驱动验收待补）
- 关联：P10/P11/P14/P22/P24、ADR-006/023

## 决定与候选

沿用串口候选同步 API，由一个专用 OS 线程独占句柄，完成验证/打开、读、写和控制线调用；不把阻塞操作放入 UI 或 Tokio 事件线程。替代方案为 tokio-serial/直接 overlapped Win32，本阶段未证明其驱动取消/兼容性更好，后续仍可替换。Worker::spawn 只接收 Config 与私有设备选择，按 ADR-023 打开一次；没有重连、命令重放或串口退出码。

全进程最多 64 个 worker，permit 在线程真正退出后释放。命令 FIFO 最多 16 个排队，加一个在途；每写请求非空且最多 64 KiB，丢弃调用者过量 Vec capacity。Write/DTR/RTS/Break 共用队列，RTS 硬件流控归属仍由底层核对。每个请求有独立容量 1 的结果通道，发送不等待慢客户端；命令/原始输出不派生 Debug。

写入按最多 1024 字节的底层调用推进，检查取消，不重发已知前缀；Interrupted 最多重试 8 次。报告成功驱动调用已接受字节的下界，失败调用可能还有未知部分；complete 只表示驱动接受，不表示设备执行。写失败/WriteZero/无效计数结束连接，队列尾部不再派发并给 CancelledBeforeDispatch；在途取消不冒充未执行。控制失败单独返回，不静默成功。Break 可能被开启（含开启失败）时，退出前 best-effort 清除；失败单独写入状态，不能承诺物理线已恢复。

原始接收块 4096 字节，输出队列 16 块，消费者可另外持有一块待交付数据。队列满丢弃新块，读取继续；使用全接收流字节 offset、read_bytes/dropped_bytes，并明确交付 Gap(from,to)。尾部全丢且之后无数据时，空队列也必须报告缺口。生产者发送/计数与消费者“空队列+计数”共用短锁，避免把尚在入队的数据误报为缺口。驱动调用不持有此锁，UI/日志等慢消费者不能阻塞读取；未来服务须把 Gap 作为缺口保留，不能无声拼接成连续流。

取消先置位并 best-effort CancelSynchronousIo；只对本 worker 专属线程发起一次，避免重复取消干扰清理。默认端口超时仍 100ms，但不能承诺所有驱动/open/control 都遵守取消。join 是阻塞操作，服务必须隔离并在同 ID 换代/移除前等实际句柄退出；不能只 Drop 就宣称句柄已关闭。Drop 只请求取消，异常驱动可能仍需结束所属服务进程，完整恢复策略留 P24。没有承诺远端动作回滚。

## 证据、代价与回退

结果见 [P10](../records/P10.md)。内存端口覆盖 FIFO、控制线、取消结算、部分失败终止尾队列、已知前缀不重放、队列满、40 块尾部缺口、2000 块并发消费者逐字节账目、打开失败和 Break 清理失败。它们验证线程/队列逻辑，不能代替 COM 驱动收发、拔插、占用或控制线实测。当前仍未接入 IPC/公共 Sessions/GUI，也未实施服务 request_id 去重/代次授权、文本/HEX/节奏或持久日志；这些必须由统一服务后续完成，不能把 transport 入口暴露给 Agent 绕过调度。

代价：单线程读的 100ms 超时会影响排队延迟，需 P22 实测；全进程最多 64 个 OS 线程，有界不等于性能目标已通过。慢消费者可能丢输出但会见到缺口。复用既有 windows-sys 版本，仅增加 System_IO 特性，无新包或配置迁移。回退新增 revert；已发生的真实驱动发送/控制动作无法撤销。本阶段没有打开设备。
