# ADR-072 有界键盘尾项合并与自适应回执/刷新

- 日期：2026-11-09（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P12.1；依据CR-012。

本机实际WebView/合成SSH证据显示，旧逐键PENDING后必等50ms再查询、串行队列16项和输出每轮额外100ms等待，会在快速输入/删除下形成积压和拒绝。网络仍可能叠加，但不能把这个可复现的软件瓶颈解释为现场唯一网络问题。候选加大队列只延后溢出并增长等待，排除；盲派发下一项/本地回显会削弱回执与输出真实性，排除；协议长轮询/推送范围较大，暂不实施。

选择复用原InputQueue及原RPC：仅SSH2的xterm onData键盘来源可合并尚未派发的队尾。key固定服务/完整connection_id/generation/焦点epoch，连续可打印文本或完全相同Backspace/DEL/固定Delete序列分别分组，变更类别、其他控制和显式Compose/粘贴/resize都是边界；字节原样顺序拼接，不解释/执行或本地模拟。活跃项不可修改，合并上限4096 UTF-8字节，队列仍16项（含在途）；单事件超4KiB不合并且沿原单次上限。没有扩大原容量、没有跨目标/epoch继承。派发仍核对完整身份和epoch，切走再回来丢弃未发旧尾项；首派发原request_id不变，出错/未知清空未派发并停止该窗格，其他窗格独立。

初始PENDING/DISPATCHING先立即查询原编号；仍未决才4/8/16/32/50ms有界退避，原17秒期限、PIPELINE_QUEUED含义和未知不重试保持，串口send回执流程不改。每窗格输出仍只有一个read/drain任务，交互唤醒受最小16ms起始间隔限制；输入/收到输出后500ms按16ms延续，空闲回100ms。反复相同状态不触发React更新，renderedTarget只在身份变化或失效后更新；输出依然来自服务字节，不做本地假回显。无服务协议/权限/配置/schema变化。

测量仅测试Harness：DOM input/keydown捕获是onData前的可观测代理，不能冒称逐函数内部时间；真实fetch发送/回复、合成SSH服务端收到字节的SystemTime微秒、service_read回包及xterm DOM变化分段，DOM变化不等GPU最终呈现/真实业务时延。fixture新增默认关闭的退格回显模型和时间戳（无真实OS shell，不把Delete序列当完整编辑器行为）；新专项主动启用，旧专项保持原始回显。Trace只合成根，未记录用户输入或凭据。主线程TaskDuration单次空闲样本不是整进程CPU。回退可恢复旧队列/轮询，无数据迁移；完整证据和局限集中P12.1。
