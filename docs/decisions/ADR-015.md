# ADR-015 有界输入调度和可查询的去重回执

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（P09 Desktop SSH2 写入/resize 阶段；Agent 调度与任务继续）
- 关联：P09/P14/P15、R01/R11/R13/R14、ADR-007/ADR-014

## 决定

实际 SSH2 的用户写入和尺寸更新统一经过服务队列，不将底层 ShellWriter 暴露给 IPC/renderer。每连接一个 FIFO，有 16 个等待槽和最多一个工作槽，写操作/resize 共用顺序。读取与写入在连接任务内并发轮询，等待远端窗口时不持会话锁，不阻塞原始输出/其他 Pipe 请求。后续 Codex、广播、触发器只能复用服务调度和授权入口，不能增加底层 writer 旁路；本阶段仍只有 active Desktop，Observer 对写入、resize 和回执查询均拒绝，P14 的 Agent 授权/人工接管尚未实现。

session-core::input 提供通用回执状态机。每个实际连接代次保留最多 1024 个 UUID request_id 和 SHA256 指纹（带 write/resize 域标签）、回执，不保留输入内容。重复相同 ID/内容只返回已有状态；同 ID 不同内容/动作拒绝。满额不淘汰去重证据，明确 CapacityExceeded；队列满先拒绝，不留下“已接受”回执。新的 connection/generation 必须重新明确提交，禁止重连重放。本阶段暂无同 ID 重连 API，后续实现必须按代次隔离旧账本。

输入最多 64 KiB、非空；尺寸 2–500 列/1–200 行。排队 payload 使用 Zeroizing 字节容器，Debug 脱敏，处理/丢弃后擦除该容器；传输库内部复制与 OS 转储不在擦除保证范围。指纹不经回执返回，也不写审计正文。所有公开请求必须显式 connection_id/generation/request_id。

## 回执与失败

- Pending：服务接受并排队，尚未进入底层写调用。
- Dispatching：已经开始调用底层，远端结果尚不确定。
- PipelineQueued：底层调用成功，字节进入 SSH pipeline；pipeline_bytes 对文本写入给完整数量，resize 为 null。这不表示远端已接收/执行，resize 也没有远端成功应答保证。
- Unknown：底层调用已开始后超时/取消/断线，可能已有部分发送；不伪造已接受字节数、不自动重试。
- CancelledBeforeDispatch：连接终止时仍未进入底层的请求，明确不会再由此队列发送。

连接关闭/失败保留回执；已知 PipelineQueued 不被改成“没发过”，Unknown 不能被迟到成功覆盖为确定结果。关闭不能撤销远端已发生动作。一次写失败结束连接任务，取消其余未发送队列，避免继续在可能部分写入的字节流上追加命令。只有重新明确操作可创建新请求，客户端无自动重发路径。

## 主机挑战与生命周期

每次握手/rekey 主机评估期间暂停新输入；未派发工作等待 writable 通知，拒绝新排队。已开始的调用保留不确定语义，不承诺回滚。服务任务结束、用户 Close 或取消会释放队列并将 Pending/Dispatching 分别结算为未派发取消/Unknown；既有 raw output 和读取游标不被输入回执替代。

没有选择每次 RPC 直接 await writer：远端窗口背压会阻塞当前 Pipe，重复提交也无法确定是否已发送；没有选择无限队列或淘汰历史重试窗口：两者分别导致资源或重复命令风险。此代价是每代最多 1024 个输入回执，后续 P14/P22 必须设计长期输入策略，在不丢去重保证的前提下解决长会话容量，不能简单清空账本。

## 实证与回退

领域测试验证重复不再次派发、同 ID 冲突、容量与不淘汰、关闭结算和迟到成功不覆盖 Unknown。隔离真实 SSH2 包测试验证 FIFO/一次发送/resize 一次、旧代次拒绝、Observer 拒绝；阻塞远端 data handler 并限制窗口为 32 KiB，让 64 KiB 写入真实停在半途，验证 16 项等待上限、Ping/Read 可用、关闭/超时后的部分 Unknown 与其余未派发取消。测试结果见 P09。桌面、真实设备、长期容量和完整 Agent 接管验收未由这些测试替代。

回退输入接口不改变配置/vault 格式；保留操作已可能执行的事实，不将 Git revert 解释为撤销远程命令。
