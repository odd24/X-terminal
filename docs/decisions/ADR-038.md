# ADR-038 服务屏幕有界重排与物理视口

- 日期：2026-11-05（Asia/Shanghai）；状态：ACCEPTED（实施方向；结果见P11.7，BUG-001尚未关闭）。
- 关联：P11.7、R04/R12、ADR-005/ADR-028。

## 候选与证据

| 候选 | 证据与代价 |
|---|---|
| 保持截断并仅标明false | 已固定15样本2匹配/13差异，不能满足普通屏resize保留输出 |
| Node headless作为正式服务 | 同一xterm模型，但增加Node运行时/跨语言有界进程及分发复杂性，本次不选 |
| 替换Rust解析器 | 缺少本仓库固定OSC/内存和兼容证据，需要重新验证整个控制序列与接口 |
| 扩展已vendor的vt100 | 可保留固定vte/单格/窗口上限，复用单元格及wrap边界，局部代价是维护重排和视口/光标算法；选择此项 |

参考为本地锁定@xterm/xterm 6.0.0源码Buffer/BufferReflow与headless 6.0.0实际结果。默认reflowCursorLine=false，普通屏跳过包含活动光标的整个逻辑行组；替代屏不重排。硬换行独立，宽字连同占位移动，组合文本和属性留在原单元格，重排不能重新解码输出或从日志重放。后台普通屏仍应响应resize。

## 实施与边界

最多200行×500列/512行历史，临时布局也必须有界；不能按新行数先展开巨量空白矩阵。历史超限从头退役，不能增加来源gap或写入原始/文本流。宽高同时变化先处理行高，再按列重排；光标/保存位置、滚动区域及历史需实质测试。服务contents改为物理视口行，与光标坐标一致；read_text仍保持解码文本，不承担屏幕布局。

只有完成相应实现/差分与Windows IPC/桌面复验后才更新生产parser身份和resize_reflow能力。复杂Unicode宽度/真实vim等仍须独立验收，不能以有限矩阵宣称完整VT等价。替代屏裁切和活动光标行跳过是参考默认语义，须明确记录，不改成自动重排所有行。

## 迁移与回退

无新依赖版本/数据库迁移。保留vt100 MIT及来源、本地补丁说明；解析器行为变更更新身份，严格接口字段不删除。失败时新增revert提交并恢复身份/能力及相应断言；不改写证据或历史，不重发输入/继承授权。

## local.3：宽字行尾与历史读取（2026-11-05）

完整历史探测7be9a76揭示原vt100采用的“宽字仅剩一格不标wrap”与锁定参考不同，后续重排产生逻辑行断裂。选择保留空的行尾补位格并标连续行，复用现有reflow对“末尾无内容+下一行宽字”的补位识别，不引入三格字形或把补位变成用户空格。续格保持宽字的rendition；trim后历史grow补列时保留wrap，避免只读滚回改变下一次resize。探针改为克隆屏幕后读取，原未修复代码用克隆重放与原基线完全一致。

不改宽度表/重放原始字节/依赖版本，身份更新local.3；旧容量参考异常和新发现的1049初始光标差异继续开放（BUG-002），后者单独处理，不用重置所有替代屏光标冒充修复。保留原41匹配/26差异基线，新63匹配/4差异独立文件；参考全部快照摘要逐一与原基线相同。正常及--record均强制只允许明确的四个剩余差异，其余必须完全相等。实际IPC/原生结果以P11.7记录为准，未完成检查不预判通过。回退新增revert并恢复parser身份/相关断言，不删除已保存证据或重发输入。

## 实施中新增的极限差异（不关闭BUG-001）

新增600行满历史、12→6→2→500→2→500→12列后发现新的确定性差异。按每一步的[精确结果](../evidence/P11.7-reflow-extreme-steps.json)，差异起点为6→2：xterm原活动行end变成ef，服务按默认光标组裁切保留en；后续扩宽xterm仍停留相同几段，服务按保留逻辑组重新拼合。两者光标仍同为(3,1)。这里只报告观察结果，不推断所有xterm版本均有此行为，也不声称服务模型完全正确。

本次保留服务的有界单元格布局和原始/文本流不变，不为了对齐该极限观察而引入内容替换。夹具固定双方确切正文/光标/替代屏和BUG-001原因，输出KNOWN_DIFFERENCE，不能将脚本退出0当作该样本兼容通过。原最小复现和普通/历史等27项可匹配；BUG-001/P11.7仍IN_PROGRESS，后续继续极限一致性分析及真实程序验收。生产resize_reflow=true只声明普通屏具备重排能力；桌面保留复杂调整可能不同的说明。

## 2026-11-05 B容量调查追加决定

[第一批调查证据](../evidence/P11.7-reflow-capacity-investigation.json)现定位到锁定xterm 6.0.0的缩窄批量插入负索引：set(-1)在非零环形起点时别名活动槽位，把end替换为ef且标记软换行，后续扩宽遂跳过含光标组。固定输入族1至258穷举首个受影响258条，原600条同路径；47字节/零历史参考局部复现不等于服务512历史复现。

本批不改解析器或依赖，不引入模仿负索引的内容替换。候选“照搬参考异常”会破坏活动行来源/属性，因此拒绝；候选“升级/修复参考后改验收”尚无其他版本与桌面证据，本批不采用。选择保留当前有界来源模型、既有KNOWN_DIFFERENCE与严格双方断言，并新增容量边界两侧正文/光标/颜色回归。诊断运行时拦截负索引仅用于因果对照，18个前缀视口/光标相等不构成兼容通过，也不替代全历史/属性、真实程序及其他极限情形验收。BUG-001/P11.7继续开放；无数据库/依赖迁移，调查脚本与测试可通过新增revert回退。
