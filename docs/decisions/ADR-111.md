# ADR-111 交互 ADB 的前台输入和屏幕交接

Windows 实窗的原始键盘记录显示，多行 LF 粘贴实际按序到达。显示错位来自同一屏幕前缀已经绘制本机记录，后来 ConPTY 又从自身首行起重绘。[P26.112](../records/P26.112.md)

命令组在进入末步裸 Shell 时报告输出边界。渲染端先完成边界前的写入，再把本机记录保存到同一终端的滚动历史，为 ConPTY 留出干净的坐标。整个任务仍用同一受限输出队列，保留溢出标记。

应用只在已进入交互 Shell 时把 Ctrl+C 交给当前 ConPTY。Windows ADB 的原始输入模式读取该字节并沿原 PTY 传递。启动阶段、普通本地命令及 BAT 继续处理本机中断。多行粘贴在该通道将 CRLF 合为一次分隔，保留末尾换行的原有状态，并在原任务及原阶段排队。[AOSP Windows ADB 输入实现](https://android.googlesource.com/platform/packages/modules/adb/+/f4ba8d73079b99532069dbe888a58167b8723d6c/sysdeps_win32.cpp)

此变更没有配置迁移。回退可用原便携程序及已有数据根；保留应用的单数据根锁。
