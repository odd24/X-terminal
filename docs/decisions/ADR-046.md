# ADR-046 有界授权签发回执与管理恢复

- 日期：2026-11-06（Asia/Shanghai）；状态：ACCEPTED（P14服务子步，实际结果见P14）。
- 关联：P14、R11/R13、T13/T14/T17、ADR-020/044/045。

## 选择

授权GUI前须解决Grant已执行但应答丢失的恢复，不能让重复点击或换ID重试产生未知的孤儿授权。候选为GUI缓存token、无界签发历史、服务内有界request_id回执；选择第三项。Grant必填request_id，同Desktop主体/同范围集合/同原始lifetime返回原ticket和原绝对到期时间，不续期、不新签发。不同参数拒绝；未知请求才核对当前Profile/ConnectionRef并签发，异步配置查询后再次同Store锁检查编号/身份和代次。

保留签发重试先查回执，再决定是否异步读Profile，避免已删除配置或旧代次阻止原编号恢复；恢复只返回既有状态，不恢复已被接管/退休的能力。令牌只在ACTIVE回执的显式签发/状态查询出现，不进argv/env、磁盘或全局Codex配置。状态包含approved_scopes和当前effective_scopes，不能把初次批准范围当当前可执行范围；接管后ticket可仍有效而变更能力已撤下。到期或撤销不返回token，撤销立即清除回执内令牌，随后过期清理同样擦除；秘密类型不实现Debug明文。

## 容量与管理契约

Pairing内最多128签发回执，与原最多128票据（含Desktop）、128策略授权分别有界。回执满额仅退休已过期/撤销的UUIDv7、推进有序水位；活跃回执和opaque UUID保留，不能回收时明确CapacityExceeded。旧/未知同退休桶不能重新签发，RequestExpired不表示原授权从未存在。无永久owner表、数据库迁移或新依赖。

Desktop专用grant_status按原request_id恢复，grant_list只返回最多128项的无token/无scope摘要（编号、ticket、原到期、状态、有效范围数量）；单项status可取完整范围和当前有效token。避免128×64范围清单挤爆IPC帧，列表与单项最坏大小须实测。管理清单仅本服务运行期的保留回执，非持久授权历史，不含旧Observer票据。

grant_revoke按原签发request_id幂等：只撤对应Agent ticket，重复/迟到请求仍返回原终态，不新签发、不影响其他票据。原按ticket_id的Revoke保持原语义，并同步擦除对应签发回执token。Agent/Observer不能签发、查管理清单/回执或撤管理授权；仅Desktop通过真实身份访问，参数不能自填角色/owner/token。所有能力仍由实际派发检查；管理查询不取租约、不接管、不自动启动任何会话。

本地开发IPC v1随同构建更新Grant严格参数/响应及schema，旧客户端遗漏request_id明确拒绝，不宣称跨旧严格客户端兼容。GUI尚未开放新通道，后续必须复用tokens/Panel/Field、明确范围/期限、应答未知只查原编号、撤销/接管不能撤回已派发动作。当前审计仍有界元数据，非完整持久审计交付。

## 验证与回退

核心测试覆盖重试同token/期限、不同参数拒绝、权限、接管后有效范围、撤销/过期token擦除与不复活、128回执/opaque保留/退休拒绝；协议验证缺失/未知字段与最大回复帧。真实Windows IPC须验证多客户端/重连原编号查询、删除配置/旧代次恢复不新签发、撤销后新旧Pipe拒绝及租约释放、未知编号不造成动作。实际结果见P14，核心通过不当GUI/MCP已完成。

回退新增revert撤下管理入口并同步调用者/schema；内存授权随服务退出消失，不持久化旧同意、不恢复过期token、不重放动作。已派发远端动作不承诺撤销。Connect/Disconnect/其他控制、授权GUI和完整审计仍按P14继续，整个方案及所有阶段门未完成。Step-ID: P14 / Decision-ID: ADR-046。
