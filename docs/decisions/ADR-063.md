# ADR-063 受管理工作区布局与显式重新连接

- 日期：2026-11-08（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P17；承接ADR-062、CR-006/007与用户持续推进。

本包提供“保存当前布局／打开布局”，复用已有配置SQLite事务/备份和连接表单。只保存工作区名称、配置引用、局部分组/标签项ID、组/标签顺序、保存时选中项及导航开关；不保存ConnectionRef、service_id、request_id、认证、授权、租约、正文、草稿、设备库存/设备ID或临时目标参数。标签项ID仅布局标识，不是连接/请求能力。同Profile多实例保留独立布局项，不按地址合并。

候选：①浏览器存储或独立JSON文件；②原配置库独立布局结构、沿原备份/恢复；③保存旧连接身份后跨重启自动接管/重连。选择②；①绕过数据目录隔离/事务备份，③错误继承身份与用户动作。当前只做单终端的组/顺序视图，横纵分屏/完整P17仍后续，不立即重构多渲染器或新建侧栏。

配置schema 5新增workspaces表，最多8份，每份1–64标签项/16组/64 UTF-16单位名称；严格字段/ID/组引用/选中项、名称控制及方向控制字符校验。写入核对配置revision及当前保存配置存在，事务内读回完整布局集合；删除配置后旧布局引用可悬空，界面明确“配置已删除”并禁用连接，不偷偷重建配置。布局读写/删除仅Desktop；全RPC审计只记类型/配置版本，不写名称或内容。使用原全库revision，保存/删除布局也使旧固定配置版本预览失效，不为Agent建例外或扩大授权。

升级前保留旧库唯一备份，v4→v5仅新增表/迁移记录；失败完整回滚。v2/3/4旧备份只读解释为空布局，原文件不迁移；旧偏好严格解释保持。ConfigImage摘要和事务恢复包含布局，预览显示份数并明确恢复范围；恢复前安全副本保留旧布局。当前坏表/坏JSON/额外能力字段拒绝，不偷偷默认空或重建。便携Profile导出不包含布局。旧版不写schema5，回退须停服务后按已验证备份恢复流程，不自动降版本。

保存仅捕获当前可见、已有保存配置引用的会话；临时会话及未连接项明确不纳入，计数可见。无可保存项时不创建空布局。不会为了补齐临时目标偷偷建永久Profile或保存凭据；需要时用户在原连接/配置表单明确保存。当前保存为新布局，删除单独明确确认，均不影响正在通信的连接。丢应答/存储失败只重新读取核对，不自动重复保存/删除/打开。

打开布局只是载入组/顺序和待连接入口，不自动Start、不推断旧连接存活、不按同Profile猜测复用当前会话。原会话保持，默认入口和导航结构不改。每项由用户明确连接，SSH仍走当前配置/必要主机身份/认证及保存凭据一次登录，串口仍显式选择当前库存身份/参数/初始控制线。仅本次精确意图成功且实际profile_id匹配后，才在窗口内绑定新ConnectionRef用于展示；绑定不写库，换服务清空，布局引用变化不继承旧绑定。迟到/取消或参数改为另一配置的连接不冒充布局目标；同配置两项必须是不同实际连接。收起布局只收起入口，不关闭连接。

验证分模型/配置迁移与回滚/真实Windows IPC/实际构建与合成SSH+内存串口WebView。原S1直接激活/关闭、S2设备身份与日志安全沿用，不因布局绕过；串口feature专项finally实际恢复普通服务。真实COM/全局DPI/物理拖动/长稳仍单列。回退新增revert/台账，不删除用户数据或篡改旧证据。
