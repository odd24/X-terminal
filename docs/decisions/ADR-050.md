# ADR-050 串口建连归属与设备打开前的授权

- 日期：2026-11-06（Asia/Shanghai）；状态：ACCEPTED（P14软件子步，结果见P14）。
- 关联：R03/R11/R13、T04/T13/T14/T17、ADR-044/045/049。

## 选择

串口Start不能照搬SSH：它绑定原Inventory revision/device_id、配置端口和独占worker，打开设备本身还会应用已配置的初始控制线。候选为只放宽入口、在异步配置前检查、在原Start回执内保存认证来源且在OS worker打开前复核。选择第三项，不新增协议字段、依赖、数据库或公开路径。

新请求只需精确Profile Connect，不需要已有连接lease；先认证、查询同owner原回执并取得固定Permit，再异步查配置。返回后同Store边界复核身份/同许可、并发原编号、Inventory revision/device_id与配置端口一致、设备占用/容量，然后创建原worker。来源随原1024回执和UUIDv7水位回收；同来源重试只返回创建时ConnectionInfo，不能借配置删除、库存刷新或Forget重新打开设备。跨来源UUID即使参数相同也拒绝，参数冲突仍拒绝。

原Worker增加可选进程内DispatchGuard，由同一OS线程在实际open_selected前调用；服务回调复核原ticket/Permit，拒绝则End::Cancelled且不调用设备打开函数。回调只做短Store策略判定，OS open不持Store锁；该判定是打开操作的派发边界，已开始的驱动调用不能承诺撤回。worker在guard返回后再次检查自身stop，避免guard等待期间Desktop关闭后仍打开设备。默认spawn无guard保持原有可信调用行为；test-backend使用相同worker入口。

Connect覆盖此配置的设备打开及原有初始DTR/RTS策略；不授后续任意Control/Write/Read/Disconnect，不允许调用者覆盖参数、端口路径或身份。Inventory、Status、Close、Forget仍仅Desktop；Agent不能由Connect枚举本机设备或读取终端。后续GUI Profile批准须说明配置与打开行为，不能把现有连接授权GUI当作已支持Connect。

## 验证与回退

服务确定性测试在真实配置消息已等待、OS线程打开前guard已到达后，再撤销/到期或Desktop关闭，检查实际内存端口open计数为0、没有字节或控制线调用；不以创建worker或回执代替实际open证据。opt-in serial-ui-fixture真实Windows IPC验证独立Connect、原来源并发/重连/删除配置及刷新库存后的恢复、跨来源和越权拒绝。普通串口和最终桌面全回归保持，finally必须核对恢复普通服务成功。合成内存端口不当COM驱动验收，实际结果见[P14](../records/P14.md)。

回退新增revert撤下Agent串口Start和guard接入，保留Desktop/原去重与回执。Disconnect、GUI Profile批准、时间范围/授权形式/脱敏/完整持久审计、真实stdio桥及P13–P25继续。Step-ID: P14 / Decision-ID: ADR-050。
