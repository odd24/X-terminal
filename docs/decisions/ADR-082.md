# ADR-082 有界独立checkpoint可行性研究

- 日期：2026-11-10（Asia/Shanghai）；状态：NOT_ADOPTED（有限实验完成，本轮B停止，不落产品）；Step-ID: P22。
- 依据：20626fa/P22的E盘checkpoint整体1.34–1.53秒超过原32队列约0.985秒吸收窗；统筹明确选择B研究，同盘有限实验后再协调产品，不直接重构/再跑服务负载。

## 目标与不变量

A保留现架构及该环境T19失败是允许结论，不能对任意磁盘承诺无损。B研究仅问：同一个生产FileJournal的真实Windows文件句柄，独立线程sync期间append是否仍被OS长时间阻塞。不能由“多线程”推断I/O可并行，不能靠增队列/无限缓存/禁审计/降速/改sync_all为弱同步取得通过。

若以后有产品方案，单writer先把本次prefix的live BufWriter真正flush到OS，raw/JSONL本来是直接File写入；冻结源/文本seq和每文件字节边界、连接代次/log_id/segment epoch，再复制原句柄（不从路径重开/越过原share策略）。每logger最多一个在途checkpoint、一个可合并的未派发最新意图，不允许无限任务队列。同步helper只sync冻结句柄，不取源/服务状态锁、不seek/append，不把完成时最新written标为同步。共同synced水位只能是**三个文件都真实sync_all成功后**冻结的最小共同prefix；允许系统额外同步后来的字节，但回执不超签发时flush水位。

错误必须回到原log/epoch并粘滞失败，停止新接纳/成功完成；旧/迟到回调不得更新新段/新代次/覆盖新失败。不能撤销已进入OS的sync或承诺超时已取消。原日志guard/原写句柄和复制句柄必须活到相应sync真实返回；stop可停新接纳，但排空已接纳数据、等待旧sync、再为最终固定前缀做真实sync，才可completion/durable。不能因UI关闭或取消遗忘未结helper。

rotation必须先等该段所有固定范围完成及回执归档，再关闭/发布新段；retirement必须在相应句柄/同步fence真正释放后执行原验证删除，不把旧失败段当完成段。若等待导致32队列满仍精确拒绝，不能隐式丢数据或伪成功。以上为后续设计必须证明的边界，**当前实验不实现rotation/retirement/stop服务协调**，不能凭实验通过宣布架构安全或产品已修复。

## 有限实验计划

仅自建E盘artifacts/P22-checkpoint-probe-中文-随机根，生产FileJournal/LiveText的原打开权限和guard，test-only hook只复制已持有真实写句柄并flush缓冲，不加入产品API/能力。每轮8份raw+JSONL+live，先写8×4096字节prefix并flush、冻结prefix=8；串行控制与独立helper使用相同三复制句柄/顺序（live/raw/text）。独立模式helper开始后writer固定再写128条；不新增输入队列/缓存，每次append最多4096字节，数据/指标均有限。8writer+最多8helper，3复制句柄/源；每模式固定2轮，合计4组，每组最多8×136×4096=4,456,448载荷字节，不延长为服务吞吐或长稳。无目录扫描/PairReader与写入并发；尾部检查在写入/helper均结束后。

记录setup、live buffer flush、各文件sync_all及共同checkpoint耗时、每次append起止和与sync区间的真实重叠，记录冻结prefix与结束written。helper只返回冻结prefix=8，绝不将最终written=136当成已同步；串行与独立均显式最终同步/关句柄后校验固定全部记录。helper错误会以原范围错误返回，不发布共同水位；实验不设假的超时取消或无限补偿。每组全部结果保存，不挑最快轮。

若同文件append仍长停顿（尤其达到约0.985秒原队列预算）、没有真实重叠/结果不稳定，或必须增加容量/削弱语义才有效，停止B并报告，不继续叠架构。只有实验支持和具体最小协调方案可证明保原语义，才向统筹呈证据决定产品落地；即便支持也不声称已经通过T19或修复旧260RPC审计异常。其他物理盘需独立只读确认及另行矩阵，不把盘符当性能依据。

## 代价与回退

B潜在多一个有界helper/三复制句柄、同步失败回传与段生命周期fence复杂度；Windows同文件写仍可能等待FlushFileBuffers，吞吐收益未证。阶段内只test-only代码/文档，回退移除实验即可，不动用户库/日志/服务/窗口；不接COM、不运行模型、不扩大设备范围。

## 实验结论

固定两轮串行/独立共四组已完成，完整证据见[P22](../records/P22.md#同句柄独立checkpoint可行性结论2026-11-10)。独立模式确实有34/35次append与同步区间重叠，但最大单次append仍739.3014/742.9168ms，时间线可见live、raw、JSONL各阶段分别阻塞同文件写。有限实验不证明必然耗尽原队列，却足以否定“仅移线程就能消除停顿”的设计依据；保持水位/fence的复杂度没有充分收益依据，按预定停止条件本轮不采纳B。不继续增加辅助层/容量、降同步承诺或再跑服务压力刷绿，A保留该环境失败。实验只有原句柄复制/最终同步与固定记录校验，未实现产品异步回执、换代、轮转/退休或故障协调，不能当这些安全条件通过。
