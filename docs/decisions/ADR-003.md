# ADR-003 SSH1 独立适配方向与 Plink 管道限制

- 日期：2026-11-03（Asia/Shanghai）
- 状态：PROPOSED
- 关联：P04/P13、R02

## 背景与候选

SSH1 是首版范围，必须显式启用，不能因当前库只支持 SSH2 而删减。需要双向字节、PTY/resize、凭据提示、主机确认、进程清理和可分发许可。

| 候选 | 本步证据 | 许可/成本 |
|---|---|---|
| 官方 Windows Plink 0.85 直接管道 | 哈希/启动/SSH1 banner/无自动协议降级通过；没有完整握手端点 | MIT；原版 Windows plink.c 无 backend_size 调用，缺少 resize 控制 |
| 基于 PuTTY 后端源码构建专用 helper | 源码有 SSH1 login/connection、terminal_size 与 backend_size；尚未实现 helper | MIT；需维护受限 IPC、Seat 认证桥、构建与补丁跟踪 |
| Unix Plink + 额外 Unix 运行时 | Unix plink.c 有 SIGWINCH→backend_size；未实测 | 增加运行时/分发与凭据边界，不能假设是 Windows 原生方案 |
| 从旧 OpenSSH/其他实现自建 | 未验证 | 老协议实现与维护成本高，不作为无证据的替代承诺 |

## 暂定结论

官方 Plink 可作为协议探针，**不直接认定为完整适配器**。更可控的后续方向是在独立普通用户 helper 进程内构建 PuTTY SSH1 后端，以明确二进制帧/私有控制通道传递 resize 和凭据响应，应用数据独立承载。所有命令仍由统一会话服务调度；不启动一个与 UI 无关的 SSH shell。

证据来自官方 0.85 源码 a3cce3a48d4ab12e0fccb32998b9042d4f7c3ff1：Windows `windows/plink.c` 仅初始化 backend 和标准 I/O，没有尺寸变化事件调用；Unix `unix/plink.c` 有 backend_size 与 SIGWINCH。仅套一层 ConPTY 不能据此认定 Windows Plink 会发送远端 resize。该差异必须通过 helper/替代实现及真实端点证明解决。

原版 `-batch` 禁止交互提示；`-pwfile` 需要读口令来源，不采用明文参数或明文落盘作为生产方案。凭据桥必须从 Windows 保护存储取引用，仅在受控边界短暂解密，不将提示文字混入应用输出，不将诊断 stderr 当成远端原始数据。主机密钥确认不能自动回答 yes。当前没有证明这条安全凭据路径。

## 验证、成本与回退

P04 只通过探针子项，保持 BLOCKED：无完整隔离 SSH1 握手/交互端点，resize/认证桥未实现，真实用户设备未测。不得将 banner 当作已经使用 SSH1 完成交互。P13 不得绕过这些缺口。

PuTTY 许可允许修改/分发但要求保留版权与许可；当前 exe/源码仅在忽略目录作本地调查，未打包。P25 若分发需附完整许可、固定来源/校验、版本维护策略。回退 P04 提交移除探针和决策，不影响 SSH2；后续 helper 不适用则新增 ADR 替换，不删 R02。
