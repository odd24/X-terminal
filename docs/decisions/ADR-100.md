# ADR-100 桌面快照和终端输出游标

0.1.36 每个窗口定期获取服务状态和可见会话。30 秒双窗口基线产生 539 次快照，每次持有 Desktop 客户端锁串行请求 Ping、List；空闲独立 SSH 窗格还取了 269 页。[测量记录](../records/P26.30.md)

**决定**　在同目录的桌面和服务之间增加只读 `desktop_snapshot`。服务在同一次状态锁内校验当前 Desktop 身份，复用 List 的可见性过滤，提供服务标识、SSH1 编译能力和每个精确代次的下一输出游标。Desktop 核对服务标识，再按当前窗口归属过滤会话和对应游标，过滤后才分开序列化。审计按 Session/List 登记一次。每次刷新重新向服务取数，原有 Ping、List 和 MCP 工具继续可用。

**选择依据**　合并两次服务往返对单窗口和多窗口都生效。仅合并不同窗口恰好同时在途的请求，收益依赖窗口调度时机。按时间缓存可见列表则需要额外解决窗口移交、服务失联和权限变化时的失效问题。本方案保留一次新鲜读取和既有窗口边界。

**读取语义**　游标仅用于调度。授权与数据交付仍经原 Read 请求。活动输入和持续输出沿用快速路径；已追平的空闲连接跳过空页，一秒兜底复查。快照游标向前时唤醒读取，首次绑定、状态变化后的尾部、代次、缺口和写入排空仍由实际页判断。未在渲染器列表状态里发布逐字节更新。

**迁移与回退**　桌面与随附服务成对交付。新桌面遇到旧服务的未知命令会显示服务异常。已有桥仍可用原契约访问新版服务。回退时成对恢复原桌面及服务，配置和日志格式无迁移。独立报告合成输入回显、空读和原始序号，避免把服务调用减少等同于整机加速。
