# ADR-048 SSH尺寸控制的独立授权与共享队列

- 日期：2026-11-06（Asia/Shanghai）；状态：ACCEPTED（P14软件子步，真实验证见P14）。
- 关联：P14、R11/R13、T13/T14、ADR-044/045/047。

## 选择与边界

SSH Resize原先只允许Desktop。候选为仅放宽入口角色、独立尺寸通道、复用已有FIFO与认证回执。选择第三种：真正Agent的Resize进入原enqueue_from，需精确ConnectionRef的独立Control和当前lease，Write/Read/Exec均不推导Control；不新增IPC字段、依赖或连接。只接SSH2现有适配器，合成Fixture/串口目标不借SSH接口执行控制。

内部Permit、真实ticket owner与request_id随原QueuedInput和Receipts有界保存；异步等待后按同一grant/lease/代次检查，派发决定与撤权在原Store锁协调。释放后重取租约不能复活旧队列项。相同客户端/参数的原编号恢复沿已有输入回执规则，不二次派发；跨来源不能借用UUID。输入回执查询仍需有效票据，旧代次不继承。

Resize成功仅表示原SSH transport pipeline接受请求，不等于远端PTY已应用或任意程序兼容。已派发请求不能承诺撤回；取消/到期阻止后续尚未派发项。桌面自身视口变化仍不执行人工接管，避免显示布局自动撤销Agent授权；用户键盘/撰写/显式接管沿原策略撤非Read范围。

## 界面、验证与回退

授权面板SSH2增加独立Control选择，明确能力为按目标协议的SSH尺寸或串口控制线，不包含Connect/Disconnect/认证/主机批准/广播。默认不勾选、固定目标/一次性预览和原编号恢复语义不变，token不入WebView，真实stdio桥仍待P15。

真实IPC须证明独立Control/租约、Write不能调整尺寸、Control不授予读取/写入、Desktop Resize保留租约、同编号不二次发送及跨客户端拒绝。背压场景以同一对端记录尺寸和FIFO fence核对释放/到期/撤销/手动输入/显式接管后的旧项未到达；不能只看CANCELLED回执。原生授权专项与最终完整19入口在实际构建后执行，结果见P14，不预填通过。

回退用新增revert关闭Agent Resize及GUI能力选择，保留既有Desktop尺寸行为和输入去重证据，不重放请求或恢复同意。Connect/Disconnect/建连owner、时间读取范围、单次任务形式/脱敏/完整持久审计、真实桥与整个方案继续。Step-ID: P14 / Decision-ID: ADR-048。
