# ADR-013 凭据元数据与保守孤立项整理

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED
- 关联：P08.3、R05/R13、ADR-009/ADR-010/ADR-012

## 决定与候选

替换凭据、移除 Profile 引用、删除 Profile 都保留原密文，因为其他配置/备份可能仍有引用。采用 Desktop 专用元数据列表、逐项引用检查和显式遗忘；不在保存/恢复时自动垃圾回收。自动删除会破坏旧备份的凭据可用性；跨 SQLite 库同时清引用和删除秘密又需要额外事务协调。因此当前遗忘只允许当前配置和本目录 artifacts 受管理备份均无引用的记录，删除仅影响 vault，不改配置数据。

列表按 UUID 排序，每页 64 条、总量 10000，跨页校验统一服务 revision。只返回 UUID 和当前 Profile 引用数，不返回密文/内容，也不为列表解密。检查及执行遗忘都读取完整有效配置镜像，重新扫描最多 64 个受管理备份；坏备份/未知版本/容量超限直接失败，不把不可读当作无引用。执行再检查 revision 和实际引用，故新建备份或外部修改备份也不能绕过使用中保护。服务单一配置线程串行化正常写入，Observer 无任何元数据或删除权限。

GUI 先检查、再勾选、再遗忘；当前/备份引用非零时按钮禁用，服务仍独立强制检查。引用变化或库故障不自动重试。缺引用修复仍使用 Profile 重新输入或清除引用，不自动拿其他秘密替代。

## 边界与代价

受管理范围是当前目录 config.sqlite 与 artifacts 内已发布的 backup-UUID.sqlite；外部复制、迁移前副本及其他目录不被扫描。GUI 明示该范围，用户确认不再用于其他副本；不支持强行删除受管理引用，不提供不可见的后台批量清理。新恢复目录不复制 vault。文件删除/SQL 删除不承诺磁盘物理擦除，沿用 ADR-009 的 Windows/备份边界。

大库扫描在有界配置线程上运行，终端通道独立；高负载/最坏扫描时间限与故障恢复仍待 P22/P24。回退仅移除管理入口，不改变 vault 格式，也不把已遗忘内容作为可恢复承诺；不自动恢复或重放会话动作。

## 实证

Windows 原生 vault 和跨进程服务测试覆盖元数据不含秘密、当前/备份引用保护、旧确认拒绝、坏备份拒绝、新备份在确认后加入引用仍拒绝、无引用删除/重启、64+1 分页及版本冲突。真实 WebView 的按钮/表单证据见 P08.3 记录；全部为合成秘密，未使用设备凭据。
