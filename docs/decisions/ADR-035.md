# ADR-035 显式未完整的恢复JSONL导出

- 日期：2026-11-05（Asia/Shanghai）
- 状态：ACCEPTED（文件流阶段；受管理发布/服务/桌面继续）
- 关联：P11.4/P24、R12、T16/T20、ADR-030/032/034

## 选择

失败日志已经可以用RecoveryReader读取连续已验证前缀。候选为复用普通导出并去掉尾行、改造普通格式让缺失尾行表示成功恢复、独立显式未完整格式。选择新增export_recovery_jsonl与shared-terminal-recovery-export v1，保留普通export_jsonl/ArchiveReader/verified语义，避免消费者把源损坏与导出文件自身截断混为一谈。无新增依赖，不修改源格式/文件或补写完成标志。

库输入为ManagedRoot/log_id/精确ConnectionRef，独立从最早可见配对头新开RecoveryReader，不采用GUI已推进的页游标。调用方必须明确授权恢复模式，不能在普通导出失败后自动尝试恢复；必须使用独立任务身份/回执声明模式，下一阶段才接服务与桌面。代价是消费者必须识别新format，不把恢复文件当作普通完成导出；首头不可识别、未知项/reparse/活动占用等仍拒绝，无法恢复已退休数据。

## 格式与错误

首行type=recovery_header、format=shared-terminal-recovery-export、format_version=1、incomplete=true，source为RecoveryInfo（含log_id、metadata、limits、起点/可见段、completion_present/partial_present）。这两个标志仅表示文件存在，不解析/传递可信source_completion，不声明同步/自然结束。中间type=record，raw原始OutputEvent（flush为null）与text派生TextEvent严格分离，原有时间/字节/缺口/控制字符保持，JSON转义只保护容器不执行正文。

最后一行type=recovery_stopped、incomplete=true、recovered为RecoverySummary：recovered_records/recovered_raw_bytes/recovered_gap_bytes/next_cursor/stop(kind/segment/next_cursor)。stop沿用ADR-034，END_OF_AVAILABLE也不改变incomplete；末行证明导出流到达某个已报告的停止点，不证明源日志完整、磁盘同步或用户文件已保存。没有verified行，不能把正常源文件走恢复模式解释成正常完成导出。

每次读32KiB逻辑页/最多128条，加一条有界JSON序列化记录；计数checked_add，缺口总量溢出不能写终止尾行或返回Ok。每页/条及最终flush前后检查取消；目标短写继续write_all，写失败/flush失败/取消传播Err。Err可能已有部分或全部字节、甚至终止尾行，调用者不得发布；Ok只说明格式流写入/flush结束，不包含sync、发布、用户目标或覆盖同意。源读取损坏按RecoveryReader转换为stop保留本页已验证前缀，源存储读取失败也只报告STORAGE前缀；打开失败则在写首行前拒绝，不悄悄生成空成功文件。

## 证据、后续与回退

6项新增实质测试/日志库72项通过：真实轮转/无完成标志及截断flush精确前缀/字节/缺口/身份，空或原本正常源也明确未完整，三字节短写、部分写/最终flush失败，打开前/记录中/最终flush后取消，错误代次/坏首头零输出，合成成对合法但总缺口溢出无终止报告。原文件逐字节保持、普通缺标志导出仍拒绝；doc-tests为0不计业务覆盖。验证结果见[P11.4](../records/P11.4.md)。

后续复用受管理暂存/限额/指纹/不覆盖发布，但恢复任务必须带不可变模式及恢复统计/stop，成功发布不可展示成源完整；取消/丢应答/清理/原生另存均保持固定精确目标和既有授权规则。文件库流通过不代表已开放恢复导出按钮、自选保存或跨重启任务恢复。回退新增revert并保留任何已导出/源文件，不改写既有普通文件或把尾行升级为verified。
