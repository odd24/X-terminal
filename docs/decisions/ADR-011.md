# ADR-011 主机密钥信任记录与过期确认

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（存储/管理范围；握手接入属 P09/P13）
- 关联：P08.3、R01/R02/R13

## 模型与边界

HostEndpoint 明确 SSH1/SSH2、主机、端口，主机仅做 ASCII 小写规范化，不将协议、端口或 DNS 别名合并。HostKey 保存调用方提供的规范公开密钥字节与算法；公开摘要为 SHA256 + 无填充 Base64，私钥不进入该表。采用既有 schema v2 的 host_keys 表，不需要修改版本。依赖复用锁定 base64 0.23.1/sha2 0.11.1。

评估为 Unknown/Known/Changed，只读，不自动存信任。同一端点新增算法也按 Changed 处理，显示已有摘要供未来握手确认，不静默继承。批准要求显示时的端点 revision：对规范端点和有序已信任摘要计算 SHA256，BEGIN IMMEDIATE 中重新评估，变化即 Conflict。更新同算法替换该记录，其他已批准算法保留。忘记记录需端点/算法/当时指纹，旧界面不能删除被修改的密钥。

每密钥 1–16384 字节，最多 1024 条、每端点最多 16 个算法；读取 blob 前检查 SQLite length，启动验证已存内容，非法数据不覆盖。候选密钥真实编码/证书/算法允许集由后端握手解析器保证，当前模型不把任意合成字节当 SSH 验证。

## 服务与 UI

配置 IPC 仅增加 Desktop 专用分页/忘记主机密钥，Observer 查/删均拒，没有从 renderer 任意批准密钥的入口。UI 显示协议/主机/端口/算法/完整指纹，勾选确认后才允许删除；冲突要求刷新重新确认，不自动重试。删除不改变已有活动连接，后续握手需重新确认。

实际握手的首次/变化提示、connection_id/generation 绑定、审批失效及连接阻断在 P09/P13 接入，不宣称当前已拦截真实服务器变更。库方法的调用方必须是服务内受信任审批流程，不能以 review 返回值自行绕过用户确认。

## 证据与回退

实际临时 SQLite 测试覆盖首次未知不写、重启已知、变化只读、额外算法使旧确认失效、两个线程/独立连接并发批准仅一个成功、旧指纹删除失败、协议/端口隔离和坏数据不覆盖。跨进程服务测试拒绝 Observer 查/删；实际 WebView 显示指纹、外部改变记录后旧确认 Conflict、刷新再勾选删除成功。见 [P08.3](../records/P08.3.md)。

回退本阶段提交保留 schema v2 原表/数据；旧代码忽略该表，不作降级握手或隐式批准。标准参考：[OpenSSH ssh-keygen](https://man.openbsd.org/ssh-keygen#E) 的 SHA256 指纹选项；当前字节/摘要算法另有固定已知向量测试，真实协议兼容仍待后续验证。
