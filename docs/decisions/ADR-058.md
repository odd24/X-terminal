# ADR-058 完整RPC拒绝记录与独立持久审计边界

- 日期：2026-11-07（Asia/Shanghai）；状态：ACCEPTED（本步仅请求尝试核心模型；服务/持久层/GUI须逐层验证）。
- 关联：P14、R11/R12/R13、T13/T14/T17、ADR-044/046/057。

## 已有证据与选择

ADR-044现有Policy只含512条授权/租约/入队/派发等元数据环，Pairing部分只读校验不可变；server::connection在Hello/帧读取失败时直接结束，typed RPC按5个子通道/公共入口派发后直接写Response。现有环不能覆盖所有身份/参数/读取/跨owner拒绝、序列化/写帧错误或服务取消，也不能区分返回Ok与远端完成，不能充当完整持久审计。ADR-057的规则/正文不得进入任何新增审计。

比较把完整Request/Reply Debug或JSON写日志、扩充原Policy环、独立元数据请求尝试流。第一项会泄漏token/认证/命令/规则/输出，禁止；第二项混淆策略许可与RPC结果、破坏已有游标消费者且仍漏握手/帧读取。选择独立RPC尝试流，原Policy事件保持原语义；以后持久层可收两类独立typed事件，不轮询可能已覆盖的环来声称无损。

## 请求尝试与真实结果

服务生成每条Pipe身份及每次尝试UUID，同一wire_id/request_id重试仍是不同审计尝试，不影响原传输去重/回执。Origin包含实际认证票据ID/角色（与活跃权限不同）、服务器观察的可选OS peer PID；拒绝客户端传入role/PID作为证据。握手开始为Unauthenticated，只有实际认证成功才追加Authenticated(client_id/origin_kind)，不回写原未认证事实。非法帧和握手失败只记Transport分类及固定错误枚举，不保存帧、token片段或错误字符串。

Descriptor只包含固定Area/Verb枚举、wire_id、原request_id及请求scope声明。分类须在服务从严格typed Request逐分支穷尽生成，不能接受caller描述、任意方法字符串或格式化Request；scope是请求声明而非实际许可。所有字段只能是枚举/UUID/整数/已有纯scope结构，没有命令、认证、配置名称/参数、文件路径、正文、规则值或可枚举秘密摘要的字符串槽。

状态按Received→ReturnedOk/ReturnedError→ReplyWritten或ReplyWrite IoFailure；读Hello/帧错误可在Transport Received后终止，服务取消记Abandoned。ReturnedOk仅表示handler构造Ok回执，可能只是入队/Requested/原回执查询，绝不自动当作远端完成；ReplyWritten仅本地write_frame完成，不能当作客户端收到，write失败也不能改写先前handler结果或撤回动作。仍须查询原业务编号，不自动重试。成功握手认证身份只追加一次，不能用于普通RPC或替换已记录身份；模型强制Hello初始未认证、成功返回前已有Authenticated，未认证来源只用于Transport，不冒充普通RPC。

核心保存512事件/64活跃尝试、单页1–128、单调源seq、固定exclusive through水位及after-cursor分页；覆盖显式gap/available_from。单条终态自带原Origin/Descriptor/start_seq/attempt_id，即使Received已覆盖也可解释该事件。不能在容量满时逐出活跃尝试；seq耗尽明确CapacityExceeded，不wrap/伪造终态。新模型没有设备操作、授权或持久化能力，也不代表服务已经记录这些路径。

## 持久层规划与准入

持久审计须独立于终端原始/文本日志、配置导出与用户文件，使用受管理固定子目录、Windows祖先/目录/文件句柄与非reparse检查，不接caller路径、不覆盖未知内容。候选为：有界JSONL分段（可复用已有terminal-log句柄和坏尾前缀机制，但须另实现唯一写入/断电/轮转/索引）；独立SQLite（已有config-store使用固定rusqlite版本及事务证据，但不能把审计表塞进配置备份，须另核对叶文件/sidecar安全、版本/坏库及磁盘上限）。不在本核心步骤虚构持久层验收或增加数据库/依赖；服务接入后的原型证据决定具体后端并补本ADR。

无论后端，要求独立有界writer/消息队列、单一顺序/固定服务身份、提交/同步水位、明确容量/覆盖/失败与未完整尾部，停止/实际join回收；不能把queue accepted当durable。压力/失败不得静默丢审计后仍显示完整成功，失败后是否阻止新Agent动作必须在实际派发/回执恢复语义一起设计，不能全局重做/取消原已执行动作或挡住安全的原编号只查。持久查询仅Desktop独立白名单、有限分页/固定水位，不与既有本服务512环混用，重启不恢复token/租约/同意。

全路径准入须包括：实际Windows IPC握手/无效帧、版本/身份/到期/撤销、参数/未知方法、五子通道/公共读取及业务权限失败、跨owner/旧代次、handler Ok/错误、真实不读/丢失应答、关闭/超时/服务停止。采样/聚合或保留窗口必须明确，不得声称持有无限完整历史。持久层另验磁盘/队列失败、坏尾/重启与原文件保持、受管理目录/junction、计数/同步水位和真实普通服务恢复，GUI再实际构建验证来源/缺口/状态，不由纯核心通过推断完成。

## 代价与回退

新增尝试/事件内存有固定上限；每事件复制有限元数据，原业务回执去重与许可不改。握手/每请求更多事件会更快覆盖本服务环，必须明确源游标/保留窗口；持久层不能靠无限RAM弥补压力。接口使用独立类型以保留原AuditKind/Page协议，暂不迁移配置或持久格式。出现问题用新增revert撤下新审计接口/接入，不扩大授权、不改原终端输出或删除原日志。Step-ID: P14 / Decision-ID: ADR-058。
