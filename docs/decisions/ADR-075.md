# ADR-075 同服务显式复查启动配置锁失败

- 日期：2026-11-09（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P12.1；依据CR-015。

原ConfigWorker只在启动申请configuration.lock，owner=Err(Locked)之后永久返回，不论持有者是否退出。保持失败封闭避免误重放是正确边界，但要求整个服务重启才能恢复基本配置读取，在当前只有一个窗口时会误导。

选择Desktop专用ConfigRequest::Recheck{service_id}与Rechecked回执。服务先核对认证Desktop/活跃身份及本运行service_id，actor仅对原Locked状态尝试固定原目录share_mode(0)；竞争仍拒绝，成功后按正常Store/Vault规则打开现有文件。owner/state已就绪时只回报同身份，不释放句柄、不重开/改revision；其他Storage/Schema/Corrupt错误保持原状态和恢复流程。请求不能携路径/新角色/Start参数。正常Page/Preferences/库存读取不重试锁，丢应答不自动续任何保存/认证/连接，显式再复查仅重观察同一就绪状态。

共享控件在SSH/UART配置LOCKED时显示，前后核对同原服务；同步在途门防重复，关闭后忽略迟到UI动作。成功只读回配置，通知主窗口重新读取偏好/会话树，保留表单参数和原连接意图阻断。串口配置/库存独立结果，端口列表读取不代表已开设备；配置未就绪禁止Start。库存更新仍必须使用最新revision和精确设备身份。

排除自动每次读重试（背景读取可能抢占目录并触发保存意图）、重启/替换运行服务（会破坏现有连接）、删锁/共享打开/重建库（破坏独占与数据保护）。回退新增revert并保留用户数据，不修改真实用户进程。新能力只恢复配置访问；启动时失败的持久审计不在本包重启，原高级Agent审计健康限制继续失败封闭，不把配置恢复说成全服务/高级授权恢复。自建IPC验证正常释放、竞争者先取得、已确认测试服务强制退出释放、同服务/错误身份、重复不改revision、损坏/未来版本保持；真实桌面验证两连接窗口/无自动Start/参数保持/迟到与丢应答。完整实机与长期另列。
