# ADR-044 Agent授权策略、派发许可与人工接管

- 日期：2026-11-06（Asia/Shanghai）；状态：ACCEPTED（P14核心子步，服务/UI接入继续）。
- 关联：P14、R11/R12/R13、T13/T14/T17、ADR-007/015/020/025、CR-001。

## 准入与选择

P07已经建立受限服务/身份，P09/P10已具备共享连接与有界输入/任务回执，P11.1/2/5/6及P11.4已有读取/日志软件证据；local.4修复有限替代屏语义，BUG-001容量/实机/长稳等仍开放。按CR-001开始不依赖实机的P14策略子步，不把父P11或G0/G1标完成，不重做P12已有显示/导航/偏好。

候选为仅在MCP检查权限、入队时一次检查、服务身份加核心策略且派发时再次检查。前两种无法覆盖其他调用来源或撤销时已排队输入；选择第三种。新增session-core::access，不增加依赖、进程、数据库或系统配置。核心只接受服务已经验证的ticket_id，不接受调用者声明角色；Desktop权限由后续服务入口在同一锁内强制，不能直接公开Policy::grant给Agent。

范围是精确ConnectionRef上的read/write/exec/control/disconnect/broadcast，以及精确Profile UUID上的connect。每项独立，不由write推导exec/control/broadcast。connect只允许发起指定配置，不自动授予返回连接的读/写；新连接仍须显式批准精确代次。认证/主机信任及秘密继续Desktop专用，connect不包含批准权限。

最多128授权、每份64个不重复范围，期限最长30分钟；服务单调时间裁决，到期不延期。票据身份由服务生成，不在原身份上偷偷续期。过期授权按需回收，内存授权不跨服务重启。新内部grant_id进一步防止旧队列许可被误用同client_id的新授权复活。

## 输入所有权与审计

每个精确代次最多一个输入租约，最多64份，最长60秒且不超过授权到期。重复acquire包括原持有者均INPUT_BUSY，不隐式续租；释放核对完整客户端/连接/lease_id。所有操作连接的Agent动作都需要相应独立范围与租约；read和connect不占已有连接输入租约。

入队取得内部不可序列化Permit，包含授权修订、客户端、精确范围、租约和request_id；实际派发前重新核对。释放/到期/撤销/旧代次退休均使待派发许可失效。重新取得新租约不能复活旧许可。服务必须把最后检查与实际调度决定置于同一协调边界，不在异步等待后直接使用旧检查结果；长串口分段同样须覆盖尚未发送片段，不能只取消上层RPC。

人工接管在接受用户输入前撤下租约，并移除该连接所有Agent的非read范围；其他客户端不能立即抢回输入。观察范围保留；恢复自动化需新的显式授权。退休代次移除全部对应范围，connect Profile范围不会自动映射到新代次。已经派发/远端已执行动作不能撤销，允许迟到结果仍准确报告UNKNOWN或实际接受边界。

审计是独立512条环形元数据：seq、服务相对时间、动作/结果、client_id、scope、request_id；没有token、命令、认证或终端正文。每页最多128条，覆盖返回available_from/gap，未来游标拒绝；不能声称持久完整审计。当前记录授权、撤销、租约、接管、退休、入队/派发允许与拒绝，IPC身份失败和持久审计交付仍在后续服务/压力范围。

## 验证、代价与回退

核心实质测试验证范围互不推导、跨连接/代次/到期、connect不扩大权限、读者不能取租约、独占与释放身份、接管/释放再取/撤销/退休后的旧许可、所有变更动作的租约、参数/容量/审计覆盖。实际命令结果见[P14](../records/P14.md)，不把核心通过当服务/真实IPC或GUI已可授权。

复用现有transport FIFO与request_id账本，策略不自行发送或重复派发；去重、任务归属、真实IPC/UI、MCP工具、串口分段接管与所有路径审计需逐步接入并实测。代价是管理器/worker必须携带并复查许可，权限检查不能只停留server入口。后续准入不得以本核心模块存在替代真实端到端证据。

无数据迁移。新增revert可移除新策略及对应开放入口，保留现有Desktop连接、配置和日志；不能撤销已执行动作或恢复旧授权。不改全局Codex配置、不push/发布。Step-ID: P14 / Decision-ID: ADR-044。

## 服务身份与所有权控制通道

后续同P14子步将Policy纳入Pairing锁，共用128票据容量（含Desktop/Observer），新增由Desktop签发的Agent token与真实Welcome.kind=agent；Agent的Welcome.client_id固定为服务票据ID，与租约/审计一致，同票据重连不产生另一个授权主体。token只在签发回执出现，Sensitive诊断脱敏；不写磁盘/argv/环境或全局Codex配置。每个请求仍检查ticket存在/期限，已建立的Pipe不能绕过撤销/到期。

新增严格agent命令族grant/acquire/release/lease/takeover/audit，grant/takeover/audit仅Desktop，acquire/release仅Agent；Observer不能自升权。Grant核对当前全部连接代次，Profile ID由原配置线程查存在（不读取秘密），异步检查后再次核对Desktop与代次。租约未知应答只能lease查询，重复acquire不续期；授权签发目前无重试回执，未知结果禁止自动重试，GUI签发流程/编号恢复仍须另做。租约查询只向Desktop显示全部，Agent只返回自身租约，其他客户端不披露owner。

公共list/read/read_text/screen使用新Agent精确read范围；持write/exec等范围但未含read不能读取。配置、认证、主机批准、日志与现有SSH/串口控制通道仍Desktop专用，不能用存储的能力替代尚未完成的FIFO/worker复核。真实Windows IPC须证明有写范围和租约的Agent也无法通过这些旧通道旁路。合成生命周期退役时同步取消旧Agent范围；真实传输生命周期和自动人工输入接管须随正式派发集成，不从合成退役通过推断已全面接入。

此增量继续本地开发IPC v1的同构建契约，新InputBusy类别明确表示租约占用，不把它当投递结果。旧严格客户端必须同构建更新；MCP/GUI尚未开放新通道，不由此声明P14完成或P15真实工具已可用。没有新依赖或数据库迁移。
