# ADR-010 配置服务所有权与有界执行

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（P08.3 后端阶段；桌面整合未完成）
- 关联：P08.3、R05/R13/R14

## 选择与代价

将 P08.1 的 DTO/验证提取到无数据库依赖的 config-model，config-store 重导出原类型。IPC 只依赖模型/schemars，不把 SQLite/DPAPI 带入客户端。单条 Profile 查询由 config-store 提供，不复制两套字段定义。

一个具名 OS 工作线程独占 Store/Vault/目录锁，Tokio mpsc 上限 16，try_send 满即 CapacityExceeded，oneshot 返回。相比在会话锁内写库，它不阻塞会话读取；相比无界 spawn_blocking，不积压任意数量的秘密/操作。服务结束释放 sender 并 join。已取消回执的队列消息开始前跳过；网络失联不等于已获知取消，执行中的配置可能提交，不能承诺撤回。客户端不自动重发，设备命令调度仍在 P14。

配置仅由受信任启动方 --data-dir 绝对路径启用，IPC 不接受任意路径。configuration.lock 使用 Windows share_mode(0) 活句柄排除同目录的其他服务，不以文件存在判断进程状态。初始化错误明确返回 ConfigReply::Error，Ping/合成会话继续；未知 schema/损坏库不自动重建或回退为空库。固定类别不含 SQL/路径/秘密。

## 权限与一致性

仅 active Desktop 可用 Config，Observer 查/写均拒，没有读秘密 RPC。输入 PortableProfile 不含 credential_ref，未知字段拒绝。Keep 由服务查旧引用并验证秘密类型；Clear 仅移除此 Profile 引用；Replace 写新 vault ID 后关联配置。失败保留旧关联并尝试删除本次新 ID。两库不是跨库事务：中途崩溃可能留未关联密文；成功替换/删除后旧密文暂留以兼容共享引用/配置备份。显式遗忘/整理待 P08.3 后续流程，10000 条 vault 上限继续有效。

分页 folders/profiles 分开，每页最多 64 项；revision UUID 在修改/重启后变化，后续页必须携带，冲突返回 Conflict。IPC v1 开发契约新增类型，拒绝注入凭据引用/未知 secret read 操作；正式跨版本升级在 P24/P25 验证。

## 证据与回退

4 个新增跨进程场景覆盖重启保留、失败清理/秘密不在回复、观察者拒绝、64+1 分页与冲突、目录占用、未知/损坏原文件不变。真实 SQLite 写锁下 20 个客户端提交，至少 3 个因 16 排队+1 执行上限被拒，另一客户端 Ping 在 1 秒内返回，解锁后落库数量与接受数量相符。详见 [P08.3](../records/P08.3.md)。

回退本阶段提交不修改已有配置/凭据。桌面、主机密钥、导出/备份恢复 IPC 未完成，P08.3/P08 保持 IN_PROGRESS，不把后端测试当 GUI 或设备验收。
