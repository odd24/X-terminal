# ADR-064 两窗格分屏的最小交互与终端实例边界

- 日期：2026-11-08（Asia/Shanghai）；状态：ACCEPTED（方案决定，尚未实施）；Step-ID: P17；承接ADR-063及用户持续推进。

本项仅收口下一实施包的交互、实例及验证边界，不改现有复制品，不声称分屏可用或P17/R06完成。目标是在现有主窗口同时查看两个实际连接并向当前焦点窗格输入；最多两窗格，固定等分，提供左右/上下两个方向。默认单终端不变，不新建侧栏，不同时推进广播、触发器、树形嵌套或任意比例拖拽。

## 用户动作

从“更多工具→分屏”进入共享Panel/Field弹窗，当前已连接会话作为第一个目标，只选择“左右／上下”和另一个已连接会话；第二目标默认空，不猜同地址/同Profile实例。显示地址或端口、协议、代次和短ID以区分同配置实例，创建前重新核对完整service_id/connection_id/generation/protocol与实际CONNECTED。缺少两个不同有效连接时说明先连接另一会话，不自动创建连接或发送。首次只接受现有SSH2/SERIAL；原测试合成会话可以验证软件，不增加正式协议承诺。

创建后保留第一个窗格焦点，两个窗格持续读取各自输出，各自标题/状态可辨；点击窗格或键盘F6循环焦点，Tab继续原控件顺序。选择某标签时替换当前窗格；若该目标已在另一窗格，只聚焦另一窗格，不重复展示同一连接、不交换输入目标。焦点边框使用既有token，标题能以文本表明“当前输入”，不能只依靠颜色。主标签选中、底部状态、复制/粘贴/查找/撰写/日志/串口详情及exec等跟随同一个活动窗格，异步回执不得切换焦点。高级对话框保持原精确目标/确认规则。

“收起分屏”恢复当前活动窗格为单终端，另一个连接继续保留输出与标签；不是关闭连接。窗格上的关闭含义只允许“收起此窗格”，不复用危险的会话×。真正关闭会话仍通过原标签×，原代次断开且隐藏，另一窗格不被关闭；关闭后仅保留剩余窗格，或回到无连接状态，不擅自挑另一个活跃连接补位。关闭请求结果不明维持原提示、不重放。远端结束保留该窗格最终输出并停输入。服务身份变化清空所有窗格绑定；旧代次不自动跟随新代次，新连接需用户明确选择，必要认证照旧。

## 实例与调度

候选①在原单xterm上挪DOM/镜像画面；②仅第二窗格只读、继续全局selected分派输入；③抽取共用终端控制器，每窗格有独立实例，以一个根级服务清单和活动窗格路由相连。选择③。①无法同时保留两份视口/解析状态；②给用户可聚焦终端但键盘仍发往全局目标，焦点与输入不一致。抽取局限在终端控制器及根部路由，不重做连接、日志、配置或Agent服务。

源码依据：main.tsx现有唯一host/runtime/selectedRef；同一effect同时轮询service_status/list、重置解码器/屏幕、维护输入/resize与clipboard/compose；状态与终端尺寸也只有一份。直接复制该effect会竞争服务清单、全局消息及选中目标。InputQueue.close只丢未派发项，不取消正在执行的promise；TerminalClipboard已有epoch/精确目标和一次性预览，ComposeDrafts已有目标/代次边界，应复用并增加窗格/服务隔离，不绕过。

抽取后根只负责一次服务状态/清单读取与连接/窗格布局；每个控制器独立持有xterm/FitAddon、TerminalWriter、OutputDecoder、源游标、缺口/解码提示、viewport、InputQueue、粘贴epoch、尺寸去重值与本地故障。实例绑定冻结完整服务及连接身份，异步读取/排队前/await后核对当前绑定与控制器生命周期，不让旧page/编码查询/回执写进新窗格。输出缺口仍清解析与解码状态、明确提示，不借分屏取消现有边界。

键盘、粘贴、撰写只允许当时活动窗格且终端已绑定、状态CONNECTED。每次焦点、目标、布局或服务变化推进路由epoch并使原待确认粘贴/撰写同意失效；排队项捕获实例/精确身份/路由epoch，焦点移开再移回也不能复活旧未发输入。已派发动作继续沿原编号查回执，不承诺取消远端动作，也不改投另一目标。故障或未知回执停止该窗格后续派发且不自动重试；其他窗格不能继承旧请求或授权。

两个窗格不能绑定同一connection_id，避免重复读取展示产生歧义及两个SSH尺寸相互覆盖。同Profile独立连接仍允许。ResizeObserver分别按实际可见窗格fit并有界合并，SSH resize沿原精确代次FIFO；焦点变化不取消未变身份的可见窗格尺寸同步，布局变化不能触发文本输入。串口仅调整本地显示尺寸，不调用SSH尺寸或改变控制线。源码ssh.rs已有Desktop Resize不takeover、Write才takeover的区分，保持该规则；GUI布局操作不申请Agent lease/新授权，不取消现有Agent。键盘真实输入仍按现行Desktop接管语义。

## 持久化边界与工作包顺序

第一实施包只交付本窗口两窗格，明确“工作区当前仅保存分组和标签顺序，不保存分屏”。现有schema5严格布局不加未迁移字段，不用localStorage持久化实例/旧ConnectionRef；保存仍沿原元数据事务，打开工作区时先收起分屏、仅呈现待连接项，不自动建连或复用活跃窗格。取消/收起不改配置或通信。跨重启恢复分屏是第二个独立包，届时只保存方向/布局项引用/活动项等有限元数据，单列schema迁移/摘要/备份与显式连接后的绑定验证，不保存实际身份/正文/授权；本项不预先声称schema版本或实现完成。

先抽取单窗格控制器并保持现有产品行为，再实现两窗格/路由；有独立产物分别提交，不攒全应用重做。产品变更后实际desktop:build，先验证单窗格受影响导航/输入路径，再完成双SSH及SSH+内存串口混合专项；只在新变化/失败/实质风险时扩大验证。配置/解析器/服务没有变化不重跑其旧全套，串口feature专项finally必须实际恢复普通服务。未通过前保持P17 IN_PROGRESS。

## 必需证据

新状态边界测试覆盖两窗格容量、同连接拒绝/同Profile不同实例允许、焦点/目标/service/generation变化、已退休绑定、旧焦点来回不复活队列、精确关闭/收起。真实WebView验证左右/上下同时输出、实际键盘/粘贴/撰写只发向当前目标、延迟与故障注入确实命中、切换/布局调整/收起不产生用户输入、精确多窗格尺寸和普通窗口resize；初始分屏尺寸是Control而非文本输入，须分别核对。

通过原fixture的实际连接接收字节与尺寸记录独立比对，不能仅看前端选中或截图。SSH+内存串口分别验证各自编码/缺口/最终只读、粘贴预览焦点切换取消、丢应答不重试、旧代次/服务响应不更新新窗格、原会话关闭/退出确认与日志目标。实际观察活动窗格/标题/全局工具一致；真实COM、物理分隔条拖拽、DPI/IME/长稳与完整R06仍单列，不因合成专项通过冒称完成。
