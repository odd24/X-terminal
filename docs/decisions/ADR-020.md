# ADR-020 输入回执的有界退休窗口

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（输入阶段；任务结果和连接历史继续）
- 关联：P09、P14、P15、P22、ADR-015/ADR-016

## 问题与候选

原每连接代次最多 1024 条输入回执，满额即永久拒绝新输入，正常长会话会停止。仅提高上限仍有同一问题；删除最旧 UUIDv4 回执会使旧 request_id 再次发送；把所有随机 ID 留到磁盘只转移了增长位置，还需新的存储/容量与恢复保证。随机 ID 无法在有限内存中精确无限去重。

采用带时间顺序的 UUIDv7 标识和单调退休水位。时间戳只用于分桶/排序，不作为授权时间、墙钟真实性或超时依据；保留 74 位随机信息，ID 不编码输入内容。旧 UUIDv4/其他无此顺序的 ID 保持原有非淘汰、有界拒绝语义，不能悄悄缩短去重保障。桌面输入/尺寸采用 UUIDv7；配置 UUID、Start/Reconnect、exec 本阶段仍保持原 ID 生成，后两者容量另行实施。

## 不变量

1. 回执总数仍最多 1024，含 Pending/Dispatching。仅在容量需要时回收已结束的有序记录；绝不回收排队/正在发送记录或不透明 ID。
2. 回收某个时间戳的记录后，把 `retired_through` 单调推进到该毫秒；任何未保留、时间戳不大于水位的 UUIDv7 均为 RequestExpired。包括未曾见过的 ID 和相同毫秒的其他随机后缀，不能冒充新请求。
3. 尚保留的记录优先按完整 ID/指纹查找；即使时间戳早于水位，仍返回原回执或内容冲突。正在执行的旧时间请求可正常结算，Unknown 不改成未发送。
4. 检查和回收在同一会话锁内；回收后再次检查新 ID，避免同毫秒新请求穿过刚推进的水位。输入窗口同样约束 exec 与显式重连，旧写入 ID 不能换动作重发。
5. RequestExpired 表示原结果可能已无法查询，此次请求不派发；客户端禁止自动换 ID/重试。新 generation 由显式重连建立，不继承旧输入和权限，不能自动利用重连绕开容量错误。

同一毫秒内可接受有限乱序，未保留且落入退休桶的新请求会保守拒绝；不把“此前没见过”误报为“确定从未执行”。系统时钟回退或不同客户端时钟相差大也可能触发过期，应清晰告知；不能用重放修复。墙钟错误的完整恢复策略留给 P24，不能宣称已验证回拨后的无缝使用。

exec 重复查询先匹配自身尚保留的任务，再检查输入水位；不能因输入已经回收较新记录而丢掉一个仍保留的任务。任务结果本阶段仍为原 16/64 限额，不能以输入容量改进冒充任务清理完成。Start/连接历史和旧不透明请求容量同样保持开放。

## 证据、代价与回退

核心用例覆盖一万次连续请求、有限内存、旧 ID/不同动作/同毫秒/未曾见过旧 ID 拒绝、活跃与 opaque ID 不回收、Unknown/取消和冲突保持。实际 Windows 服务隔离 SSH2 跨进程场景覆盖 2200 次写入及 1099 次 resize、服务器字节一致、重复不重发、旧 ID 不能转 exec/reconnect、旧 exec 重查不重跑；桌面跨过 1024 后键盘可用的结果见 [P09](../records/P09.md)。这些不是 8 小时/20 会话压力结果。

成本是过期结果不能永久查询和保守拒绝旧桶，以及最多 1024 项扫描的回收操作；P22 需实测尾延迟。未新增依赖、数据库或凭据内容，IPC schema 新增明确错误枚举。回退用新 revert；服务重启丢弃内存连接而不重放，不改变存储格式。未来所有可回收请求表必须保留等价拒绝水位，不能仅按 LRU 丢弃 ID。
