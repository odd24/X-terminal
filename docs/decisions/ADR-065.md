# ADR-065 受管理两窗格布局与显式连接后的恢复

- 日期：2026-11-08（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P17；承接ADR-063/064和用户持续推进。

本包沿现有“保存当前布局／打开布局”，只增加两窗格方向、两个布局项引用；活动项复用selected_tab。不增加复杂布局编辑器/新侧栏/任意分隔树，不保存ConnectionRef/service/generation/request、认证/授权/租约、正文/草稿或设备库存，临时会话仍不建隐含Profile。

候选：①旁路浏览器存储；②schema5偷偷加可缺省字段；③schema6版本化扩展、原迁移/事务/备份读回。选择③。①绕过受管理目录及备份；②破坏旧schema形状和错误拒绝边界，容易把坏数据当默认单窗格。新split必填且可为null；有值时只有horizontal/vertical及两个不同已存在布局项ID，selected_tab必须为其中之一。同Profile两个布局项合法且独立。

schema5只读按独立deny_unknown_fields旧结构解释为split=null，不接受伪装旧版本的新字段或多余能力。v5→v6前生成原配置库副本，在同一事务逐行标准化、检查更新数量/全量读回/迁移行后提交；失败原字节/版本保持，备份保留。v2/3/4旧备份继续原只读兼容。新库split缺失/坏引用/未知字段或坏表严格拒绝，不自动修复；ConfigImage摘要/恢复与安全副本包含新元数据，旧副本读取不改原文件。便携Profile导出不带布局。旧程序不能读写schema6，新版恢复旧副本只恢复内容，不降版本；完整目录降版本仍独立验证。

保存把当前两个精确、可见、未退休的窗格映射为本次快照中已保存Profile的布局项。任一窗格是临时/缺失配置/变化身份/未纳入可见快照时，保留其余可保存标签但略过分屏，并在原表单说明，不挑另一个同地址项补齐。无可保存项不保存。

打开只展示方向及待连接入口，不Start/不认证/不发用户输入。每次明确打开都清空旧的窗口内布局绑定；当前连接保留，不能把同名/同Profile或同地址现有连接猜进新布局。两目标沿原SSH/串口流程逐项明确连接后，原意图/配置/服务/精确代次匹配且均实际CONNECTED，才一次性恢复两个窗格及保存活动项；串口仍重选当前库存设备。部分连接时保留原单终端路径及明确待办，缺失项禁用，不用其他会话替换。

恢复只是一项窗口内展示意图。手动分屏/收起、选择其他标签、关闭目标、换工作区或关闭布局取消待恢复意图，不在之后焦点/连接回调里迟到覆盖用户布局。旧代次不继承绑定或授权；重新连接要再次明确当前目标。已恢复后不因普通轮询/重读反复摆放或抢焦点；只有恢复动作本身在原意图未变化、目标渲染就绪后按保存活动项聚焦一次。尺寸沿ADR-064原Control FIFO，不当用户文本输入/接管授权。

验证分严格模型/坏字段、schema5迁移/失败回滚/旧备份字节保持、摘要/事务恢复、真实Windows IPC权限/revision/重启零会话，实际构建和新持久分屏WebView专项。需核对同Profile独立槽位、临时略过、两协议显式连接、部分/配置缺失/手动取消不自动补齐、保存丢应答只重读、跨进程布局保留但会话为空、备份恢复新元数据；串口fixture后finally实际恢复普通服务。无变化旧全套不重复，实机/DPI/长稳及完整R06仍按实际证据分列。
