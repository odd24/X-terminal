# ADR-009 当前用户 DPAPI 凭据库与认证记录

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（本机 Windows 原生存储证据范围）
- 关联：P08.2、R13、ADR-008

## 候选与决定

采用 Windows 当前用户 DPAPI 保护随机数据密钥，AES-256-GCM 加密秘密；独立 SQLite vault 只保存 UUID 与认证记录，不在 config-store 中存凭据。每次写入均用 OS 安全随机源产生新的 32 字节密钥和 12 字节 nonce，密钥只使用一次，DPAPI 不启用 LOCAL_MACHINE，禁止系统提示 UI。DPAPI 的 optional entropy 绑定产品版本、随机库 namespace 与凭据 UUID；这些绑定信息是公开上下文，不是额外密码。

Credential Manager 是可行替代候选，但本次未实现/验证其凭据 blob 分段与任意大小私钥存储。当前选择可支持 0–64 KiB 不透明秘密；不要求用户自己管理加密密钥。保存空密码合法，缺失引用明确 NotFound，不拿空串冒充缺失。

最初直接 DPAPI 加密内容并检查内部格式的实验发现：修改合成 DPAPI 头部第 8 字节仍能成功解出相同内容；因此不把 DPAPI 成功返回当作整个外部记录的完整性证据。最终使用已锁 aes-gcm 0.11.1 标准 AEAD，认证完整头部（magic/长度/DPAPI 包裹密钥/nonce）和密文。没有自制密码算法；SQLite 只接收已完成认证加密的记录。逐字节修改最终合成记录均失败，截断、跨凭据/库替换也失败。

## 格式与生命周期

记录为 magic、u32LE 包裹密钥长度、DPAPI 包裹密钥、12 字节 nonce、AES-GCM 密文/16 字节 tag。包裹密钥上限 8192 字节，整个记录上限 128 KiB；解析先检查长度，读取数据库 blob 前先在同一读事务查长度。每库最多 10000 条，数量检查和写入同一事务；更新保留引用但生成全新密钥/nonce。

Secret 不实现 Serialize/Clone，Debug 固定 [REDACTED]；所有者使用 Zeroizing 字节，API 层接收后立即纳入擦除包装。DPAPI LocalAlloc 输出由 RAII 在 LocalFree 前 zeroize；AES-GCM 启用 zeroize（包括 AES/GHASH 成员状态）。不承诺消除编译器、操作系统或调用方的全部副本。DPAPI 失败只返回 OS 错误码，不打印内容。

vault application_id/schema v1 与配置库不同，未知版本/其他应用/损坏/已有空文件只读拒绝，不自动重建。无配置导出/通用文件接口/renderer 调用入口。P08.3 服务才负责受限写入与引用关联；GUI 可提交新秘密，不能读取已保存秘密。真实认证在 P09/P13 消费服务内部引用。

删除使当前库 get 返回 NotFound；不承诺撤销其他已读取的内存副本、远端动作、备份或安全擦除磁盘历史。库副本/操作系统漫游和恢复策略必须在后续备份 UI 明确；普通配置导出不含 vault。当前用户 DPAPI 通常要求同一登录用户/机器，但 Windows 漫游等例外以系统语义为准，不声称绝对不可迁移。

## 验证与边界

本机真实 CryptProtectData/CryptUnprotectData、Windows OS 随机源、SQLite 磁盘事务运行通过。6 个主集成场景包含独立子进程重开读取、0/64 KiB/二进制、更新删除/缺失、最终记录每一字节修改/截断/ID 与 namespace 替换、未知/损坏库字节不变、明文标记落盘扫描。子进程 helper 在主测试列表为 ignored，由父用例显式运行，不能算作未执行或额外主场景。详见 [P08.2](../records/P08.2.md)。

没有执行其他真实 Windows 用户、Windows 10、DPAPI 用户配置丢失/重置、磁盘满/掉电、恶意同账户进程或专业密码审计。同账户进程可调用 DPAPI，也可能读内存/替换文件；本设计不承诺抵御这些能力。P22/P24/P25 保留边界/恢复/分发验证。

回退 P08.2 对应提交只移除尚未接入服务的 crate；未来已存的 vault 不能退回明文，必须保留原库/Windows 用户保护条件。格式变更需增版本和迁移证据。
