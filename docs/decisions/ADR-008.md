# ADR-008 配置数据库与分层凭据

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（配置存储选择；凭据实现由 P08.2 另补实际证据）
- 关联：P08.1、R05/R13/R14

## 候选与证据

| 候选 | 证据/代价 |
|---|---|
| rusqlite 0.41.1 + bundled SQLite | MSVC 实际构建、临时磁盘数据库 CRUD/迁移/备份恢复通过；同步 API 需服务独占配置执行，不在异步传输读取循环执行阻塞 SQL |
| sqlx + SQLite | 未原型；异步池对当前单配置写入者增加运行时/迁移复杂度，暂不引入 |
| JSON 文件 | 无外键/事务迁移与在线快照能力；目录树一致性和崩溃恢复要自行构造，不采用 |
| Windows 系统 SQLite | 库版本依赖部署机器；不作为本机确定版本来源 |

采用 rusqlite bundled，libsqlite3-sys 0.39.1 的已锁源码 SQLITE_VERSION 为 3.54.1。依赖锁和许可明细进入 evidence/dependency-licenses.json，不动态加载用户 SQLite 扩展；发行许可整理仍属 P25。此处版本来自实际下载/构建依赖，不把其他机器的系统 DLL 视为同一引擎。

## 数据与迁移

Profile 有 UUID、可选 folder_id、名称、可选 credential_ref 和严格协议设置；没有密码/私钥字段。SSH1 必须显式开启；SSH2 支持密码/公钥/交互方式标记，实际认证仍属 P09。串口参数保留显式 DTR/RTS，硬件流控下 RTS 由驱动管理；保存配置不打开设备。编码为 UTF-8/GBK/GB18030，协议模型未知字段拒绝。

当前 schema v1 为 folders/profiles，v2 增加迁移历史与 host_keys 表基础；主机信任 API/确认 UI 在 P08.3。application_id 标识本产品；已有文件先只读检查版本、quick_check、外键与领域语义，未知版本/其他应用/损坏配置不覆盖。没有自动删除/重建损坏库的策略。新文件用 create_new 取得，已有空文件拒绝，不误当新库。

迁移在 BEGIN IMMEDIATE 内实施，修改前从单独只读 SQLite 连接使用 Online Backup API 备份；保留写入预留锁防止其他写者改变迁移基线，备份用唯一文件且 create_new。失败回滚，保留迁移前备份供诊断，不用文件复制覆盖原库。未知 schema 拒绝发生在写入连接之前，进入事务后再核对版本。schema 更改必须增版本/备份/测试，禁止仅更新结构不记版本。

目录更新事务内校验缺父节点/循环，引用目录不能直接删除。最多 1024 目录/10000 Profile；数量检查和写入在同一事务。导出使用读取事务一致快照，PortableProfile 从类型上排除 credential_ref，且不导出 host_keys/秘密。名称/用户名/主机等自由文本仍需由用户避免手工嵌入秘密；字段排除不代表内容自动脱敏。

备份包含配置/凭据引用，不包含受保护秘密；恢复先只读验证备份，当前仅恢复到新目标，拒绝覆盖现有目标。正式恢复替换流程/诊断 UI 在 P08.3。备份失败可能留下不完整新目标，返回错误且不自动接受它；磁盘满/掉电注入在 P24。Windows 保护凭据不在本 SQLite 库保存明文，P08.2 接入后仍由服务端使用引用，renderer 不获得读秘密能力。

## 验证、回退与来源

6 项真实临时磁盘数据库测试验证重启/CRUD、协议约束/未知秘密字段、目录循环、预迁移快照和中途 DDL 失败回滚、未知/损坏文件字节不变、新目标恢复及拒绝覆盖。测试不访问用户配置/凭据/设备。见 [P08.1](../records/P08.1.md)。

回退 P08.1 只移除未接入服务的独立 crate；未来已生成较新 schema 时旧程序应拒绝打开，回退配置须由备份恢复到新目标，不强行降 schema。服务/编辑器/保护秘密未完成，不标记父 P08 完成。

来源：[rusqlite](https://docs.rs/rusqlite/0.41.1/rusqlite/)、[SQLite PRAGMA](https://www.sqlite.org/pragma.html)、[Online Backup API](https://www.sqlite.org/backup.html)。已直接核对锁定的 backup.rs 和 sqlite3.c，并实际执行迁移/恢复。
