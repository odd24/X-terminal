# ADR-037 终端剪贴板的固定目标与换行保真

- 日期：2026-11-05（Asia/Shanghai）
- 状态：ACCEPTED（软件范围；实际桌面证据见P11.6）
- 关联：P11.6、R04/R15/R16、T06/T22/T23、ADR-036。

候选为继续xterm默认paste、调用Terminal.paste、在终端宿主捕获剪贴板后走已有输入入口。仓库锁定xterm 6.0.0的Clipboard.ts公开源码显示前两者把LF/CRLF转换为CR，再按模式加边界；因此选择宿主capture阶段拦截paste，阻止原默认路径，纯文本保留CR/LF，显式toolbar及Ctrl+Shift+V同一入口。复用已锁定windows-sys 0.61.2（仅启用DataExchange/Memory features，无新版本），无底层连接访问或任意RPC。当前P12仍负责习惯选项。

多行、控制/双向格式字符或超过1024单元的文本先预览/确认；预览JSON转义并截到8192单元，总正文按现有SSH/串口输入UTF-8上限（含边界）拒绝超限。SSH最终编码限制仍由服务严格转换，失败沿用原队列停发/不重试。预览固定connection_id/generation/protocol和页面操作代号，不持久化正文/授权；异步剪贴板读取不跟随目标，切换、键盘输入、新粘贴、取消、换代和卸载使旧代号失效。确认前重新核对可写目标和括号粘贴模式，仅同一proposal对象一次有效。

当终端请求bracketedPasteMode时只加ESC[200~/ESC[201~，不改正文；正文含任一边界序列整批拒绝，避免逃离边界。不声称括号模式保证远端不会执行命令。模式变动拒绝原确认并要求重新粘贴。Ctrl+C选区存在时复制，无选区时保留xterm正常中断；Ctrl+Shift+C及按钮显式复制，无选区提示。系统复制复用已验证navigator.clipboard.writeText；显式读取候选为浏览器readText和Windows只读命令。本机真实点击已触发但readText仍未完成，不能作为可用功能交付，因此使用独立terminal_clipboard_read原生命令。固定CF_UNICODETEXT，不接受格式/路径/连接参数；OpenClipboard→GetClipboardData→GlobalSize/GlobalLock，限定196608 UTF-16单元和UTF-8字节，严格UTF-16及NUL结尾，RAII解锁/关闭，不释放系统handle，不写剪贴板。最多一个阻塞worker，3秒等待超时仅放弃本次前端结果，worker仍持占用直到结束，禁止后续排队膨胀或自动重试。正文不落日志。读取前冻结目标，读完再核对epoch，原生命令不能自行发送。系统剪贴板失败显示实际失败，不假装完成。

代价：默认粘贴换行与xterm原行为不同，故UI明确CR/LF原样，无自动尾换行；LF在具体shell的含义需真实设备验收。预览只显示一次且取消优先焦点，确认不是撤销承诺。剪贴板系统权限由WebView/Windows管理，测试合成文字不能代表所有宿主/远端兼容。回退使用revert并同步步骤/台账；不涉及配置迁移、全局Codex设置或历史重写。

依据：[Microsoft GetClipboardData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboarddata)要求把内容当不可信数据、在关闭前复制且不释放系统handle；[OpenClipboard](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard)要求成功后关闭，占用失败由调用方处理。本实现逐项使用有界读取与RAII，不自行请求全局WebView剪贴板权限。
