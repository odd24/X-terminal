# ADR-025 串口共享会话、去重与接收缺口

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（软件服务范围；GUI 与实机继续）
- 关联：P10/P11/P14/P15/P24、ADR-007/020/023/024

## 服务与设备选择

在同一个 session-service/Named Pipe/领域 Sessions 中接入 SERIAL。active Desktop 专用 serial 请求：inventory/start/status/write/control/input_status/close/forget。观察者仍只能通过公共 list/read 读取其明确 ConnectionRef 范围；不公开原生句柄/接口路径，不增加通用 RPC，也不让 UI/Agent 绕过服务打开串口。P14/P15 的 Agent 写授权和真实 MCP 工具仍未实施。

inventory 在 blocking pool 做只读枚举，返回 revision、随机 device_id、COM 名称/实例 ID、未识别端口和元数据失败数；实例 ID 仅供本机 Desktop 核对，不写诊断日志。刷新替换最多256项选择表，旧 revision 失效；start 读取 Profile 快照，再在 manager 锁内重查选择表与端口对应关系。Worker 内再次核对完整原生身份并通过专用接口打开。未知接口不回退 COM；本服务仍有未退出同端口句柄时拒绝再开，其他进程占用由实际驱动失败报告。

start 创建公共 Protocol::Serial，打开阶段 CONNECTING，实际 worker Ready 才 CONNECTED，跳过 SSH 认证；失败有结构化类别，不编造设备退出码。配置参数沿用已有 Profile/原生枚举；不读取凭据，不迁移配置。当前显式再次打开创建不同 connection_id，旧读取票据/回执不迁移；未增加自动重连或 same-ID 串口重连工具。

## 输入、生命周期和容量

Write/RTS/DTR/Break 都由服务派发至同一 worker FIFO。每次显式 ConnectionRef/request_id，服务留内容指纹和独立串口回执：PENDING（可能已派发）、DRIVER_ACCEPTED、CONTROL_APPLIED、CANCELLED_BEFORE_DISPATCH、UNKNOWN。驱动接受计数是成功调用的下界，不是设备执行证明；失败可能还有未知字节。部分写失败/取消报告 UNKNOWN，已知队列未派发才报告取消前未发送。控制失败也不假定物理线未变化。写与控制有独立指纹域，同 ID 换动作/参数拒绝，保留重复只返回原回执、不重派发。

连接数由公共 Sessions 限64，输入与 Start 回执各最多1024；沿用 UUIDv7 单调退休水位。仅在容量需要时回收结束的有序输入，PENDING 与 opaque 请求保留；Start 仅回收对应连接已移除/完成清理的有序结果。旧桶/未知同桶拒绝，保留记录优先匹配。拒绝新请求前可能退休旧结果，不能以此自动换 ID 重发。时钟回拨边界沿用 ADR-020，旧随机 ID 满额仍明确拒绝。

服务定时轮询 worker 非阻塞状态、结果与原始输出，每条连接一轮最多32个输出事件；仅扫描最多17个未结算 ticket。关闭立即禁用新输入并进入 CLOSING，发送取消；排空已捕获输出，再在 blocking pool join 已结束线程，实际 join 完成才发布 DISCONNECTED（用户关闭）或 FAILED。清理期间不能 forget 或再次打开同端口。forget 仅移除终态且已清理连接，独立 Start 回执继续阻止原请求重建。服务退出最多等待2秒，异常驱动仍不退出则报告超时并结束服务进程；不能声称 CancelSynchronousIo 或 Drop 已关闭句柄。

## 原始输出缺口

公共 OutputEvent 增加可选 gap_bytes；普通字节事件省略该字段，缺口事件 bytes 为空、占用自己的递增 seq/时间戳，数量仍受输出缓冲事件上限约束。Worker Gap 传入领域缓冲，多个独立读者都能看到；与消费者落后造成的 truncated/available_from 区分。关闭排空只允许当前代次的 CONNECTED/CLOSING，不能借此恢复输入权限，旧代次写入/缺口明确拒绝。桌面公共消费端显示丢失字节，不把两段原始数据无声拼接。

这是 IPC v1 开发增量，schema 与所有绑定组件一同重新构建；不宣称对旧严格客户端跨版本兼容。旧客户端遇到未知缺口字段应失败而非假称连续输出，后续版本协商/升级仍留 P24。持久原始日志和 screen 缺口后的解码恢复留 P11。

实际结果见 [P10](../records/P10.md)：核心缺口/关闭排空、严格契约、服务内注入内存端口、生产服务跨进程观察者拒绝和无效选择零打开。test-backend 是 Cargo 测试适配入口，仅 Rust 进程内构造虚拟设备/worker；生产 Manager 固定 Native，未增加可从 IPC 启用的假串口。没有实际 COM 收发、占用/拔插/控制线或长期压力证据。
