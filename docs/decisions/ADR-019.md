# ADR-019 重协商主机信任检查的本地依赖补丁

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED
- 关联：P09、R01/R13、ADR-002/ADR-014、CR-001

## 问题与证据

复核锁定 russh 0.65.0 的 client::reply，发现 check_server_key 只在初始握手分支调用；rekey 验证交换签名后直接安装新密钥。交换签名证明对端持有本次公钥，不能替代应用的主机信任策略。ADR-014 原“接入时包括 rekey”的描述是设计要求，之前没有相应运行证据，不是已实现事实。

新增隔离 SSH2 服务器将读/写重协商阈值设为 16 KiB，真实 512 KiB 并发 shell/resize/exec 和拒绝场景在未修改依赖上均 FAIL：重复信任决策次数为零；拒绝场景等待挑战超时。没有以传输正常工作证明权限边界正确。

## 候选与决定

继续原依赖会违反既定信任契约；禁用 rekey 不能提供长期安全会话；仅在包装器 kex_done 检查不可行，因为该公开回调不提供本次主机密钥。换库或升级需要重新验证所有认证/流控/生命周期，并无现成证据证明满足范围。

保留版本 0.65.0 与全部生产依赖，在 vendor/russh 保存可审查源码，通过根 Cargo patch 统一生产和 fixture。把已有裸公钥/证书检查移到初始及 rekey 共用路径，在安装密钥/排放待处理 channel 数据前等待统一服务策略。证书仍由包装器拒绝；未知/变化密钥由当前 endpoint/connection_id/generation 和配置 revision 决策。已知密钥自动通过当前信任评估，无重复 GUI 弹窗。

本地来源、原归档校验值、许可和改动边界见 vendor/russh/LOCAL_PATCH.md。只复制构建所需源码及清单，移除未复制的上游示例/测试目标与开发依赖；省略上游固定私钥测试模块/文档示例，保留生产逻辑和版权头，使用主仓库每次随机生成的合成密钥回归。不宣称运行上游完整测试套件。未变更协议、SQLite、用户 SSH/Codex 全局配置或真实设备。

## 代价、迁移与回退

承担约 1 MiB 第三方源码及后续补丁维护；依赖元数据应标明 vendored 来源而非 workspace 自研。上游版本有等效检查后，核对 diff 与许可，再运行全部 SSH/服务/桌面回归方可移除 patch。原归档 SHA-256 可重建基线；需要回退本提交时使用新的 revert 并同时暂停生产 SSH2 路径，不能悄悄恢复已知缺口。

结果见 [P09](../records/P09.md)。真实 OpenSSH/UNIX、算法矩阵、长期性能和独立安全审计未因此完成。
