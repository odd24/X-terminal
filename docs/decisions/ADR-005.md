# ADR-005 P02 渲染与候选屏幕解析器

- 日期：2026-11-03（Asia/Shanghai）
- 状态：ACCEPTED（渲染选型及候选验证策略，不是完整服务端兼容性声明）
- 关联：P02、R04/R12；ADR-001

## 背景与候选

UI 使用 xterm.js，Rust 服务需要在 GUI 不打开时维护独立 screen。不能将截图当作机器接口，也不能用逐块字符串解码破坏多字节输入。

| 候选 | 本步证据 | 许可与代价 |
|---|---|---|
| @xterm/xterm 6.0.0 + addon-fit 0.11.0 | 本机 WebView 原生窗口、逐字节 UTF-8/ANSI、替代屏幕、键盘/字号 | MIT；固定版本使用 buffer API |
| Rust vt100 0.18.1 | 5 个合成样本的视口文本、光标、替代屏幕与 @xterm/headless 6.0.0 一致 | MIT；resize 不重排，存在兼容缺口 |
| Node @xterm/headless 服务 | 本步仅作差分测试参考 | MIT；正式采用会增加服务运行时，未选择 |
| 其他 Rust 解析器/自建模型 | 本步未实现 | 迁移成本待评估 |

## 决定与限制

UI 固定使用 xterm 6；Rust 选 vt100 作为 P02–P06 候选而非最终完整屏幕实现。encoding_rs 0.8.44（(Apache-2.0 OR MIT) AND BSD-3-Clause）提供 UTF-8/GBK/GB18030 增量解码，明确返回替换标记；原始字节由调用者独立保留。

vt100 关闭默认 std 特性，使其 vte 0.15.0 使用固定 OSC 缓冲（1024 字节）；源码检查发现启用 vte/std 时 OSC 使用动态 Vec，不适合不受信输出。单块输入上限 64 KiB、屏幕 1–200 行/2–500 列、滚屏 512 行。vt100 单格最多 22 UTF-8 字节，极长组合字符不保证与 xterm 一致。

已复现宽度缩小差异：输入 `abcdefghijklmnop\r\nnext`、12 列缩为 6 列，xterm 为 `abcdef/ghijkl/mnop/next`，vt100 为 `abcdef/mnop/next`（斜线代表物理行）。因此服务快照必须声明解析器与尺寸，不能暗示与 UI 完全相同。BUG-001 在 P11 处理 resize/reflow，未解决前相关 screen 兼容验收不得通过。

渲染消费者最多 256 KiB（包括 in-flight）、128 等待事件加 1 个 in-flight，单块最多 64 KiB。等待 xterm write callback 后释放占用；溢出锁定缺口状态，拒绝后续输入，等待重置/从服务游标重读，避免从被截断控制序列继续解析。消费者背压不能施加到串口读线程；服务缓冲与 cursor 在 P07/P11 实现。原型本地回显仅为测试，不是生产输入旁路。

## 证据与回退

见 [P02](../records/P02.md) 与合成对比报告。尚未验证真实 vim/top/less/tmux、复杂 emoji/组合字、色彩属性完全一致、长稳与多会话吞吐。回退 P02 可恢复 P01 外壳；未来替换解析器保留同一有界输入/快照接口，新增差分样本并 supersede 本 ADR。
