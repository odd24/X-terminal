# ADR-027 桌面接收解码与缺口边界

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（桌面显示范围；服务派生文本/screen/日志仍待实现）
- 关联：P11.1、R04/R12、ADR-005/ADR-026

## 决定

保留统一服务的原始 OutputPage，不改 bytes/seq/cursor；桌面在连接/代次开始读取前查询串口 Status 的编码快照。配置编辑不改变活动连接；重载再从服务快照恢复，而不是查询当前 Profile 猜测编码。SSH2 仍保持现有 UTF-8 限制。

候选一是浏览器 TextDecoder，候选二是将 Rust encoding_rs 派生文本加入服务协议，候选三是逐块转字符串。本子步选择一：无新依赖，按串口 UTF-8/GBK/GB18030 增量解码，再编码为 UTF-8 交给现有有界 TerminalWriter。三会破坏跨块字符，不采用。二是后续服务 screen/文本日志的必要独立路径，不能以本子步代替；不同实现的边缘映射一致性仍需扩展差分验证。

每个当前连接仅一个解码器，输入块最多64KiB；实际公共事件最多4096字节，因此转换结果最多约12KiB，不扩大256KiB渲染队列。原始HEX读取和输入调度不变。保留BOM字符，不做自动编码检测。状态终止但仍有输出页时继续读取，首次无事件的终止页才flush；不完整尾字节只flush一次。显示文本遇U+FFFD提示核对原始字节，它可能是原始字符或替换字符，不伪造精确解码错误计数。

本地锁定源码检查发现xterm 6的公开reset()仅重置显示与属性，InputHandler.reset未重置控制序列解析器；实际WebView缺口测试复现未结束OSC吞掉后续文本。改经公开write发送CAN/SUB取消残留序列再RIS完整复位，等待回调后清屏；连接切换同样使用该复位屏障，不访问私有xterm字段。

服务保留历史覆盖或接收字节缺口发生时，先排空已接受渲染，再清屏并重置终端解析器和字符解码器；界面持续显示缺口。缺口两侧的字符/ANSI前缀不可拼接，缺口后的首个片段仍可能从某个序列中间开始，不能宣称屏幕完整。渲染队列溢出仍锁定，需要重载，遵循ADR-005。这里的清屏影响显示，不修改服务原始数据或HEX历史。

## 验证与迁移

结果见[P11.1](../records/P11.1.md)。测试使用合成字节和仅测试编译的内存串口，不打开COM。服务screen、日志、SSH旧编码发送/exec、BUG-001 reflow、真实程序与硬件都保持开放。没有schema或持久化变更；回退使用新增revert提交，恢复直接UTF-8显示与旧提示，不重放输入。
