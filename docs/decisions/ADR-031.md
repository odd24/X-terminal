# ADR-031 显式日志整理的句柄快照与部分失败语义

- 日期：2026-11-05（Asia/Shanghai）
- 状态：ACCEPTED（文件库与服务已接入；GUI确认入口待接入）
- 关联：P11.4、R12/R13/R14、T16/T19、ADR-029/030

## 选择与候选

当前日志目录限64项、导出尝试限8项，已满时不能靠自动删除或回收去重证据扩容。候选为递归按路径删除、预览后重开路径删除、持有精确句柄的显式整理。选择第三项：前两项容易把未知子树纳入清理，或在用户确认前后指向不同对象。

terminal-log的ManagedRoot/ExportStore仅提供自身受管理根下非空UUID的preview_cleanup，返回不可序列化的CleanupPreview。Windows逐级祖先/根pin；UUID目标目录用DELETE、FILE_READ_ATTRIBUTES、FILE_LIST_DIRECTORY和不允许delete共享的句柄打开，拒绝reparse。现有logger/ArchiveReader目录pin使预览打开失败；预览存在时同目标新的普通pin也被拒绝。每个固定文件以DELETE/属性访问和share=0打开，拒绝reparse/目录/只读文件，持续持有直到取消或确认。没有新增依赖版本，仅使用现有windows-sys。

预览仅列元数据：类别、UUID、固定文件名和逻辑字节数，不读内容、不宣称内容有效。日志允许最多34个固定原始/文本段或完成/partial文件，导出最多export.jsonl/export.partial两项；不接受自定义文件名、子目录或未知条目。空尝试目录可显式清理，已知名称的坏内容/超大完成标志仍可预览，避免损坏日志因不符合读取格式而无法整理。大小计数checked_add，内容不加载内存；不存在目录和nil标识拒绝。

## 提交与失败

丢弃预览只释放句柄，无删除副作用。apply消耗预览一次；调用方必须先获得可信用户对完整预览的明确确认，不能把JSON中的CleanupInfo反序列化当作授权快照。确认时再次核对目录文件名集合，变化则零删除并报告Changed。随后对已持有的精确句柄逐项调用SetFileInformationByHandle(FileDispositionInfo)，关闭成功标记的文件后再处理目录，不重新解析待删除文件路径、不递归删除。

删除不是事务：任何中途失败返回removed_files/removed_logical_bytes、directory_removed=false、Storage及OS错误码，先前删除不可撤回，不能自动重试或声称回滚。外部同用户进程仍可能添加新名字；提交前出现时拒绝全部操作，途中出现时已批准文件可能已删除，新增项保留且最终目录非空失败，不扩大清理范围。重试须重新预览剩余文件。

logical_bytes只表示被删除目录项关联文件的逻辑大小，不代表实际释放分配空间、擦除数据、压缩/硬链接存储量或断电持久。OS标记删除后关闭句柄是本库成功依据；不承诺异常文件系统驱动的实时完成。Windows语义参考[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)、[FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)及[FileDispositionInformation错误语义](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/12c3dd1c-14f6-4229-9d29-75fb2cb392f6)；实际保证以本仓库Windows临时目录测试为证。本新增整理API仅在Windows编译，不给其他平台提供弱化的按路径替代。

## 服务接入约束与代价

本文件库不承担Desktop身份、预览到期、去重回执、当前任务状态或GUI确认。后续服务须在有界文件actor内保留少量预览，超时/取消释放，提交精确预览ID/目标；拒绝Observer和活动/排队任务，不能通过删除目录重新执行旧Start。当前捕获注册64项/导出64回执不会因文件库目录释放自动回收，必须同步引入有界去重治理；导出成功记录在显式清理后不能继续向GUI声称文件可用。

保留快照会暂时占用最多35个目标句柄及祖先句柄，并阻止同范围读写/rename。服务不能让用户无限持有；当前导出目录计数也会尝试pin子目录，整理期间应明确调度冲突，不能让新任务悄悄失败或扩大目录限额。损坏/未知条目不自动删除；完整故障恢复仍P11.4/P24，物理容量/驱动长稳仍P22。

## 证据与回退

文件库阶段见[P11.4](../records/P11.4.md)：46项日志库测试（新增9项）、严格clippy/fmt通过。覆盖完整/取消/占用、真实8项导出满额后清理一项再导出、64目录释放、未知项/只读/过多条目、坏/超大完成标志、提交前改变、途中注入112和新增未知文件导致145、NTFS junction拒绝并保持目标；硬链接目标外另一个名字和字节保留。服务/GUI清理尚未开放，不将库测试当作产品整理已交付。

回退新增revert，停止暴露整理API；不自动删除或恢复已删除文件，不重建日志、不重放命令。正式GUI接入前仍需权限/预览确认/到期/旧请求不重跑/原生操作等证据。

## 服务接入与有界生命周期（2026-11-05）

新增Desktop专用cleanup_list/preview/status/cancel/commit，全部经active Desktop检查；目录枚举、预览和提交还须配置线程持有数据目录所有权。文件维护按kind(Log/Export)+UUID定位，预览ID与随机确认码绑定原快照；这不是连接输入操作，不从损坏文件头编造ConnectionRef，也不扩展Observer/Agent的会话read票据。没有任意路径/文件名/递归选项。目录列表仅UUID，不宣称记录完整或来源身份；导出根只读枚举不取得写入者的exports.lock，不创建缺失目录，最多64个目录名用于显式整理，写入者8项限额不扩大。

选择独立terminal-log-cleanup文件actor，8队列、最多4个快照、128回执；30秒租期不因查询/重复预览延长，约200ms空闲检查并在每次操作前重新核对期限。确认码只在PREVIEW返回，取消/到期/提交后撤下，旧确认不可用于重新打开。提交复用原预览ID+原确认码返回相同APPLIED报告，改kind/id/确认码拒绝；APPLIED仅表示尝试已结束，是否完整清理必须看report.directory_removed和failure，不能把它当成功枚举。原预览消费后即使同名UUID目录后来重建，重试旧提交也不得删除新内容。

预览/提交与新建记录、导出共享控制gate，已有快照期间明确拒绝新的Start及历史目录/新开读取，已有其他范围的终端收发和读取继续。任何排队/执行中的导出使新整理预览拒绝，避免删除其源或输出。排队预览在入队前增加保留意图计数，由消息而非等待future持有；因此客户端取消等待也不会在文件actor打开句柄前解除冲突保护。提交回执与日志/导出注册失效在文件actor内完成，不依赖发起者收到响应；已接受的提交不能靠关闭客户端声称撤销。

实际删除至少一项或删除目录后，相关本次捕获/导出注册标为REMOVED，停止宣称durable/产物可用。捕获统计保留为历史，导出成功计数清空；仅当已结束失败捕获仍挂在同一ConnectionRef且capture_id完全相同时解除该旧sink，不影响另一份正在记录的capture或远程连接。桌面识别REMOVED且隐藏成功文件路径；已完成产物每5秒进行只读内存状态查询，收到整理状态后自动撤下路径（无实时/外部任意文件改写检测保证）。其他非终态约500ms查询，重载/应答不明仍仅主动查询原ID，不自动Start；RequestExpired同NotFound允许显式新ID。

捕获64注册/Start回执满额只退休已明确整理且可排序UUIDv7的条目，导出64回执允许退休已整理或已结束失败/取消的有序条目，推进共享RequestWindow水位；旧请求及同毫秒未知ID返回RequestExpired，不换动作重跑，保留中的opaque条目固定保留。整理128回执同样只退休关闭的有序预览，不移除活跃快照；opaque占满时明确拒绝，不能偷偷失去去重证据。物理目录64/8限额仍独立。失败且从未创建目录的捕获回执尚不通过文件清理伪造为已整理，其显式维护仍开放；GUI整理和完整长期故障治理继续P11.4/P22/P24。

服务阶段最终138项相关Rust测试、4包严格clippy/fmt、16项前端测试、桌面构建及完整原生回归通过；补焦点后再次构建/导出专项通过，详见P11.4。原生测试消费受限RPC真实预览/确认并核对现有导出UI自动失效，不把它当作已实现GUI清理确认流程；没有真实用户日志删除、真实磁盘耗尽或长稳结论。

## 桌面清理交互（2026-11-05）

历史工具内新增默认折叠的清理面板，独立选择Log/Export类别及完整UUID；不借用活动连接或历史选择。预览期间冻结目标，显示全部受管理文件/逻辑字节和北京时间期限，必须重新勾选明确确认后才能提交。确认码仅在本次内存快照中使用，sessionStorage只保留kind/id/preview_id，重载只查询原编号，不恢复文件、确认码或勾选。该选择沿用现有导出任务恢复方式，避免页面重载隐式再发删除；代价是应答不明时用户须明确查询/取消后才能切换目标。

桌面校验响应作用域、文件白名单/数量、精确整数总量、期限及不可撤回的实际删除前缀。APPLIED只报告尝试结束，只有directory_removed且无failure显示完整结果；CHANGED和STORAGE保留目录/失败码及精确已删计数，不自动重试，不宣称回滚。前端本地时间仅用于禁用过期确认与倒计时，服务期限仍是最终依据，查询不续期。错误撤销勾选，未知提交只查询原回执；用户仍可显式取消，但取消不能撤销已执行删除。关闭面板取消尚未提交的预览，迟到响应再次释放；已提交/未知提交保留可恢复编号。

目标日志被删除/改变后，只清除其对应历史目录项/缓存页和搜索显示，不改选另一个日志或写入终端；导出目标仍通过原有REMOVED轮询失效。使用公共details/fieldset/button/input/select/pre和焦点样式，完整UUID可换行，失效时焦点回到查询入口。原生test:desktop:cleanup验证真实WebView/IPC/文件结果，全部数据为自建中文临时目录合成输出；部分存储失败的报告形状由前端实质单测和已有文件库故障测试组合验证，没有把合成成功响应注入当作实际删除。

无目录失败捕获回执维护、自选保存位置/打开目录、失败前缀恢复仍继续；不据本面板宣称完整P11.4/T16/T22/T23或真实磁盘/长期可靠性通过。回退新增revert，停止暴露面板，不能恢复此前已经删除的内容。
