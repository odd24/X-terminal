# ADR-076 原撰写队列中的有界逐行发送

- 日期：2026-11-09（Asia/Shanghai）；状态：ACCEPTED；Step-ID: P19。

按CR-006 S3/R09补撰写节奏。候选为新增两协议服务端定时任务、复用串口按字节节奏、或原桌面FIFO内逐行调用现有发送。前者需要新任务/权限/恢复协议，串口字节节奏不能直接表达SSH及原文行界；本包选择桌面FIFO内一个有界任务，不改协议、授权、schema7或底层传输，不扩大到广播/触发器。每片段仍由原服务统一输入调度，不能保证与其他客户端的输入原子隔离。

原基础撰写默认0，沿原整批路径。主动设50–1000毫秒整数时，预览冻结完整目标、草稿revision/选区、末尾和间隔；改参数撤预览。CRLF为单界、CR/LF分别为界，保留空行、控制字面量和Unicode，不补额外末尾。最多256片段、计划间隔合计60秒；沿原正文与两协议字节预算，不把间隔预算称整个任务完成期限。只有上一片段可信发送回执后才开始目标间隔，实际受浏览器、服务和网络调度影响可能更慢，不承诺硬实时。

一个任务占原16项FIFO的一项；每片段独立随机request_id，原编号查回执，不重复Start。每次派发前检查原service owner/协议/完整代次/活动路由epoch/连接状态，路由改变不向新目标投递。手动停止、关闭面板、切目标/焦点、终端键盘/粘贴、重载/销毁停止未开始尾部；等待间隔可唤醒取消，在途动作只能等待原回执，不能撤销已经决定的服务操作。失败/未知立即停尾部并沿原队列失败封闭，不自动重试或重连；原编号服务回执仍由既有接口保留，不增恢复派发按钮。

逐行模式保留原草稿及未选部分，不自动移除、补回或重发；界面明确再次发送可能重复已发前缀。进度只计算可信SSH管线/UART驱动回执，不等远端执行。后续片段编码失败可能留下前缀，预览须说明。为避免把未发尾部记录为已入队历史，本包逐行不写撰写历史，原整批/选区历史保持。间隔、进度、正文和同意只在窗口内存，无数据库/日志字段；关闭/切换后的新面板回默认0，无自动续发。

验证模型行界/Unicode/预算/冻结、回执后间隔、单FIFO占位、取消在途和间隔、路由/关闭/未知封闭；实际desktop:build后新第41入口合成SSH/内存UART核对精确字节、每行不同编号、真实应答挂起/丢失、取消/关闭/切换/人工接管、默认及重载。原撰写/选区/历史与键盘延迟按影响复验，内存feature finally实际恢复普通服务。真实COM/SSH现场、长稳、全部入口/全局DPIIME及完整P19/R09仍分别留验。回退移除逐行模型/面板入口，不动用户库或日志。
