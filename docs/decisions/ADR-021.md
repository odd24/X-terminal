# ADR-021 exec 任务结果的容量回收

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED
- 关联：P09、P14/P15/P22、ADR-016/ADR-020

## 决定与替代

原每连接 16/全局 64 项任务结果满额后永久拒绝新任务，不适合长期工作。提高上限仍然耗尽；直接丢弃随机请求 ID 会使旧请求重新执行；永久落盘需要额外容量/恢复契约。沿用 ADR-020 的有序请求退休水位，只在容量需要时回收已结束、已从 FIFO 取出且请求 ID 为有效 UUIDv7 的任务。各连接独立水位，不把一条连接的退休范围扩展到另一条。

保留每连接 4/全局 16 个活动任务、每连接 16/全局 64 项结果上限。局部满额先找局部可回收项；全局满额可从任一连接回收符合条件的最旧时间桶任务。无法回收时明确 CapacityExceeded。请求先检查完整重复/指纹冲突，再检查输入/任务退休水位；预留 FIFO 槽后才回收，在同一 manager 锁内再次核对水位并创建。满额新请求若处于刚退休的桶，会被保守拒绝，不重新运行。

对于有序请求，task_id 等于 request_id，仍以 connection_id/generation 共同限定；其 ID 可直接经过同一退休水位判断，从而不需要无限增长的 task_id 墓碑表。旧不透明请求继续产生随机任务 ID、不回收，保留原去重保障。API 从未承诺 task_id 必须与 request_id 不同，均仍为 UUID。任务身份不能当作授权。

回收同时删除有界任务状态、输出和请求指纹，并推进不可回退的时间桶水位。旧任务 status/read/cancel 和旧 exec 请求明确 RequestExpired；旧 ID 转 write/resize/reconnect 同样拒绝。尚保留记录优先返回，避免运行中旧时间戳任务被较新结果退休影响。未知 ID 在水位之前保守报过期，不宣称它确定曾执行或从未执行。

取消排队任务会立即显示 Finished，但 FIFO 仍可能持有它；直到 launch 实际取出并设置 dequeued 才能回收，否则稍后队列消费会因缺任务导致整条 shell 失败。运行中/取消中均不可回收。后台作业启动、迟到输出和完成回写均须匹配原 connection_id/generation 与任务 ID，不能写入新代次复用同一任务 ID 的任务。

桌面 exec 使用已有 UUIDv7 生成器，本页仅保留最近 64 项元数据，移除页面条目不会取消服务任务；仍可在服务保留期内按 ID 查询。界面明确局部/全局结果上限及已结束结果可能过期，不承诺保留整个 generation。命令不持久化、不进任务列表，不自动换 ID 重跑。

## 证据、代价和回退

具体测试结果见 [P09](../records/P09.md)。新增局部/跨五连接全局回收、运行任务与 opaque 结果保留、旧 ID 查询/换动作拒绝、服务端执行次数，以及取消未出队不可回收。原生桌面连续 70 个任务跨页面/服务结果上限并验证过期查询不重跑。不得以快速循环代替 P22 的长稳/尾延迟。

成本：结果/输出可能因其他连接创建任务而提前过期，不能永久取回；时间回拨/客户端乱序可能保守拒绝，沿用 ADR-020 边界。旧 opaque 客户端仍有有限容量；连接历史 64/1024 上限另行处理。没有新增依赖/数据库迁移。回退用新增 revert；重启服务不会恢复或重放任务，Git 无法撤销已发送远端动作。
