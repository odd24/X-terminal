# ADR-004 MCP SDK 与 stdio/IPC 边界

- 日期：2026-11-03（Asia/Shanghai）
- 状态：ACCEPTED（P06 mock SDK/stdio 结论；真实 IPC 尚未实现）
- 关联：P06、R11/R13；P07/P15

## 候选、证据与决定

| 候选 | 证据 | 许可/成本 |
|---|---|---|
| 官方 Rust SDK rmcp 3.8.0 | 中文路径构建、stdio 契约测试、本机 Codex app-server MCP 客户端发现/调用通过 | Apache-2.0；与 Rust 服务共享类型，选用 |
| 官方 TypeScript SDK | 未做本机原型 | 需额外 Node 运行时；本步不选择 |
| 手写 MCP 协议 | 未作为产品实现 | 版本、取消和协商维护成本；仅测试客户端使用小型 JSON-RPC 驱动 |

使用 rmcp 的 server/transport-io，关闭默认 features，仅提供 stdio；没有 HTTP 监听端口、模型 API 或密钥管理。schemars 1.2.3 生成工具 schema，serde deny_unknown_fields + 服务运行时检查共同约束参数。锁定版本见 Cargo.lock。

原型必须 `--mock` 显式启动；只有 `sessions_list` 与 `terminal_read` 两个只读工具，结果显式带 mock=true。单请求行上限 128 KiB，read 预算 4–65536 字节，最多 4 个并发工具处理，多余立即返回 INPUT_BUSY。取消通过 SDK RequestContext token 释放处理容量，EOF 清理进程。stdout 只输出协议，诊断 stderr；不依赖客户端注解实施授权。

## 真正的共享会话边界

正式方向仍是 Codex → MCP stdio 桥 → 当前用户 Named Pipe → session-service，尚未实现 Named Pipe、配对、ACL 或真实会话授权。P06 的固定 connection/generation 只用于契约，不是权限引擎或生产 session-core 替代。生产工具在 P15 接到 P07/P14 服务，禁止桥接直接打开 SSH/串口。P06 mock 游标是 UTF-8 字节偏移，最终 cursor 语义需在 P07/P15 版本化，不能直接移植为真实输出保证。

## 客户端实测范围

Codex CLI 0.163.0-alpha.10.2 的实际 app-server MCP 客户端，在独立 CODEX_HOME 测试目录与命令行临时配置下发现并调用两个工具。测试只创建进程内 ephemeral 测试上下文，不创建侧栏聊天、不进行模型推理/委派、不复制用户认证、不修改用户全局/项目配置、不绕过组织策略。不是由模型主动选工具的端到端测试，也不是桌面 UI 客户端验收。

官方当前文档支持 stdio 命令配置，CLI 也支持相应临时覆盖。桌面版本/策略与真实终端闭环留到 P16；CLI 成功不代表桌面成功。

## 影响与回退

后续 SDK 升级必须重跑旧版本协商、取消、EOF、帧边界和实际 Codex 调用。当前协议测试协商到 2025-03-26，不声称所有协议版本通过。回退 P06 提交移除 mock 与测试脚本；用户全局配置无需恢复，因为未修改。`.tools/codex-p06` 与 artifacts 是可删除的本地测试状态，不含复制的认证文件。
