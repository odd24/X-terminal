# ADR-012 配置备份预览与事务恢复

- 日期：2026-11-04（Asia/Shanghai）
- 状态：ACCEPTED（存储层及服务/桌面阶段已验证）
- 关联：P08.3、R05/R13/R14

## 决定

恢复不通过覆盖正在打开的 SQLite 文件实现，而是读取备份的一致逻辑镜像并在当前配置库中事务替换目录/Profile/公开主机密钥。镜像含 credential_ref，但没有凭据材料；vault 不被该逻辑恢复。便携 JSON 导出仍使用原 PortableProfile，排除引用/主机信任。配置备份和便携导出不能混称为同一格式。

ConfigImage 在 SQLite 读事务内核对 application_id/schema/quick_check/外键，读完整数据并验证数量、字段、目录循环、重复 ID、缺引用及密钥约束。逻辑内容有序序列化到 SHA256 写入器，不另分配完整大 JSON；预览调用方持有摘要，确认时重新读取并匹配摘要，拒绝过期内容。不是用原数据库文件字节哈希，避免忽略 WAL 中的已提交内容。当前新服务备份为 schema v2；read_backup 对其他版本拒绝，已有 v1 到新路径的迁移仍使用 P08.1 restore_to_new，不修改源文件。

单备份限 64 MiB、拒绝叶符号链接。配置连接启用 SQLite 64 KiB 行/字符串长度限额；Profile 读取时立即校验，避免累计大量非法长字段。有效 Profile/16 KiB 公开密钥在此限额内；不影响独立凭据库的 64 KiB 秘密限额。

## 恢复顺序

先验证镜像/摘要，BEGIN IMMEDIATE 后再次检查目标 schema；持有写入预留锁时，第二只读连接通过 Online Backup API 将精确旧库写入 create_new 的安全副本。副本创建/写入失败不进入替换。随后一次事务删除/写入所有目标表，defer_foreign_keys 支持名字排序中子目录先于父目录，提交前检查完整引用。失败回滚，不悄悄重建或降 schema。保留目标的既有 schema/触发器，不把备份中的任意 SQL 拷贝到目标执行。

库方法不分配外部任意路径，安全副本路径由受信任调用方提供；后续服务会限定目录/UUID、预览与用户确认。异常/掉电的最终持久结果及副本发布规则在 P24 进一步注入，不能把当前 SQL 回滚测试当作所有 OS/磁盘故障通过。部分备份文件失败后可能留在新路径，不能被当作成功镜像。

## 验证与回退

真实 SQLite 测试验证嵌套子目录先写仍恢复、Profile/凭据引用/主机信任恢复、精确旧镜像的安全副本、重启保留、源备份不变、拒绝覆盖已有副本；注入 INSERT 触发器让事务已删除旧行后失败，旧数据全部保留；未知源 schema/非 SQLite/缺父 ID 拒绝；预览后修改源内容导致旧摘要拒绝，活目标变成较新 schema 时不创建副本、不写目标文件。详见 [P08.3](../records/P08.3.md)。

回退本阶段库方法不改已有数据格式。服务/GUI 后续阶段见下文；凭据整理尚未完成，父 P08.3/P08 保持 IN_PROGRESS。

## 服务与桌面入口补充

服务只接受 UUID 副本 ID，不接受客户端任意恢复路径；固定 artifacts 目录内最多 64 个已发布副本。普通备份验证 .partial 后通过 Windows MoveFileW 不覆盖发布；恢复前的安全副本仍由事务恢复库方法 create_new 创建。Desktop 权限检查在进入工作队列前完成。预览的源摘要和目标 revision 均须匹配，故障不自动重试。坏库初始化失败仍持有目录占用锁，只开放副本读取/删除及新目录恢复。

新目录命名 recovered-UUID，限 16 个，恢复成功后写 recovery.ready；不复制凭据库，缺引用在配置列表/预览中明确提示。当前开发版返回完整目录供 --data-dir 启动，启动选择及完整故障向导留 P24。失败 partial/未 ready 目录可能留存，不作为成功产物。凭据显式遗忘和孤立项整理继续实施。
