## 逐字段映射与明确缺项

下表只列静态模板可见的键；“可对应”是研究映射，当前没有接受该格式的解析入口。

| 源概念/公开模板位置 | 本应用目标 | 当前结论 |
| --- | --- | --- |
| CONNECTION节的Host、Port | SSH Settings.host/port | 名称/语义有依据；仍须完整来源版本、协议及严格值校验，缺端口不补22 |
| 同节Protocol | Settings协议分支 | 模板从PuttyCM透传，不能据此认定取值集合或把SSH默认为SSH2；未支持 |
| 同节Description | 无直接字段 | 不借作配置名称/路径或执行内容；未支持，不静默抛弃后宣称等价 |
| 同节IPV | 无直接字段 | 模板固定0不证明全部枚举及语义；未支持 |
| CONNECTION:AUTHENTICATION节的UserName | SSH Settings.username | 可对应用户名；空值不能猜当前Windows用户 |
| 同节Password | 不映射 | 无论空/密文/明文均不导入、不解密、不写Vault，不据存在此键推断auth |
| 模板中的登录脚本、转发项 | 无对应迁移字段 | 存在额外自动动作/转发语义；报告未支持，不能仅删去后称完整配置 |
| 会话名称/层级 | Profile.name、Folder引用 | 模板以输出文件名/目录组织；不能推出.xsh内部名称键、跨文件引用/唯一身份；本包不扫描目录 |
| 认证选择/密钥/代理/跳板 | Settings.auth及实际认证端点 | 模板不提供完备契约；缺失或存在本应用不支持语义均阻止生成可应用Profile |
| 终端编码 | Settings.encoding | 文件编码不等于终端编码；不能填UTF8/GBK等默认值，未支持 |
| SSH1 | explicitly_enabled及完整参数 | 无可靠版本/显式启用映射，未支持；保留原SSH1需求 |

## 后续有限解析的准入边界（尚未实现）

只在获得明确版本/序列化及完整必要设置依据后另开实施包。建议复用原生单文件安全读取和事务预览，但不放宽现有JSON入口：最多单个64KiB普通本地文件、无目录扫描/归档解包；文本层最多1024行、单行4096字节、128节/512键、64条白名单问题，超限整件拒绝。编码只接受明确契约和严格解码，不按系统代码页猜ANSI，不静默替换坏字节；BOM/字节序未确认前不据“版本6”自行判断。版本缺失/未知、重复键/节、大小写别名、未知转义的处理须先有契约，否则拒绝，不采用最后值覆盖。上述是后续安全预算建议，不是已支持的Xshell限制。

未支持报告仅白名单代码、行号、已知安全字段名/类别；未知名称可能本身含秘密，只给“未知字段/节”和数量，不输出原名、值、路径、源片段、摘要或解析异常。秘密字段即使未映射也不得进入WebView、日志、审计或持久回执；不借配置导入触发脚本/转发/连接。必要协议/认证/终端编码/控制线缺失时只能报告，不生成可应用配置。安全完整映射成立后，新增Profile始终无credential_ref、无Vault写、无自动连接；再复用ADR-080冻结源字节、逐字段差异/独立同意、原服务owner回执、CAS单事务及失败无部分写，不新写导入引擎。

## 最小授权样本与验收条件

后续由用户自行选择提供、明确授权的最小脱敏导出即可，不要求密码/私钥/主密码；本轮不索取或搜取样本。需产品版本/build、导出方式、原文件编码/BOM及一份对应UI非秘密设置说明；SSH2至少明确协议版本、占位端点/端口/用户名、认证方式、终端编码，SSH1另有显式开关，串口另有全套参数及控制线。去除所有真实口令/密文、密钥路径/正文、认证令牌、脚本、转发和业务地址；保留原结构时应标明删除字段，删掉必要字段的样本只支持结构研究，不作为成功导入fixture。未知字段须经授权脱敏，不能通过改名编造官方键。
