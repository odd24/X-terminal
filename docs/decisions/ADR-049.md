# ADR-049 建连请求的认证归属与异步派发

- 日期：2026-11-06（Asia/Shanghai）；状态：ACCEPTED（P14分阶段软件接入，真实结果见P14）。
- 关联：R11/R13、T13/T14/T17、P14、ADR-044/045/048。

## 选择

候选为仅放宽Runtime角色、在MCP保存归属、在原服务Start回执内保存认证来源并复核派发。选择第三项：原有有界Start指纹新增内部owner，None代表可信Desktop，Agent为真实ticket_id。不同来源不能借用同一UUID，即使配置和尺寸相同；同来源参数冲突仍InvalidArgument。归属随原1024回执及UUIDv7退休水位回收，不新增永久表、公开owner字段、依赖或数据库迁移。

新SSH Start需要精确Profile UUID上的Connect，不要求已有连接租约，也不推导新ConnectionRef上的Read/Write/Exec/Control/Disconnect。先认证及查询保留回执，再为新请求捕获不可序列化Permit，之后才异步查配置；配置返回后复核同一身份和许可，最终创建连接/入账/调度也在Store协调边界内复核。已完成的同来源Start重试只是查询原ConnectionInfo，删除Profile、连接结束/移除不会重新建连；票据撤销或过期仍拒绝查询。

SSH Actor实际首次轮询连接future前，再与撤权共用Store锁复核并进行首次poll。该派发决定涵盖DNS/TCP连接尝试，之后已开始的操作不会因授权撤销被声称回滚；原Desktop关闭仍能取消连接。尚未首次派发时失权，Actor以Cancelled失败结束，不连接对端。短锁只包首次非阻塞poll，不跨await持锁，不把创建Start回执当作已经建立SSH或通过认证。

## 边界、验证和回退

主机信任、凭据及交互认证批准继续仅Desktop；Agent不读取challenge、秘密或配置，不通过Start获得终端输出。SSH Reconnect/Forget、串口Start与Disconnect在后续独立子步实现，不能由本子步推导已开放。GUI的Connect选择及真实stdio桥安全令牌交付仍继续，不把服务能力当用户授权流程已交付。

实际验证必须覆盖真实Windows IPC的同来源并发/重连恢复、跨来源冲突、独立Profile范围、无隐式Read/lease/认证批准，以及原连接删除后不重放。配置查询等待和Actor首次派发前撤销/到期须有确定性测试及无实际socket接受证据；不能以sleep推测请求已进入等待。结果与未执行检查见[P14](../records/P14.md)。

回退用新增revert关闭Agent Start并保留Desktop路径和旧去重行为；不重放原请求、恢复授权或撤回已经执行的远端动作。完整P14/持久审计/全部阶段门保持开放。Step-ID: P14 / Decision-ID: ADR-049。
