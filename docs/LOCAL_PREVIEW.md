# 共享终端 0.1.0 本机开发预览

2026-11-08已接入简洁SSH2直连和基本文本日志，S1软件阶段收尾后按[主方案](EXECUTION_PLAN.md#现行路线cr-006)推进S2串口/UART单弹窗与基本日志。新流程的软件与真实使用证据分别记录在[P12.1](records/P12.1.md)、[P10.1](records/P10.1.md)。

这是供当前Windows电脑直接试用的开发预览，尚非正式安装包或完整v1。需要Windows及WebView2；干净系统安装、升级与签名未验。

## 启动

保留同目录的三个文件：`shared-terminal-desktop.exe`、`session-service.exe`、`terminal-mcp.exe`。双击第一个。默认使用应用用户数据目录；隔离试用可以运行：

```powershell
.\shared-terminal-desktop.exe --data-dir 'C:\Users\你的用户名\Documents\共享终端试用'
```

使用新的自建目录，不手工覆盖旧配置。关闭主窗口会停止本窗口连接和服务。此预览不自动重连或重放命令。

同一数据目录一次只能由一个窗口服务使用。若旧版仍在运行，新版会明确提示配置目录被占用，不能读取/保存配置或继续登录。先保存旧窗口中的工作并正常退出旧版，再重新启动新版；旧版退出会停止其连接。不要在两个版本间同时使用同一目录。

## 基本使用

1. 点顶部“连接服务器”，在居中弹窗填写地址、用户名和密码，或选择密钥并填写本地私钥路径/口令。端口默认22，其他端口或编码在“高级连接设置”展开。无需先保存配置。“连接配置”和“外观”也使用弹窗，会话导航保留侧栏。
2. 首次连接或指纹变化时，在同一表单通过可信渠道核对完整指纹，再明确确认。认证信息只用于本次；仅主动选择“保存连接”和“记住凭据”时才保存Windows受保护凭据。保存连接可选，下次在同一表单选择。

已保存SSH2连接可从“会话导航”直接双击，或右键该项选择“连接”。有可用保存密码/密钥时自动认证一次，正常无需再选配置或点击凭据按钮；缺失/被拒绝才停留补录，首次/变化指纹仍需核验。连接进度完成后自动进入终端。快速重复手势只发起一次；完成后再次明确连接会新建独立实例，同地址标签不合并。
3. 登录成功后弹窗自动关闭，焦点进入终端。标签只显示服务器地址，同地址连接各自独立；状态/精确身份见底部和标签提示。失败时弹窗保留并明显说明已知原因及下一步，信息不够时只报告网络/SSH大类，不推测精确故障。多行粘贴先预览；发送成功不代表远端命令已执行。断开/重新连接时再次打开连接窗口，重连需重新登录，不重放命令。连接结果不明时只“查询本次连接”。Esc/关闭会取消尚未完成的本次登录，已连接会话保留。

关闭会话直接点标签的“×”，不弹确认，对该连接代次请求断开并隐藏；不删除配置或日志。关闭结果不明会提示且不重复发送，服务已显示结束后可直接隐藏该标签；迟到旧应答不会隐藏重连新代次。程序退出仍有独立确认。关闭连接表单与关闭会话标签是不同动作。

读取配置失败会在连接弹窗内直接显示原因并禁用连接。选择保存时，保存失败会明确说明“尚未发起SSH登录”；保存应答不明只“重新读取配置”核对，再明确选择已保存目标，不会自动重复保存或继续登录。密码提交后会清空，空框不能用来判断上一请求是否填写密码。
4. 点“终端日志”→“开始记录终端”，记录之后的服务器输出/终端回显。结束时“停止记录终端”；点“查看日志”预览，或点一次“保存日志”，程序准备文本后直接打开系统位置选择器，选择`.log`位置即可。完成后显示保存位置并可“打开目录”。结果不明时才显示“查询保存结果”，不会自动再保存；已有文件需独立确认且保留备份。任务编号及高级历史工具默认折叠。

文本日志为UTF-8，含来源、代次、开始时间和实际保留范围；控制字符安全显示，缺口会明确标记。起录前内容和独立发送的未回显内容不补录；认证表单密码/密钥/口令不进入日志。服务器主动回显的秘密仍是终端输出，使用时注意自己的终端内容。停止/关闭连接后的最终状态以记录回执为准，失败或缺口不能当完整日志。

## 串口/UART

点顶部“串口连接”，在弹窗选择实际设备端口、填写波特率（默认115200），核对初始DTR/RTS后点“连接串口”。默认8N1、无流控、UTF-8、DTR/RTS低电平；其他设备参数在“通信参数与控制线”展开，硬件流控的RTS由驱动管理。端口身份不明不会按COM号回退打开；插拔后刷新端口并重新选择。

无需预先创建配置，保存连接可选。连接成功后弹窗关闭，回到终端持续接收；只抓UART日志不需要发送命令。连接下方一行显示接收字节和状态，不挤占终端列宽。需要发送时，可在终端输入，或点“发送与接收详情”，在弹窗展开“发送、HEX与控制线”选择文本/HEX和CR/LF/CRLF；不要向不明设备发送内容。顶部“终端日志”的开始/停止/查看/保存与SSH一致。断开可用标签“×”或“停止发送并关闭串口”，已交给驱动的字节不会撤销。连接结果不明时只查询原编号，重载不自动重开或发送。

保存的串口配置从导航双击/右键连接会预填参数，仍须选定当前真实设备并显式连接，不能把过期库存当现有设备。旧完整串口工具在“更多工具→串口高级工具”。用户暂时没有设备，本轮只用内存夹具验证软件，不打开真实COM；真实电平/拔插/驱动/Android板端待后续验证。Android UART不等于ADB，不要套用合成COM7。全局DPI/输入法、长稳和全部SSH认证/算法矩阵继续按记录追踪。

## 窗口内标签分组

按需打开“更多工具→标签分组”，输入名称新建分组，在“会话归属”中为每个独立实例指定组；同地址连接仍分别列出。可以调整组顺序、改名或“解散分组，保留连接”。原标签条上的组标题也接受标签拖放，左右移动按钮只在同组内移动，键盘箭头仍可选相邻标签。分组不建连、不发送、不关闭会话，所有标签仍可见；隐藏的已结束标签可从管理窗口显示，不会重新连接。

未保存的分组关闭或重载后清空。需要下次复用时，可用下述工作区布局；分屏见下节，符合保存条件的两个窗格可随工作区保存。SSH直接连接、标签地址和关闭无确认规则保持。真实软件证据与剩余范围见[P17](records/P17.md)。

## 保存与打开工作区

在“更多工具→工作区”输入名称，点“保存当前布局”，保存当前可见且已有保存配置的标签、组、顺序和两窗格排列；每次创建一份新布局，最多8份。临时会话/未连接项不纳入，略过数量会显示，需要复用时先明确保存连接。任一窗格是临时、变化或不在本次快照中的目标时，只保存其他可用标签/分组并明确略过本次分屏，不自动挑别的连接替代。

选择布局后点“打开布局”，再在待连接栏逐项连接。若保存了两窗格排列，只有两个指定连接项都明确连接后才一次恢复方向及保存的活动项；部分连接保持单终端，缺失配置禁用，不用其他同地址现有连接补齐。每次打开都清空旧布局绑定，当前连接继续保留，不会自动猜测复用。可点“取消分屏恢复”，手动选其他标签、关闭目标、修改或收起分屏也会取消本次待恢复，避免迟到回调改动布局。打开本身不会自动登录、打开串口或发送；已有连接保留，也不会按同地址猜测复用。SSH沿当前配置/必要指纹与认证流程，串口仍选择当前设备并明确连接。配置已删除的项会禁用。收起布局和删除保存布局都不关闭当前连接，删除需独立勾选。结果不明只重新读取核对。

布局纳入本数据目录配置备份，恢复前显示数量；不含旧连接身份、认证、授权、正文或草稿，便携连接JSON不含布局。本次配置格式为schema6；首次升级旧库前生成`config-before-v<来源版本>-<UUID>.sqlite`，从上一schema5升级时为`config-before-v5-…`。旧版不能读取或写入新库，不能在同一目录任意交替新旧版本。新版界面恢复旧备份只恢复配置内容，库仍为schema6，并不使旧版兼容。schema5旧布局按单窗格读取，原副本不改写。迁移副本不含凭据库或日志，不是完整目录备份；实际降版本/完整目录回退未验证，需保留升级前完整目录副本并单列处理，不手工改库或覆盖正在使用的目录。

## 本窗口分屏

先连接两个SSH或串口会话，选中其中一个，在“更多工具→分屏”选择左右/上下排列和另一个已连接会话。第二目标默认空，同地址实例以协议、代次和短ID区分；创建不会新建连接。

点击窗格或按F6切换当前输入，标题标明“当前输入”；全局复制、粘贴、查找、撰写、日志和设备详情跟随该窗格。选另一窗格已有标签只切换焦点，不重复展示同一连接。切换取消待确认输入，已发送的动作不会撤销；应答不明不自动重发。两边继续独立显示输出，SSH尺寸按实际窗格更新，串口只调整本地显示。

“收起此窗格”和“收起分屏，保留连接”仅整理显示；真正断开仍点标签×。远端结束后保留输出、停止输入；代次变化需明确选择当前会话，不自动采用新代次。默认单终端，重载后不自动打开布局或连接、不重放输入。可用“工作区”保存两个有保存配置的窗格；下次明确打开后逐项连接，再恢复排列及活动项。只保存方向和布局引用，不存实际连接代次、正文或授权。

## 常用命令

“更多工具→常用命令”或Ctrl+Shift+K打开命令库。按组保存命名模板，变量写成`{{name}}`；填写全部变量后点“准备到撰写”，再在原撰写面板预览和确认发送。只作用于当前就绪连接；已有草稿需明确勾选替换。切换目标或配置变化会取消本次准备，选中、保存及准备都不自动发送。变量按字面替换，不做Shell转义。

模板随配置保存和备份，请勿在模板中保存密码/令牌；变量值与发送同意不持久化。最多64条命令、16组。新配置schema7，升级前保留旧库副本；旧schema6及更早程序不能读写升级后的库，恢复备份内容不等于降版本。完整多目标发送/历史/节奏仍待后续。

## Codex共享当前会话（高级）

1. 在“Agent 授权”中选定已连接目标的精确代次，预览并明确批准Read；确需输入时另勾Write和合适期限。批准本身不发送。
2. 展开“MCP 初版连接”，刷新并复制本次公开启动参数。实例及Desktop PID每次启动都不同，不能沿用上次值。
3. 在支持stdio的Codex中使用显示的command/args启动此MCP。先看工具发现，再回桌面刷新，核对实际桥进程PID及原授权编号，预览完整范围并明确勾选确认。token始终留在原生端。
4. 先让Codex只读检查。发送需独立取得输入lease（最长60秒），明确connection_id/generation/request_id和精确正文；不会自动补换行。应答不明只查原编号，不换编号重发。人工输入可接管，撤销不会撤回已执行动作。

临时CLI只读检查可用`codex exec --ignore-user-config --ephemeral --sandbox read-only -c 'mcp_servers.windows_terminal.command="实际路径"' -c 'mcp_servers.windows_terminal.args=["--stdio","--broker","本次instance","--desktop-pid","本次PID"]' '仅检查指定连接，不取租约或发送'`。路径中的Windows反斜线须按TOML/命令行规则正确转义；优先使用界面显示的实际参数。此命令不改全局配置；需要保留现有其他工具时先核对自己的配置，勿覆盖。Codex登录/模型服务需另可用。

本机Codex 0.163.0-alpha.10.2的`exec`模型已经识别实际配对和同会话，但取写入lease被客户端以“requires approval, but approval policy is never”拒绝，实际未发送。桌面授权不能代替Codex自身批准；模型写入需要客户端正常可见的交互批准流程，当前未验通过，勿用降低工具真实属性或绕过审批的参数解决。独立显式app-server客户端的共享发送/回执/读取已通过；这不代表模型自主写入或Codex桌面GUI通过。

当前9工具：agent_status、sessions_list、terminal_read、terminal_screen、terminal_send、terminal_input_status、input_lease、input_acquire、input_release。输出先Info再固定through_cursor分页；受保护票据不能绕过保护。配对快照不等于当前权限，服务持续核对到期、撤销和代次。一次只连接一个桥；应用重启后重新启动/配对。

## 限制与反馈

SSH1正式桥、复杂工作区/分屏、广播/触发器、完整MCP工具、真实设备/程序兼容、全局DPI/输入法、长期压力及安装升级仍待后续。合成SSH与内存串口专项不代表真实设备通过。极限历史重排有已知差异；缺口和未完整日志不能当完整输出。

发现问题请记录版本、协议、连接代次、时间、操作和脱敏错误，不提供密码、私钥或真实设备正文。删除本预览目录不会删除默认用户数据；退出后妥善保留自己的数据，不手工降级配置schema。
