# CR-015 配置目录锁状态复查与连接错误分类

- 日期：2026-11-09（Asia/Shanghai）；来源：用户“现在没有重复打开该软件，为什么显示端口被占用”；Step-ID: P12.1；状态：IMPLEMENTED（配置锁现场与自建IPC/原生软件验证，真实COM未操作）。

现场截图实际为配置目录LOCKED，不是COM打开的ACCESS_OR_BUSY。当前仅一个桌面及其子服务，锁已释放但错误保留，不能假定用户重复启动或确定启动时的占用者。优先修复基本连接，暂停无关S3。

连接窗口明确区分配置读取、端口清单与实际打开失败。LOCKED说明是启动时未取得配置权、当前需复查，不假定另一个窗口仍存在。新增明确“重新检查配置目录”，仅同一认证服务和固定原目录尝试原独占锁；正常读取不触发，已持有状态不重开库，错误不重置/覆盖库。成功后只读取配置/库存，保留当前输入；不自动Start、认证、开COM或重放保存。关闭/迟到不改变其他会话。

沿ADR-075实施协议、服务、共享SSH/UART控件及自建根专项；必须实际构建，只受影响验证。用户真实进程/窗口/日志不操作，不删锁/数据库、不旁路独占锁，不探测打开COM89。当前旧版可正常关闭本窗口再启动以清除滞留状态；新版提供同窗口复查，具体现场/验证/交付见P12.1记录。完整实机/全局验收保留。
