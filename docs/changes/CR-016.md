# CR-016 普通日志保存直达与自动收尾

- 日期：2026-11-09（Asia/Shanghai）；来源：用户“保存日志操作不够简洁……选中位置后应该直接保存……不需要再次点击保存，还要收起弹窗”；Step-ID: P11.4；状态：IMPLEMENTED（最终桌面构建/定向原生软件验证，实机另列）。

现状核对：系统选择器的新文件路径返回后，原生worker已直接copy/校验/sync/发布，并非必然没有落盘。误导来自“选择保存位置”按钮、MENU/TEXT重复常驻“保存日志”，以及MENU成功后继续显示操作面板。只修复普通流程与反馈，复用原发布/校验/覆盖备份引擎，不重建向导或扩S3。

主流程：右键导出→系统窗口填写路径/文件名并点“保存”→自动写入/校验/同步/发布→可信COMPLETED回执后自动收起本次MENU操作面板并交回仍匹配的原窗格焦点，简短非阻塞反馈含路径；最近成功路径按原服务/协议/完整代次在菜单保留查看/打开目录。系统取消或确认取消只结束本次普通保存UI，不续存；失败/到期/需要恢复/结果不明保留明确界面和原编号查询，不混作成功。TEXT共用保存控件终态改行内回执，“另存一份”是另一次明确意图，不是本次完成的必要步骤。

普通新文件不再有应用内第二个保存按钮或确认；已有文件仍需独立明确同意、目标核对和备份。切换/关闭撤下旧自动UI，不对新目标弹窗/抢焦点，已发布动作不能承诺撤回。完成回执先存入子控件再通知父级，卸载不得误cancel或删用户目标；临时源清理仍走原受管理路径，实时/用户另存文件保持。未知仅查原编号，不自动重放。实际构建后用合成SSH/内存UART及自建根真实系统选择器验证一次动作到字节/SHA/焦点、取消/覆盖/错误/丢应答与迟到，再交付预览；真实日志不作fixture。
