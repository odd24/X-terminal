# CR-022 终端模拟器桌面界面与操作需求

2026-11-20 · 产品需求首稿 · 首稿状态 PROPOSED（记录用户偏好，实施及分项验收见后续记录）

后续维护以[现行桌面交互基线](../UI_GUIDELINES.md#现行桌面交互基线)为准。下文保留问卷、四场景首稿和原始验收条件，首稿的工具与标签同排已改为独立工具栏和各窗格自己的标签栏。阶段记录中的全界面纯黑、同名标签短编号也已由后续修订替代。首轮软件回归、真实 Windows 150% 缩放和中文输入法候选操作、首次使用者体验等项目分别查阅原验收状态。[CR-022 软件回归](../records/CR-022.md#软件回归) · [历史发布验证 P25](../records/P25.md) · [0.1.36 部署](../records/P26.27.md)

适用产品为现有 Windows 桌面终端。视觉采用 macOS 风格，键盘、剪贴板、输入法和系统文件选择器遵循 Windows 使用习惯。主要使用者长时间打开应用，通常同时维护 3～6 个会话，在 SSH 上工作、用串口观察设备，并保存现场输出。

## 1. 目标和取舍

| 用户优先级 | 交付结果 | 可观察的成功条件 |
|---|---|---|
| 1 常用 SSH 直达 | 从连接库直接进入终端 | 双击已保存配置后，仅在需要时核对主机身份或补充认证。连接成功即可输入 |
| 2 统一的 Mac 视觉 | 主窗口、侧栏、标签、表单、弹窗、菜单使用同一套控件 | 四个核心场景中，同一动作、状态和层级有一致的位置、措辞与样式 |
| 3 找到并保存日志 | 未录制也可保存保留缓冲；录制状态和文件位置随时可查 | 用户能区分缓冲、已记录内容和可见屏幕，并知道此次保存属于哪个窗格 |
| 4 长时间阅读 | 浅灰界面配深色终端，工具区紧凑稳定 | 日常工作时仅一行常驻工具和标签。提示与录制状态变化不挤压终端 |

用户对空间占用、视觉疲劳、日志状态不清的关注依次对应问卷 4D、4H、4F。遇到窄窗口时优先保留活动标签、日志状态和输入区域；其余标签可横向滚动或从溢出菜单选择，低频工具收入「更多」。

## 2. 四个界面场景

### S1 连接前的主窗口

- **首次启动**显示浅灰连接库和中央「新建 SSH」「新建串口」。两项同等可见；尚无会话时，中央工作区承担新建入口。进入会话后由标签旁的「＋」提供同样两项选择。
- **连接库**按现有目录呈现已保存配置。单击选中，双击连接，右键管理点中的项。选中和展开目录本身只改变导航状态。连续双击一次连接意图只发起一次请求。
- **侧栏**支持收起、展开和拖动分隔线调整宽度。记住用户最后一次手动展开或收起的状态，包括重启后的首次显示。收起后保留可用键盘访问的展开按钮。
- **恢复工作**沿用已保存的工作区及布局引用。用户可找回标签顺序、分屏方向与活动项，并显式连接目标。临时会话、退出应用和关闭标签沿用各自既有语义。

### S2 连接弹窗

| 表单 | 默认可见 | 按需出现 | 成功结果 |
|---|---|---|---|
| SSH | 服务器地址、用户名、认证方式、对应密码或私钥字段、「连接」 | 高级设置中的端口与编码；必要的主机指纹确认、私钥口令、凭据补录；可选保存配置 | 新标签显示实际服务器地址，弹窗关闭，键盘焦点进入对应终端 |
| 串口 | 端口或设备、波特率、「连接」 | 数据位、停止位、校验、流控等高级参数；现行流程要求的设备身份或控制线提示在确认前可见 | 新标签显示真实端口名，使用选定设备和参数，进入对应终端 |

新建 SSH 时初始焦点在地址栏。Tab 按视觉顺序移动，普通表单按 Enter 提交，中文输入法候选确认不触发连接。提交后主按钮原位显示「正在连接…」，阻止重复提交。取消和 Esc 遵循当前阶段已有的取消语义。主动取消后回到发起入口。

必填项或端口不合法时，在字段旁标明修正方法。连接或配置读取失败时，弹窗内给一句可确认的原因和一个下一步，例如「认证被拒绝，请检查用户名或凭据」，技术详情可展开。保留地址、用户名等可复用输入；凭据沿既有安全流程处理。结果未知时提供原操作结果查询。错误持续显示，直到用户处理或关闭。

### S3 连接后的终端

- **一行操作区**从左到右容纳侧栏开关、会话标签、新建、日志和更多。标签直接切换会话，显示 SSH 地址或 COM 口；同名会话分别保留，可从提示或详情区分。常用配置、外观、布局及低频工具从「更多」到达。
- **终端和分屏**占据剩余空间。使用可辨识的焦点边线标记活动窗格，鼠标点入、键盘切换和恢复布局后，焦点、输入目标与顶部日志目标保持一致。切换会话保留各自缓冲与录制状态。
- **键盘**采用 Windows 习惯，在菜单提示可用快捷键。终端有焦点时优先保留 Ctrl+C 的中断语义。打开菜单、表单或系统选择器后按各自焦点范围处理输入。
- **右键**以点击的窗格为准。有选区时复制该窗格选区并短暂提示；无选区时打开其菜单。复制失败要给出反馈。即使已有选区，顶部日志按钮仍可用。右键行为的本次变动应同步更新操作指南及剪贴板回归。

### S4 日志菜单、录制和保存

顶部入口面向当前活动窗格，右键入口面向实际点中的窗格。菜单首行标明目标，例如「COM7 · 右窗格」。菜单打开时固定目标、会话代次及相应文本快照；若切换、重连或关闭使目标失效，关闭菜单或提示重新打开。迟到的保存反馈只属于原操作。

| 操作与层级 | 数据来源、可用条件 | 用户看到的结果 |
|---|---|---|
| 第一保存项「保存终端缓冲内容…」 | 当前窗格仍可回看的显示文本，包含历史滚动区与当前屏幕。存在可用快照即可保存，可在首次起录之前使用 | 直接进入系统另存流程；已经滚出保留范围的行不计入 |
| 常用项「开始记录」或「停止记录」 | SSH 与串口均默认手动起录；按目标会话的真实状态启用动作。开始、停止处理中显示进度 | 起录成功后对应标签有标记，活动窗格按钮显示「● 记录中」。停止并完成同步后解除标记 |
| 常用项「打开日志目录」 | 现有受管理日志目录 | 在系统文件管理器中定位文件；录制采用固定目录及既有命名规则，含目标名称和起录时间 |
| 其他保存范围「另存全部已记录日志…」 | 当前会话已有可读记录的完整已刷新范围，按冻结水位导出；有缺口或失败须提示 | 另存时可继续录制，文件反映本次冻结范围 |
| 其他保存范围「只保存当前可见屏幕…」 | 操作当时实际滚动位置的可见文本 | 上滚后导出当时看到的内容，保留可见空行 |
| 文件操作「打开当前日志文件」 | 当前轮次已有可读文件 | 直接打开该文件；当前文件未就绪时显示不可用 |

保存确认只做一次，遇同名文件走既有覆盖确认和保全流程。成功后短暂显示文件名并提供「打开所在目录」，取消返回工作区。状态查询失败显示「状态未知」，禁用依赖该状态的起停动作；可信缓冲快照的可用性独立判断。进行中、失败及交付结果未知，均不得显示为「已保存」。恢复只查询原编号。

## 3. 统一视觉和反馈

以下尺寸是首稿设计值，以实际窗口和 Windows 显示缩放验证。初始外观采用浅灰侧栏与工具区、深色终端。已有用户主动保存的主题、终端字体和配色优先。

| 元素 | 设计规则 |
|---|---|
| 分区与空间 | 用留白、细分隔线和相邻中性色表示层级。终端随窗口伸缩。阴影集中于浮动菜单与弹窗 |
| 字体 | 界面使用系统无衬线字体和中文回退；正文建议 14 px、辅助文字 12 px、弹窗标题约 18 px。终端使用独立等宽字体，核对中文双宽、英文、路径、光标及选区对齐 |
| 按钮与输入框 | 以 32 px 高度、约 8 px 圆角、4/8 px 间距为起点。每个表单仅一个强调色主动作；常用熟悉动作可单用图标，提供可访问名称、悬停说明和键盘焦点提示 |
| 标签与菜单 | 激活标签有稳定的形状或底色；录制使用标记和可访问状态文字。具有不同数据范围的保存项用完整动词和对象命名。菜单支持方向键、Enter 和 Esc |
| 弹窗与提示 | 标题、字段、错误区、次按钮与主按钮位置统一。成功复制或保存使用短暂非模态提示；持续录制用持久状态，待处理错误留在操作处。提示不抢输入焦点，不引起终端高度跳动 |
| 设置及其他面板 | 设置、确认、管理弹窗复用相同的按钮、字段、标题和错误样式；保留高级能力原入口及必要确认。窗口框架和系统保存框沿用宿主平台行为 |

## 5. 验收用例

各项初始状态均为待验证。使用自建配置、合成 SSH 和内存串口，可为两个会话注入不同标识文本以核实输入和导出目标。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| T01 | 新配置启动；展开、收起侧栏后分别重启 | 首次有两个连接入口；后续恢复手动选择；收起后可用键盘展开 |
| T02 | 单击、双击已保存 SSH；对同一项快速重复双击 | 单击只选中，同次意图只创建一个会话；认证完成即可输入 |
| T03 | 临时 SSH 分别输入错误字段、错误凭据及有效凭据 | 错误位置明确，可就地修改；成功进入正确标签，失败不冒充连接成功 |
| T04 | 打开串口，选择端口与波特率，展开高级参数再连接 | 标签为实际端口；使用指定配置；SSH 和串口初始均未录制 |
| T05 | 打开 3～6 个会话，左右和上下分屏，保存并重新打开布局 | 所有标签可达；手动连接对应目标后可恢复布局；焦点边线与实际输入相符 |
| T06 | 两窗格放不同文本，分别在有选区和无选区时右击，测试 Ctrl+C | 复制内容来自点击窗格，无选区出现其菜单；右键无意外粘贴，终端中断可用 |
| T07 | 未起录时产生多屏输出，上滚并分别保存缓冲和可见屏幕 | 缓冲文件含仍保留的屏幕外标识；屏幕文件仅含该视口；两者均可从系统保存框取消 |
| T08 | 仅录串口，切至 SSH，再从串口窗格右键打开菜单 | 串口标签持续标记，SSH 无标记；顶部随活动窗格变化；右键菜单及后续操作指向串口 |
| T09 | 录制多轮，活跃时另存已记录内容，再停止并打开目录 | 导出范围与冻结时已刷新内容一致；录制继续；停止同步后可从固定目录找到正确文件 |
| T10 | 取消另存、确认覆盖、拒绝覆盖，模拟丢应答或切换会话 | 取消或拒绝时原文件完整；确认后核对目标字节；未知仅查原编号；迟到回执不改投其他会话 |
| T11 | 普通及窄窗口、100% 和 150% 缩放下检查四场景，使用中文输入和键盘导航 | 关键控件可达，文本和焦点可辨，中文输入正确；切换状态没有工具栏换行或终端高度跳动 |
| T12 | 请首次使用者完成新建连接、切换目标、在未录制时保存异常输出 | 无口头提示可找到入口、保存正确对象并指出文件位置。记录实际卡住的步骤，作为体验验收依据 |

后续验证按改动选择已有 desktop 专项，包括 navigation、appearance、quick-ssh、ssh-dialog、quick-serial、split、workspace-split、clipboard、log-files、log-menu。窗口和布局截图证明视觉表现，输入落点和保存范围用实际目标及文件内容核对。

## 6. 需求来源与实施假设

问卷原答按原顺序保留。多选超过建议数量时保留全部选项，第 24 题以填写顺序作为优先级。

| 题号 | 答案 |
|---|---|
| 1–6 | 1 ACEDF · 2 D · 3 C · 4 DHF · 5 E · 6 C |
| 7–12 | 7 A · 8 A · 9 A · 10 B · 11 B · 12 A |
| 13–18 | 13 E · 14 B · 15 AB · 16 SSH A / 串口 A · 17 CF · 18 A |
| 19–24 | 19 E · 20 B · 21 CEFG · 22 C · 23 B · 24 AFDE |

方案细化了三个执行取舍：未录制时保存异常输出采用终端保留缓冲，因此将其列为第一保存项；「记住布局」沿用受管理工作区及显式连接行为；首次采用浅灰界面和深色终端时尊重已有外观偏好。字号、圆角、窄窗口收纳方式属于可依据实际可读性调整的设计值。本文记录需求与验收方法，产品交付状态以实施后的构建和实测记录为准。
