# 桌面终端性能优化执行文档

**交付状态**　方案已编制。实施起点为 Windows x64 0.1.36、提交 `74445ed` 的仓库状态。若启动时版本已变，先记录新提交、构建标识和相关代码差异，再测当前版本。下面的数值目标是建议的决策口径，当前版本的性能实测栏仍为空。

## 一、按用户动作确定优先级

第一轮回答两个问题：打开一个空闲的独立窗口会多做多少工作？在 SSH 窗口点下快捷指令后，时间花在切换标签、启动本地进程还是等待设备？前者决定是否合并窗口快照，后者决定优化哪里才能让日常调试变快。

| 顺序 | 已查明的行为或历史证据 | 需要当前测量回答的问题 |
|---|---|---|
| 1　窗口快照 | 各窗口在上次请求结束约 100 ms 后再次读取。前端已有列表相等检查。原生端持桌面客户端锁等待状态、会话列表，再按窗口过滤。终端读页也使用此锁。[前端](../../apps/desktop/src/main.tsx) · [原生端](../../apps/desktop/src-tauri/src/main.rs) | 第二个窗口增加多少底层请求？交互变慢时，锁等待、服务应答各占多少？ |
| 2　快捷指令 | 从 SSH 或串口启动本地 ADB 涉及切到结果标签、进程启动、设备响应和终端绘制。交互式 shell 还需接收键盘输入。[路由专项](../../scripts/Test-Desktop-ShortcutRoutes.mjs) · [结果回显记录](P26.25.md) | 首屏迟是焦点尚未切换、子进程尚未就绪，还是设备命令自身耗时？ |
| 3　远端窗格输出 | SSH、串口控制器按游标取页，单页上限 64 KiB。空闲约 100 ms，交互或读到输出后的短窗约 16 ms。每页检查代次并等待终端写入排空。[窗格控制器](../../apps/desktop/src/terminal-controller.ts) | 空读占比、每页有效字节和绘制积压各是多少？双窗格的按键回显是否变慢？ |
| 4　持续日志 | 旧 E 盘测试曾测得同步耗时 1.34～1.53 秒，超过当时队列约 0.985 秒的吸收窗口；独立同步实验仍有追加停顿。[日志实现](../../crates/terminal-log/src/storage.rs) · [历史边界](P22.md) | 当前报告的慢属于显示、传输还是落盘？只有定位到日志通道才进入该工作包。 |
| 5　标签与主组件 | 主组件同时负责快照、焦点、路由和标签排序；比较器重复线性查找。拖出预览的 100 ms 定时器仅在相应拖动态启用。[主组件](../../apps/desktop/src/main.tsx) | 在实际标签数下，排序是否占用可观的渲染时间？拆分订阅能否降低改动风险？ |

本地 ConPTY 已使用通知唤醒和有界二进制读取。历史 0.1.18 → 0.1.19 对照中，1.8 秒空闲 IPC 中位数由 161 次降至 19 次，而 PowerShell 打开耗时的中位数由 366 ms 降到 339 ms、P95 从 397 ms 升到 549 ms。因此每项优化同时看前台延迟、尾部延迟和后台工作量。历史对照的宿主、样本数及观察开销见[原始记录](P26.6.md)。

## 二、工作包 A：建立可复现的基线

1. 固定同机、同电源模式、相同 WebView、终端尺寸、配置及发布构建方式。记录系统、CPU、磁盘卷、WebView 和 PowerShell 版本、程序哈希、提交、夹具模式与观察开销。基线和候选用相同仪表，分开记录冷启动和已有窗口操作。测量期间避免并行编译。
2. 使用独立测试数据根和自建窗口。SSH 用回环夹具，串口用内存设备，ADB 用输出固定序号和退出码的模拟程序。保留用户现有 PowerShell 配置；若既有性能脚本因检测到配置文件而拒绝运行，换隔离测试账户，记下差异。
3. 先运行已有本地基准。以下 PowerShell 示例中，两个变量由执行者填入已核验的发布版 exe 和现有证据目录。报告文件按版本及轮次另取名。脚本每次支持 1–10 次启动，已有报告覆盖本地终端，SSH 和 ADB 分段时间需补采。[性能脚本](../../scripts/Measure-Desktop-Performance.mjs)

   ```powershell
   $desktopExe = Read-Host '输入待测发布版 exe 的完整路径'
   $evidenceDir = Read-Host '输入本轮独立证据目录的完整路径'
   node scripts/Measure-Desktop-Performance.mjs $desktopExe (Join-Path $evidenceDir 'baseline-local-01.json') 5
   ```

4. 为缺失指标加最小测试仪表。按窗口、请求类型、窗格、原请求编号关联事件。前端用同一单调时钟算端到端差值；Rust 分别计锁等待、持锁及服务应答耗时。跨进程只关联编号，避免直接相减未对齐的时钟。只保留计数、字节数与时间，采集开关可关，逐输出事件的详细记录限于合成测试。

| 场景 | 操作与起止点 | 同时采集 |
|---|---|---|
| 空闲窗口 | 打开普通本地 PowerShell，稳定后采 30 秒；增加一个空闲独立窗口再采 30 秒 | 每窗口快照次数、底层状态及列表请求数、读页空页率、锁等待、Desktop／服务／WebView 进程 CPU 时间增量。WebView TaskDuration 单列 |
| SSH 回显 | 同一回环端点，单窗格及双窗格各输入带序号的字符；从键盘事件到匹配回显写入完成 | 前台回显 P50/P95、读页大小、队列等待、渲染耗时；标明合成输入或实体键盘 |
| 快捷指令 | 在 SSH 和串口分别点击同一条本地快捷指令，测单条及两行模拟 `adb root`、`adb shell` | 点击→结果标签激活→进程启动→首段输出显示→shell 接收并回显探针。分别记总时长及各段；固定模拟设备等待，另测一次普通 PowerShell 打开作为参照 |
| 持续输出 | 前后台合成源发送相同数量的编号行，在输出中切换标签、分屏并关闭一个窗格 | 首尾序号、缺口、重复、输出字节、末段刷新、旧代次迟到数据，比较当前窗格输入延迟 |
| 标签交互 | 用相同内容的 4 个和 20 个混合标签，执行切换、拖动、普通本地标签双击复制 | 操作到焦点就绪、渲染次数与耗时、最终顺序、复制次数及关闭后的实际焦点 |

先做一轮冒烟核对场景、计数和结束条件，再取两批独立基线确认噪声。频繁交互每批建议至少 30 次，报告样本数、中位数、最近秩 P95 和最大值；少量冷启动逐次列值。给超时、失败和缺口单列计数。若两批基线的差异接近预期收益，先查波动来源。A 包交付场景结果表和耗时最大的可优化环节，再选一个实现包。

## 三、按证据选择实现包

| 包 | 进入条件 | 实施方法 | 验收与回退 |
|---|---|---|---|
| B　窗口快照 | 多窗口产生重复请求，或测到快照占锁期间前台读页明显排队 | 先按同一服务实例合并**同时在途**的只读快照。共享原始读取后逐窗口执行现有过滤；窗口归属在返回时复核。服务重启、失败、窗口移交及迟到应答分别处理。若热点确在服务往返，再以 ADR 单独评估只读连接 | 比较 1、2 窗口底层调用和前台 P95。覆盖服务失联、窗口关闭、标签移交和服务换代，确认旧窗不见已转交会话。收益不足则恢复原逐窗口读取 |
| C　快捷指令 | 分段数据显示软件自身占了主要可改善时长 | 标签激活慢时先查同步配置读取与重复渲染；启动慢时查启动次数、路径解析和首次初始化；输出慢时沿读页与绘制跟踪。一次只改已证明的环节。分别采集模拟设备等待与主机开销 | 两行命令保序、同一设备、末行进入可输入 shell；从 SSH／串口启动后焦点切至正确结果，原会话仍可返回；脚本自动关闭按原选项生效。检测重复执行或焦点错投立即回退 |
| D　远端输出 | 空闲空读多或轮询等待主导回显；已排除 B 对数据的干扰 | 参考本地实现，先在一种协议试验有界通知。按服务、连接及代次唤醒，游标仍是取数依据。订阅后补读防漏唤醒；持续有数据按预算分页，每批给 UI 调度机会；断开唤醒并读完尾段。保留低频兜底，第二协议独立复验 | 比较空读、首字回显、持续吞吐和内存。覆盖无输出、突发、缓冲覆盖、取消、重连和窗格切换。出现丢尾、重复、串会话或输入积压即恢复原轮询 |
| E　标签与组件 | 多标签时排序或组件更新在跟踪中明显占时；或 B 需隔离生命周期 | 排序前建立 ID→顺序索引；保留分组、同地址独立会话和稳定次序。若因 B 提取快照订阅，仅迁移订阅及清理逻辑，焦点和路由另行验证 | 对比 4／20 标签，验证拖动零复制、双击只复制一次、Alt+数字与关闭焦点。微小且落在噪声内的性能改动可撤回 |
| F　日志专项 | 当前证据能定位到队列、追加或同步，或后续单独安排日志容量工作 | 先按源对齐接收、接受入队、写入、持久化、明确拒绝和源缺口，记录峰值深度、写入及同步时长。保持队列有界。按既有 P22 失败条件选择最小受控实验，再决定是否需要架构变更 | 核对序号、字节、摘要和失败显示；界面回显另行计时。若同步语义弱化或有未报告缺口，撤销候选。历史长稳与特定磁盘失败继续按 P22 跟踪 |

B 至 F 各包独立提交。第一轮建议先完成 A，再从 B、C 中选证据更明确的一项。若时间主要消耗在外部设备应答，记录可改善的主机耗时上限，停止该路径的重构。后续若涉及协议、授权或持久化边界，先记录 ADR、兼容路线和回退方式。

## 四、合入、回退和交接

- **性能判定。** 执行前选定一个主指标和一个用户可感知的保护指标。例如 B 以双窗口底层重复请求数为主，SSH 回显 P95 为保护指标；C 以点击到可输入为主，普通 PowerShell 打开 P95 为保护指标。建议候选与基线交替运行两批，收益方向一致且超过两批基线的自然波动才计入结论。主指标改善但保护指标持续退化时，列出绝对差值与分段解释，暂缓合入。
- **正确性判定。** 受控容量以内，编号输出无丢失、重复和错投；刻意制造缓冲覆盖时能显示缺口。任何未知应答仅按原编号查询。重点回归当前版本的快捷指令执行位置、键盘焦点、原会话存活及脚本关闭选项。UI 的颜色、尺寸、菜单和交互依据[维护规范](../UI_GUIDELINES.md)。
- **验证入口。** 先核对当前构建和脚本前置条件。`npm run desktop:build` 生成调试构建，用于功能回归。双窗格可运行 `npm run test:desktop:split`；快捷动作按影响选用[路由专项](../../scripts/Test-Desktop-ShortcutRoutes.mjs)、[串口快捷指令专项](../../scripts/Test-Desktop-ShortcutUart.mjs)及[本地终端专项](../../scripts/Test-Desktop-LocalTerminal.mjs)。性能对照使用相同发布配置。夹具测试结束恢复并核对普通服务。现有入口未覆盖的新计数和竞态，在相应包补充定向测试。
- **回退。** 每次只引入一个可比较的候选；归档失败数据与源码提交。出现身份、输出完整性或重复执行问题时先停该候选，通过独立 revert 恢复原路径，再复验同一场景。正式交付另按既有发布流程办理。

每包完成后把以下表格填入该包的步骤记录，并在执行台账登记。原始证据使用测试根相对路径或可复建标识。

| 场景／指标及单位 | 基线提交、样本数、P50／P95 | 候选提交、样本数、P50／P95 | 绝对与相对变化 | 失败数／正确性结果 | 证据位置与结论 |
|---|---|---|---|---|---|
| 待 A 包采集 | 待测 | 待测 | 待算 | 待验 | 采用、继续定位、回退或跳过，说明依据 |
