# P26.21 全窗格快捷指令

实施范围、Windows 语法和版本边界见 [CR-044](../changes/CR-044.md)。

验证矩阵包括 SSH2、内存 UART 和本地侧栏，固定代次单次发送；模拟 ADB 的 root 拒绝、重启、同设备绑定、真实本机管道、交互和中断；脚本及本地步骤的成败和回焦；旧条目与 MCP 33 工具管理隔离；0.1.30 的本地双击、拖动、别名和只读预览。所有设备和服务均为自建测试设施。

实际 Windows x64 Release 专项通过回环 SSH 与内存 UART。模拟设备的 root 拒绝使用退出码 0 加拒绝文本，末尾命令未收到。等待原设备超时和 Ctrl+C 后，模拟调用清单均无尾部执行。标准流验证覆盖实际本机 grep 可执行文件、Windows PowerShell Select-String、输入经管道回显及前段退出 7。脚本等待输入时留在结果页，成功回到原连接，失败保留标签。用户切到另一 SSH 后，成功退出只关闭后台结果。远端草稿原文保留。

TypeScript 和 145 项前端用例通过。发布门单独构建内存 UART 服务，将同一 Release 桌面文件复制到测试目录，正式目录仍使用普通服务。验证报告为 `artifacts/SharedTerminal-0.1.31-windows-x64-verification.json`，同版本的 `shortcut-routes-ssh.json` 与 `shortcut-routes-uart.json` 包含独立检查。

Rust 语法专项确认双引号内的管道符仍属于原参数，裸管道才拆分本机进程。首轮完整发布门发现全展开侧栏覆盖下的标签分屏落点失败。共用侧栏成为终端区域的同级浮层后，落点命中需要沿整个窗格内容区判断。修正并以原窄窗总览和分屏专项复验。
