# P26.6 桌面发布版性能优化

依据 [CR-029](../changes/CR-029.md)，比较 0.1.17、0.1.18 和带优化的 0.1.19。0.1.18 是直接实现对照，包含上轮标签拖动和复制功能。

ConPTY 在空缓冲变为有数据或进程实际退出时唤醒。每个任务一个有界等待读取者，等待不持有会话或进程输出锁。浏览器仍按原有节奏处理持续输出，空闲无需持续取空页。响应使用小块 JSON 元数据加原二进制输出，保留溢出提示、退出码、末段、输入任务身份和原编号回读。切换可见性仅调整视口，主题设置变化才重应用外观。

每次主界面刷新用单次桌面调用取服务状态和窗口可见的连接列表。原 Ping、列表请求、窗口过滤和失联处理继续执行。服务的记录、授权、协议及队列容量保持原有行为。

## 同机发布版对照

每版五次独立启动，每次四个本地标签，其中两个空闲 PowerShell。双源测试每源 480 条带编号的固定行，一个在前台、一个在后台，逐标签核对顺序、文字、尾段和进程结束。CPU 工作量以 WebView 的 TaskDuration 表示，它包含界面计数钩子及观察开销，覆盖的是渲染器任务时间。传输量是读取响应体累计值。启动从启动子进程到 WebView 可用且显示正确服务标识，包含测试探测粒度。

直接基线的空闲本地输出请求中位数由 131 降到 3。启动基本持平，轻量打开和键入的中位数略升，PowerShell 的打开和命令回显尾部比直接基线更慢。PowerShell 回显包含该进程的首轮准备，双源运行耗时包含固定发射步进及子进程退出。测试使用同一宿主当前用户下的 Windows PowerShell，启动前核对四类标准配置脚本均不存在。空闲 WebView JavaScript 堆的观测中位数约为 9.67 MB 和 6.67 MB，只有短时样本，可能随回收波动。

## 公共路径对照

配置读取通过 Desktop IPC 发起。SSH 使用回环端，预热一条准确回显后计时并核对原始字节顺序。录制每轮核对同步完成、worker 退出和实际文本尾段。ADB 使用自建程序和单次按钮操作。UART 单独使用同一个显式内存测试服务配三版发布 Desktop，库存必须报送合成身份；测到的是内存 UART 与界面的合成本地路径。

公共路径是短时回归对照。其波动同时包含进程启动、探测和服务调度。正式仪表修正了两个预检问题。双源下一轮等待上轮实际退出后才输入；SSH 在前台且焦点确认后用一条回显预热。失败记录保留为 desktop-performance-0.1.17-harness-failure.json、desktop-performance-common-0.1.18-focus-failure.json 和 desktop-performance-memory-uart-0.1.17-preflight-failure.json。最终汇总及原始证据文件哈希见 artifacts/desktop-performance-0.1.19-comparison.json。

## 交付与边界

139 项前端测试、Windows x64 普通 release 构建、语法和格式检查通过。候选目录复验 0.1.18 配置锁和复查、关闭与释放、官方 MCP 客户端读取边界、本地输入和未知回执、PowerShell、模拟 ADB、本地脚本、默认目录及本地拖动。最终目录另通过合成 SSH 与本地混排、双击复制、认证和独立输入验证。独立内存 UART 的测试服务留在 target 下的专项目录，交付为普通服务。
