# P26.44 R5 会话服务领域分派

接续 [P26.43](P26.43.md) 的管道连接模块，移出 [Runtime 的领域分派和处理方法](../../crates/session-service/src/server/dispatch.rs)。连接模块仍先接纳受审计的原请求，再等待领域分派，随后原序记录处理结果、结算回执并写回原管道。保留 T19 允许项及审计诊断的丢回应答判定。服务运行入口继续持有监听器、容量、领域对象和关闭顺序。

## 验证

- 核对实际搬移的方法体，并按原枚举分支核对 Agent、日志、保护导出、串口、SSH、配置和其他请求。权限判定仍由原领域方法完成，操作身份、请求号和原代次继续走原逻辑。
- Windows IPC 用 `cargo test -p session-service --locked --test windows_ipc -- --test-threads=1 rpc_audit config_observers ssh_shell_logging ssh2_service_shares agent_context_uses` 复用握手超时、审计、共享输出、真实回环 SSH、日志及配置权限的定向用例。复核发现一个入选串口 IPC 测试会枚举宿主端口，已在编译阶段停下并留下日志。串口正常流改用单独构建的内存 UART。另检查两项诊断构建特性的编译路径，正式服务使用默认特性。
- Rust 格式、9 项 Windows IPC 定向测试及 `cargo check -p session-service --locked --features t19-timeline-fixture,audit-diagnostics-fixture --lib` 通过。默认 Windows x64 Release 服务也通过，SHA-256 为 `ee7abdfab17108b2b2e16ed9667e9cc45477551bc38728117fa1ffe9d801ba32`，与 P26.42 桌面和普通桥一起放在 `artifacts/SharedTerminal-0.1.36-refactor-P26.44`。
- Release 候选的保护导出、原请求回执及权限通过真实 Windows 桌面和回环 SSH 验证。串口复制、端口独占和取消通过隔离内存 UART，夹具构建使用单独 Cargo 目标目录和同哈希桌面。其后核对普通服务散列保持，另启普通候选完成窗口权限及拒绝夹具入口复验。

原生候选和回执报告见 `artifacts/P26.44-r5-dispatch`。以 `Step-ID: P26.44` 定位提交并新增 revert 可单独撤回本步，保留 [P26.43](P26.43.md) 的连接处理模块。
