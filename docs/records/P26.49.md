# P26.49 R9 Windows 候选整体验收

[P26.37](P26.37.md) 和 [P26.48](P26.48.md) 冻结的断言故障分别来自工具栏中导航按钮的位置和窗格新增菜单首项。新版断言核对导航按钮独立落在标题栏左侧、按钮可见且与工具栏不重叠、工具和标签的位置，连接菜单使用当前连接操作的可访问名称。原有实体鼠标模式保留文件与窗口归属检查。

[SessionCopy](../../scripts/Test-Desktop-SessionCopy.mjs) 的 `--combined` 通过 WebView 输入拖入右侧窗格，走保存和临时配置两种复制入口，核对独立请求、落位和输入。实际原生命令移交原连接到独立窗，在独立窗复验已丢应答的复制走原编号查询，并用系统文件选择器另存原连接录制。选择文件后以原导出散列、字节数和录制标记验证结果，最后读主窗关停回执。

[PaneGroups](../../scripts/Test-Desktop-PaneGroups.mjs) 的 `--webview-drags` 补齐分隔条、原生移交和回收。保留原模式的跨窗口实体拖放路径。[MCP 配对专项](../../scripts/Test-Desktop-Mcp.mjs) 使用 Release 组合时以另一条实际回环 SSH 会话验证越权读取拒绝，并先验证普通服务拒绝夹具入口。

## 已核对证据

- 最终 x64 Release 桌面运行 `--combined` 通过。背景保存凭据复制、临时认证、右侧窗格落位、精确输入、独立窗复用原编号和关闭回主窗通过。系统实际保存 864 字节，选定路径与保存回执一致，SHA-256 `41cd97a8a562cbe81d031f059dba55a4d9ea682cc7a87b71b4d83f21e07287d7` 与准备回执一致。主窗服务关闭回执为 `ACKNOWLEDGED`。同一桌面在 `--webview-drags` 下通过八项落位、嵌套分隔条、原渲染器身份、分组、输入、录制和移回。
- 组合夹具首轮在应用数据根保存，被产品以 `TARGET` 拒绝。另起保存根时使用了 JSONL 扩展名，文本选择器改用了默认日志扩展名。最终使用独立保存根和原生 `.log` 扩展名，核对了最终文件。一次并行编译中的 WebView 启动等待超时，使用最终候选复跑通过。
- 最终候选通过 `Test-Desktop-PaneGroups.mjs EXE` 的 Win32 鼠标自动化。八个边缘落位、分隔条、移交及拖回均通过。 `Test-Desktop-SessionCopy.mjs EXE` 的完整原生窗口专项也通过，包括两个复制入口、主窗和独立窗标题拖动、最大化与还原、独立窗的复制和关闭。`Test-Desktop-ShortcutRoutes.mjs EXE --verify-reads` 首次通过，使用模拟 ADB 和回环 SSH，覆盖两段命令、错误和中断、后台快捷任务、精确远端输入归属以及空读边界。
- 最终普通候选用 `Test-Desktop-Mcp.mjs --desktop-exe EXE` 核对实际 v13 目录、固定桥 PID、精确输入及原回执、另一条实际回环连接的拒绝、接管、撤销和服务丢失后结果不明。另把最终桌面复制到内存 UART 专用目录，验证独占、复制和取消。该目录使用 P26.45 隔离的夹具服务。随后比对普通候选三份二进制散列，复验普通服务拒绝夹具入口、窗口归属和迟到回执。
- 最终候选的受保护导出也改用第二条实际回环连接。首轮普通候选因测试缺少第二目标而在错目标查询处返回 `INVALID_ARGUMENT`。补齐合法的第二目标后，按原编号查询、错目标拒绝、真实选择器及保存通过。同一候选经官方 stdio 客户端复验 v13 工具目录、0.1.35 旧桥、旧回执和两个版本的快捷指令授权。
- 前端类型检查、158 项测试、普通 Release 构建和 Rust 格式通过。普通前端产物中没有 R3 诊断标记。候选构建有既有 Vite 大块提醒。
- 三个受影响 crate 的 `cargo clippy -p CRATE --all-targets --locked -- -D warnings` 均被已有服务诊断阻断。以 `git archive 8ad5cc2` 取原始源码，在独立目录、相同工具链和已生成前端资源下分别重跑，三个同样退出 101。核心诊断为原分派的可折叠条件及 SSH1 的固定大小分块写法，服务测试另有配置测试模块位置问题。原分派诊断从 `server.rs` 对应到现行 `server/dispatch.rs` 的原语句。三 crate 去掉 `-D warnings` 可完成静态扫描，按诊断及原语句去重，两端均为 10 项，无新增或漏项。
- 服务单元 63 项、桌面原生单元 26 项、桥单元 5 项通过。将 R7 桥并发测试放到模块尾部后重建最终桥并重跑单元。选定 Windows IPC 用例首轮在并行编译期间有一次服务握手超时，复跑 11 项全部通过，包含输入、重复和背压、人工接管、重连、SSH1 默认拒绝、握手和回执审计。全量 Windows IPC 会枚举宿主串口，实际运行使用定向用例和内存 UART 替代。
