# P26.43 R5 命名管道握手与连接审计

按[全仓重构方案](../REFACTOR_PLAN.md)将单连接处理移动到[连接模块](../../crates/session-service/src/server/connection.rs)。监听器、32 个接纳许可、任务回收与关闭仍由[服务运行入口](../../crates/session-service/src/server.rs)持有。逐字核对函数体。Hello 和请求读取的超时、当次身份、原线编号、审计 guard、记录 handler 结果再写回应答的顺序沿用基线。领域分派另步拆分。

## 验证

- 定向跑 `cargo test -p session-service --locked --test windows_ipc handshake -- --test-threads=1` 和同入口的 `rpc_audit` 组。断言使用本次自建 Windows 管道，覆盖握手、无权请求、坏帧、早关、容量及原审计事实。
- `cargo test -p session-service --locked --lib request_audit` 覆盖真实管道应答写失败与异步任务中止。按原 handler 结果和交付阶段分别判断，验证丢失回应不会被记成已写给对端。
- 握手筛选 2 项、原管道审计筛选 4 项通过，其中有一项重叠。另新增并通过 1 项实际静默 Hello 及提前关闭用例，先确认提前关闭的原管道已接纳，再关对端。两条管道分别留下 `HelloRead/Closed` 与 `HelloRead/Timeout`，均无 `ReplyWritten`。写应答审计 3 项通过，断开对端后的实际写入失败留有 `ReturnedOk` 与 `ReplyWrite` 失败终态。
- 错误类型的初次导入来自协议库私有引用，已改为从原会话核心定义导入。Rust 格式与 Windows x64 Release 服务构建通过。候选目录 `artifacts/SharedTerminal-0.1.36-refactor-P26.43`，新服务 SHA-256 为 `83c45fcf537967421cbec0495263bce30c3d11d9bcb8ddf2fd605a654e06de8e`，桌面及桥沿用 P26.42。
