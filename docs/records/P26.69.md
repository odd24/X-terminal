# P26.69 实现独立删除确认和修订约束

实施 [CR-052](../changes/CR-052.md)。左侧会话树右键打开独立的「删除会话配置」确认，默认聚焦取消。取消回到原条目，删除或只读核对结束后按原条目是否存在恢复焦点。配置窗口保留内部确认，取消或结束后继续留在管理界面。

两处共用 [删除流程](../../apps/desktop/src/profile-deletion.tsx)，冻结配置编号和当前修订。按 [ADR-102](../decisions/ADR-102.md) 在普通服务中串行核对后复用原删除逻辑。运行中禁止重复派发，应答不明只读查询同编号并区分已不存在和核对时仍在。

通过前端类型检查与 158 项测试、Rust 格式检查、Windows x64 Release 三程序构建。在同一实窗候选完成两条删除路径、Esc 和焦点、单次派发、真实修订冲突、受控迟到和应答丢失两种核对结果。删除配置后原合成 SSH 连接代次仍在线，已开始的录制及受保护凭据编号保留。独立配置管理专项验证普通成功删除、配置 CRUD、重启持久化和坏库处理。

首轮树测试假定导航默认收起，改为检查实际可见状态。后续实窗发现等待期间 Esc 可由 WebView 收起模态，删除确认改为先处理键盘关闭意图，再按状态决定。旧配置测试的异常数据库复验曾回退到默认调试路径，现统一使用指定候选。修正后复验通过。

构建和实窗日志见 `artifacts/P26.69-profile-delete`。实窗使用自建数据根和回环 SSH。通过提交正文 `Step-ID: P26.69` 关联。
