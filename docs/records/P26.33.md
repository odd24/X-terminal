# P26.33 桌面前端局部重构执行方案

**决策**　首轮只提取会话快照订阅。完成条件是主窗口可以直接读出“收到快照后如何更新当前窗口”，订阅模块可以独立证明“何时发请求、何时停止、哪些变化要发布”。第二轮在下一次扩展快捷指令执行行为时启动。两个工作包独立验收、独立回退。

**基线**　审阅提交为 `3e7b03d`。桌面、会话服务、传输模块和 MCP 桥已有明确边界。上轮实测表明，减少桌面与服务之间的重复读取就能获得收益。此次验收目标是降低改动耦合并守住这些收益。正式安装版 0.1.36 与同版本号的 P26.32 性能候选有不同二进制；对照应使用 P26.32 候选或从对应提交重建的产物。[架构决策](../decisions/ADR-100.md) · [实测记录](P26.32.md) · [测量摘要与二进制哈希](../evidence/P26.32-summary.json)

## 首轮：会话快照订阅

### 1. 从现有执行顺序划分职责

| 时点 | 订阅模块负责 | 主窗口负责 |
|---|---|---|
| 开始读取 | 每个已挂载窗口立即发起一次请求，在发起时取得当前路由版本 `epoch` | 提供读取当前路由版本的方法 |
| 应答成功 | 返回本次服务身份、原顺序的会话与游标、发起请求时的路由版本。区分服务变化、可见列表变化和仅游标推进 | 先保留该服务的撰写历史，更新服务引用和连接视图，再通知仍有有效归属且未暂停的窗格 |
| 路由协调 | 将请求时的版本交回调用方 | 按原顺序检查触发器，执行窗格 `retain`；根据版本变化选择 `routeChanged` 或 `syncRoute`。单窗格无请求目标时沿用选择首个可见会话的规则 |
| 下一轮 | 本轮处理成功结束后等待约 100 ms，再发一次 | 用户切换标签、输入、拖动和关闭走各自的现有入口 |
| 失败或卸载 | 请求或应用快照失败时结束本轮订阅；卸载时取消计时器，忽略旧订阅已发出的应答 | 失联时沿用停用触发器、清理历史归属、递增路由版本、使旧路由失效及显示错误的顺序。正常卸载静默结束 |

建议新增一个普通 TypeScript 模块，例如 `session-snapshot.ts`。入口接收读取函数、获取路由版本的方法、成功及失败回调，返回清理函数；主窗口原有的 `useEffect` 只负责启动和清理。可以把现有列表、服务比较提为同模块的纯函数。具体命名允许按实施时的仓库习惯调整。整个窗口只保留一份会触发 UI 更新的状态；不要在模块和 React 中各维护一套可独立写入的连接列表。

### 2. 先处理两个容易遗漏的边界

- **列表与游标的对应关系。** 原生应答先按窗口过滤，再从同一批记录拆出 `sessions` 和 `next_cursors`。当前 `openSessionWindow` 成功后会主动过滤本窗口的 `liveConnections`，而 `paneSelection` 用列表下标读游标。两个数组存在短暂错位的可能。这是源码风险，尚无已观测的串会话故障。推荐将游标查询绑定到同一次原始快照的服务、连接 ID、代次和协议；窗口的本地过滤只决定可见性。也可成对过滤，但必须覆盖所有本地写入点。没有精确匹配时不给游标提示，交给既有读页机制处理。
- **相等列表也可能有进展。** 服务比较沿用 `service_id`、PID、夹具标志、SSH1 能力及退出策略；同一服务启动时捕获的 `previous_close` 不参与每轮变更判断。列表比较保留顺序及 ID、代次、协议、状态。只推进游标时仍让窗格检查输出，同时复用相等列表的 React 引用。列表相等不能成为跳过整轮路由或触发器校验的条件。

### 3. 实施顺序

1. **固定对照。** 记录开始提交和基线 exe 哈希，检查主窗口、独立窗口、分屏各由谁订阅。盘点所有写 `liveConnections.current`、读取游标以及变更路由版本的入口，特别标出移交窗口与关闭回执。
2. **锁定行为。** 为现有桌面专项难以稳定制造的竞态补小测试。用可控制的 Promise 和计时器证明同一订阅最多一个请求在途、慢应答期间不追加请求、卸载后旧成功和旧失败均无回调、重新挂载后旧应答不能更新新窗口。用两个会话及不同游标覆盖本地移除第一项、同 ID 换代、仅游标变化三例。
3. **接入真实入口。** 抽取订阅和比较，替换原轮询 effect，删除原定时器。让成功回调读取最新窗格与控制器引用；保持请求前捕获版本、应答后比较版本的时机。对照上表逐项核对通知顺序。一次提交包含模块、接入和对应测试，便于整体回退。
4. **受影响路径复验。** 用下表跑真实桌面。若隔离用例暴露了已存在的游标错位，记录能复现的最小序列和修复前后结果；如果发现另一项既有缺陷，单独登记，避免与订阅迁移混在一起。

### 4. 首轮验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 单窗、双窗空闲各 30 秒 | 每个窗口只有一个刷新循环。相等列表不反复发布；空闲 SSH 仍主要取兜底页 |
| 快照在途时切换标签、移交或收起窗格 | 旧应答不能覆盖新选择。主窗与独立窗只呈现各自会话，移除一项后其余窗格仍使用自己的游标 |
| 真正的新输出、迟到页、快照暂缓 | 新输出能唤醒正确窗格。压住快照后兜底页仍可读；持有旧正文页再切换，释放后只在原目标可见 |
| 重连、断开、服务终止 | 新代次重新绑定；断开尾段可读；终止本次自建服务后显示现有失联反馈，旧输入不会重放 |
| 本地 PowerShell、SSH 和混合标签 | 输入焦点跟随当前窗格；普通本地标签双击只复制一次，拖动只移动；Alt 加数字切到原有目标 |

## 后续轮：快捷指令执行协调

**启动条件**　下一项需求涉及新增执行目标、改变结果标签复用、取消／重试或成功关闭策略时启动。只有菜单文案、图标、排序等展示调整时，可以继续直接维护对应 UI。启动前重新核对当时版本的指令类型和原生契约。

| 指令路径 | 需保留的行为 |
|---|---|
| 发给当前 SSH／串口 | 点击时冻结服务、窗格、连接 ID、代次、协议和路由版本。异步读取文本后复核来源及可写状态，按配置追加回车，交给原控制器发送一次 |
| 单条 ADB／本地命令组 | 在 Windows 执行。沿用原有复用条件，含空闲、无草稿及按钮类型等限制；否则新建并聚焦结果标签。命令组按保存的顺序执行，末行交互 Shell 可继续输入 |
| 本地脚本 | 继续使用按钮 ID 与修订定位脚本；执行成功且启用自动关闭时，仅关闭本次结果标签。失败结果可查看；用户已切走时保留当前焦点 |
| 多设备、取消、未知回执 | 单设备沿用直接执行，多设备沿用原选择流程。取消设备选择释放相应在途状态。原生启动回执不明时按原标签和请求号核对，禁止自动重复发起 |

**具体拆法。** 先为“用户在 A 会话点按钮、结果在 B 标签运行、随后用户切到 C”建立定向用例；然后把来源冻结、复用判断、在途请求及原结果匹配提到一个窗口级协调模块。由 `executeShortcut` 接入，沿用 `openLocal`、`closeLocal`、`prepareShortcut`、`launchShortcut` 和控制器现有调用。保留终端组件对输入草稿、IME、ConPTY 输出和设备选择框的所有权。启动回执到达可释放“正在启动”状态；任务是否真正结束、是否可以自动关闭，仍以原任务的终态回执判断。按“本机执行”和“发送到当前会话”分别验证后，清除重复状态再提交。

**额外验收。** 在 SSH 和内存串口各运行单条与两行模拟 ADB；检查快速连点、设备选择后取消、Ctrl+C、脚本退出 0／非零、后台完成、来源已关闭、同标识换代和诊断迟到。确认命令只执行预期次数、已有草稿完整、回执绑定原结果标签，界面名称与快捷键按[维护规范](../UI_GUIDELINES.md)核对。

## 构建、比较与交接

从仓库根运行，先按 [README 的 Windows x64 发布构建步骤](../../README.md)准备依赖、工具链、回环 SSH 夹具和配套 exe。保存基线副本后再构建候选，保持构建配置一致。下面给出首轮候选的最小命令组；报告文件名按本次执行编号另取，保留基线数据。

```powershell
. ./scripts/Enter-Toolchain.ps1
npm test
npm run build
# 完成 README 的 Release 构建后
$candidateExe = Join-Path $PWD 'target/windows-x64-portable/x86_64-pc-windows-msvc/release/shared-terminal-desktop.exe'
node scripts/Test-Desktop-ShortcutRoutes.mjs $candidateExe --verify-reads --measure artifacts/refactor-snapshot-trial-01.json
node scripts/Measure-Desktop-Performance.mjs $candidateExe artifacts/refactor-tabs-trial-01.json 5 --tabs
node scripts/Test-Desktop-SessionCopy.mjs $candidateExe --tab-interactions
```

各命令以退出码和报告断言判定。将新增订阅测试纳入仓库实际测试入口。第二轮另用配有内存 UART 服务的独立目录执行 `Test-Desktop-ShortcutRoutes.mjs <该目录桌面exe> --uart`；普通服务和用户设备保持隔离。脚本覆盖不到的快捷键、移交游标及服务失联等用例，补定向验证并标明证据来源。[桌面测试入口](../../scripts/Test-Desktop-ShortcutRoutes.mjs) · [标签性能入口](../../scripts/Measure-Desktop-Performance.mjs)

**性能判定。** 首轮主要看两窗 30 秒的快照和空读数，同时看单／双 SSH 回显 P95。P26.32 的两批参考为快照合计 541／543 次，空闲 SSH 读页 29／28 次；每批 30 次的双窗格回显 P95 为 46／41 ms。按相同设备、构建、采样器和场景交替测当次基线与候选各两批，记录样本数、中位数、P95、失败数和完整性。历史数字用于识别数量级；若候选连续落在当次基线波动之外，先查定时器数量、重复读页、全局重绘及焦点等待。正确性失败即暂停合入。

**回退与完成条件。** 每包有独立 Step-ID、提交、实际执行命令、候选哈希和对照报告。发现串会话、重复执行、自动关闭错误标签、失联后继续派发或可重复的性能退化时，保留失败证据，使用新增 revert 提交撤回该包，再在恢复后的构建上复跑失败场景。首轮通过验收即可单独交付。第二轮由后续需求触发。本步骤交付物为实施方案，以上重构和验收均待后续执行。
