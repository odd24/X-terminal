# P26.24 本地命令组末步 ADB Shell

用户报告 `adb root` 后进入 `adb shell` 时停在「[2/2] 开始」。在 0.1.33 用相同两行复现。模拟器同时检测 stdin 和 stdout 的终端属性。单条快捷指令可见终端与提示符，组命令末步看见匿名管道而没有提示符。前一步已完成，结果标签的输入焦点正常。

本地命令组只将末步的独立裸 `adb shell` 交给已有 Windows ConPTY。两条执行路径共用固定设备参数构造。交互步在本次标签收发终端字节，应用当前尺寸，退出回报组结果，原请求重交不再次启动。Ctrl+C 或关闭结果标签停止归属该组的前台客户端。带参数的 shell 及管道步骤继续使用标准流。组命令支持固定设备上的 `get-state`。明确确认设备原本就是 root 时省略重连等待，确认实际重启时继续等待原设备，并保留 12 秒子步骤上限、失败和中断停止后续步骤。

0.1.34 Release 软件专项覆盖单条与同组双行、真正的终端属性、等待行为、原启动请求重复提交、输入回显、`pwd`、Windows 控制台缓冲区尺寸 94×31、退出 0 和 7、Ctrl+C、成功按项自关闭回焦及失败保留。回归包含固定设备重启等待、拒绝和超时、标准流带命令、真实本机 grep、Select-String、管道输入及段失败拦截。首轮新版测试已完成新增交互检查，旧管道断言误用了前面测试的同名命令记录。将断言绑定到同一次运行后，完整专项通过。

实际 Android 验收只使用截图同一台已授权在线设备。独立数据根的桌面组命令执行 `adb get-state`、`adb shell`，随后在真实提示符只键入 `pwd` 和 `exit`。观察到键入回显、目录输出及退出码 0，测试桌面和服务正常退出。实际 root、设备权限变更及业务数据读取均未参与。报告只记录布尔结果和程序 SHA-256，不保存设备编号与输出正文。

软件对照、定向回归、实际设备及便携运行报告依次位于 `artifacts/windows-0.1.34-shortcut-routes-adb-shell-baseline.json`、`artifacts/windows-0.1.34-shortcut-routes-ssh.json`、`artifacts/windows-0.1.34-adb-group-device.json` 和 `artifacts/SharedTerminal-0.1.34-windows-x64-verification.json`。
