## Windows 子进程尺寸派发原型（2026-11-18）

`cargo test -p session-service --locked --test ssh1_resize_child` 通过。测试目标自启动一个无网络子进程，沿已有有界帧通过私有 stdin/stdout 传输精确代次、原 UUID 和行列。父进程在写入请求前将子进程加入关闭即回收的 Windows Job。子进程 I/O 将请求交给单槽队列，只有后端所有者线程更新合成尺寸及回调计数。

错代次、501 列、0 行均返回原编号的拒绝，未触发回调。137×41 的有效请求返回原编号及实际合成状态。重复同一请求仍报告一次回调，复用原编号改行数被拒。关闭输入后实际收到 stdout EOF 和子进程 exit 0，父测试进程 exit 0。父子均设有截止，正常路径实际等待并回收子进程。

此证据覆盖本机进程、帧和单线程派发。合成回调未经过 SSH1 wire，凭据、主机信任和真实 PTY 仍待独立验证。此次未启动 Plink、旧 banner 探针或 Desktop。

### 合成主机信任与认证响应

同一无网络父子进程定向测试通过，保留原 Resize 断言、Windows Job、EOF 和实际退出回收。子进程所有者线程发出两个合成挑战编号。测试验证主机信任与认证回复绑定各自种类、同一精确连接代次和原编号。交叉使用种类、未知编号、错代次、主机批准前认证及消费后重复均拒绝，拒绝路径不增加回调计数。

真实私有管道的认证响应复用 `Sensitive`。只有通过绑定核对的合成值进入认证回调，回调只返回状态。父进程检查挑战回执不含合成值，并逐字节核对独立应用数据帧。此验证覆盖本机测试协议和合成回调，真实 SSH1 认证与主机密钥信任流程仍待验证。

## PuTTY Seat 异步接口（2026-11-18）

原版 `ssh/login1.c` 的认证提示在 `SPRK_INCOMPLETE` 时暂停，恢复后用同一个 `prompts_t` 重进 `seat_get_userpass_input` 取得结果。主机确认则以回调传回最终状态，SSH1 调用者随即恢复处理队列。主机密钥的临时显示字段在原调用返回后释放。探针的待答状态只持有编号、种类和有效的延续所需引用，主机确认不保留该临时文本或密钥指针。

自有 C 测试通过上游 `seat_get_userpass_input`、`seat_confirm_ssh_host_key`、真实 `queue_toplevel_callback` 和 `run_toplevel_callbacks` 驱动一个单槽 Seat。两种挑战各实测一次接受和一次明确拒绝，错误编号、错误种类、并发占槽及重复响应不触发恢复。认证未答时重进仍为 INCOMPLETE。有效认证值只写入上游 prompt 的结果缓冲区，恢复时检查合成值，输出不含该值。关闭删除已排队延续并清除尚未消费的认证结果，晚到回复和原队列均未触发回调。每个恢复回调核对 Windows 线程与初始所有者一致。
