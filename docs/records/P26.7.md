# P26.7 快捷指令管理和布局

按 [CR-030](../changes/CR-030.md) 在本地终端侧栏增加管理和布局。配置以受保护记录和原版本比较方式保存。首次读取接受旧记录，首次新写入使用新的记录槽保存排序、置顶和显示选项，旧版本记录保留其升级前快照。

拖柄只在管理模式出现。管理状态不能从指令行触发运行。拖动和方向键操作在各自的置顶或普通区域内调整顺序，置顶和取消置顶用于跨区域。选中多项后拖动其中一项会移动它所在区域的已选项，顺序保持。批量移除冻结当时的版本和确切 ID，弹窗默认焦点为取消。服务端保存被拒绝时界面保留列表，用户可重新读取。

紧凑区支持单双列。全部展开仍处于原终端窗格内，换行显示命令与脚本路径。低于 270 CSS 像素宽的窗格临时使用单列，保存的列数不受影响。退出重新打开仍保留布局和置顶。

## Windows 软件实测

普通 release 实际运行，142 项前端测试通过。0.1.19 自建数据根存入 32 条 ADB 与 CMD 混合指令，0.1.20 首读逐项一致。实际 Windows 窗口测得紧凑行高约 38.2 CSS 像素。验收包含单列拖动、Escape 取消、方向键后焦点跟随、双列跨行拖动、多选全选清除、批量相对顺序、置顶和取消置顶。

移除两条入口的取消和并发冲突均保留原条目。并发改名保存后，旧确认被拒绝，重新读取并确认才移除。有脚本入口被移除，文件字节保持一致。管理期间模拟 ADB 和脚本执行均为零，恢复日常模式后一次实际点击只运行一次模拟 ADB。展开后完整显示长命令与中文脚本路径。窄窗可滚动到底，30 条时焦点可见。实际约 194 CSS 像素的分屏总览填满原窗格，单列且无横向溢出。重开后双列、展开和置顶保持。

保留初次紧凑行高不达标、分屏测试按钮未限定活动窗格的预检记录。打包首轮的旧 ADB 用例曾用旧文件和终端文本判断本次执行，采样早于新文件写入。用例改为等待本次新产物后，原候选专项通过，验收仍要求精确调用数。原本地标签用例在分屏焦点就绪时立即读取 xterm，截图已显示随后重绘的原草稿；改用有界等待保留同一 xterm 节点和精确草稿断言，在同一候选上复验通过。
