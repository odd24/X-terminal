# P26.9 MCP 快捷指令正式执行方案

本包依据 [CR-032](../changes/CR-032.md)，以 Windows x64 0.1.21 为基线。交付 0.1.22 可运行目录、契约和软件证据。保留现有用户数据与未提交修改。

## 需求与复用

MCP 管理与 Desktop 右栏使用同一数据目录、同一 ADB/BAT/CMD 列表和同一版本。保留已有布局、ADB 程序选择、旧格式迁移、置顶分区和右栏交互。AI 只登记或修改入口元数据。脚本登记只核对本机绝对驱动器路径与扩展名，实际文件可用性仍由原来的运行流程判断。AI 路径不打开脚本文件、不启动终端、不连接设备、不运行 ADB，也不修改或移除目标文件。

复用现有相邻 terminal-mcp.exe、当前用户 NamedPipe、对端 PID 和实际映像校验及固定 Desktop 预览。新的类型化桥分支在本地授权后进入 Desktop 的快捷指令存储，不借用会话服务的 Agent token 或通用 RPC。原 29 工具的 schema、参数、回执及授权保持原样。

## 工具契约

| 工具 | 输入与含义 | 成功结果 |
| --- | --- | --- |
| shortcuts_list | 无参数列举。query 可选，按名称、命令或路径做不区分大小写的有限字面筛选。也可单独传 receipt_request_id 查询原写入回执 | 当前 revision 与有序条目。回执查询只返回原提交版本、受影响的 ID 和请求编号 |
| shortcuts_create | request_id、revision、items。每个条目有名称、类型化的 ADB 命令或脚本路径，以及可选置顶 | 原编号、提交版本、新建稳定 ID 列表 |
| shortcuts_update | request_id、revision，changes 按 ID 更新名称、同类型命令/路径或置顶，moves 可把同组的一批 ID 放在未选中锚点之前或之后 | 原编号、提交版本和变动 ID |
| shortcuts_remove | request_id、revision、ids，接受单项或多项 | 原编号、提交版本和移除的入口 ID |

条目投影含稳定 ID、类型、名称、完整命令或路径、置顶状态及从 1 开始的原顺序。筛选保留原顺序和版号。无保存记录时公开全零 revision。正式写入编号使用 RFC9562 UUIDv7，同一写入须携带刚读取的版本。容量沿用 32 条和 64 KiB 存储上限。每批检查缺失、重复、无效类型、无效锚点和跨分区移动。未变化条目的相对顺序保留，置顶变化的条目按原相对顺序追加到目标区，随后在同区顺序应用 moves。任何一项失败都不提交。

## 授权与界面

主窗口在现有 MCP 连接面板分别预览和批准「查看快捷指令」及「管理快捷指令」。每个预览固定实际桥 PID、原待配对号、范围及期限，30 秒内只使用一次，默认不同意。期限选项为 15、60、300 秒。两种权限相互独立，可明确撤销，桥断开或 Desktop 重启即失效。管理可以提交变更及按原编号查回执，不因此取得列表正文。旧会话绑定不隐含快捷指令权限，快捷指令权限不隐含任何终端或文件操作。新桥可以独立使用快捷指令权限而无需选择 SSH 或串口会话。

未获查看权限的任何响应都不投影名称、命令或路径。错误使用固定码，领取状态和界面刷新事件只传授权元数据或版本号。已批准且先达到提交点的动作允许结束，撤销或到期后拒绝随后操作。

## 并发、事务及应答不明

与人工保存共用 Windows 独占锁和 CAS。受保护的现有列表记录与独立受保护的有限回执记录在一个 SQLite 事务同步提交。人工写入继续使用原格式并保留回执。写入请求以类型化参数的摘要匹配。有效管理权限下，同一编号、同一参数的已提交请求返回原安全回执，不再写入。已提交编号改参明确拒绝；回执保留最近 32 个，旧请求的已使用 revision 即使回执退休也无法再提交。

应答不明时工具和界面只提示用原编号查回执，或者用有权查看的列表核对。没有回执不能推断是否提交，不自动重发或改用新编号规避版本检查。重新配对后仍须新的管理批准才能查已有集合的安全回执。成功写入通知打开的右栏重新读取，未提交表单保留原编辑版本，陈旧保存明确被拒绝。

## 实施顺序、矩阵及交付门

1. 冻结类型化契约、稳定排序及事务回执，验证容量、原子性和相同/不同编号参数。
2. 接通原生桥独立批准、撤销、期限与定向刷新，再登记四个 stdio 工具。比较原 29 项的全部 schema 和注释。
3. 用真实 Windows Desktop 点击授权，官方客户端通过实际 stdio 检查未批准、查看专用、管理专用、到期及撤销，核对旧工具在原权限下继续工作。
4. 用一个自建混合列表测试筛选和排序，测试批量置顶/取消置顶、命令与脚本路径编辑、增删和失败回滚。模拟人工并发修改，检查 CAS、重试、原编号回执以及打开的面板自动更新。比较自建脚本 SHA-256 和指令执行计数。
5. 构建普通 Windows x64，复验公开工具、主界面、原快捷指令和关闭路径。发布目录旁保留证据，给出直接启动 exe、启用桥的步骤和测试边界。测试仅用合成数据和本机隔离目录，无 ZIP 和安装。
