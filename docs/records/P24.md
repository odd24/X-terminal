## 另存异常退出保全（2026-11-10）

`SaveTarget` 固定目标父目录及原文件句柄，验证并同步私有暂存，随后按句柄执行原名到备份及暂存到目标两次不覆盖改名。错误仍能返回时，发布失败尝试以原句柄不覆盖地恢复原名。进程被强制终止时这段错误处理无法运行。Desktop 的 `Registry`、确认码和阶段回执属于当前进程，渲染器保存的编号无法重建这些状态。原编号查不到时，无法仅凭这个结果判断哪一步已执行。

在三份独立自建中文临时根中，Rust 测试父进程启动实际子进程。子进程调用真实 Windows 保存库，到达同步后的暂存、原名改到备份、发布完成但尚未发送测试回执三个固定位置后停住。父进程只终止该子进程并等待退出。新进程只观察固定名称及试查旧保存编号，不调用发布或恢复。每次从实际文件句柄取卷和文件索引，并读取完整合成字节。

| 强制终止位置 | 终止后证据 | 新进程观察 |
| --- | --- | --- |
| 暂存完成 | 原名仍是原对象，完整新字节在独立暂存中，备份不存在 | 原名与暂存的对象 ID 和全部字节一致 |
| 原名改为备份后 | 原名为空，备份仍是原对象，完整新字节仍在暂存 | 父进程在空位创建独立外部同名项，新进程核对同名项、备份、暂存的 ID 和全部字节保持 |
| 已发布、未发送测试回执 | 目标是新对象且字节精确等于源，备份仍是原对象，暂存名消失 | 新目标与备份的 ID 和全部字节一致 |

## 先行验证后的只读诊断提案（历史）

如果需要重启后在应用内说明残留，现有内存回执和文件名不足以建立关联。建议先评审一个原生私有、版本化、有界的只读诊断槽。保留 `save_id`、阶段提示、经过显示转义的基名，以及准备时从已固定句柄取得的目标父目录和原文件/暂存对象标识。暂存同步后、首次改名前记录意图，后续记录可推进到备份或已发布。断在改名和记录之间时显示“结果不明”，任何阶段提示均不等同当前磁盘状态。

建议首版省略持久绝对路径、文件内容和确认码。启动只读固定应用根中的记录，显示可能保留的文件名；应用无法据此自动定位旧目录。若以后需要核对，另行协调由用户通过原生选择器指定父目录，并按目录/文件标识和可信内容指纹只读验证。对象标识或指纹无法核对时保持未知，尤其不能用文件名、长度或路径存在来认证旧对象。若决定承诺记录持久性，首次改名前的记录写入失败需要明确失败策略，这会增加保存路径的同步成本。另存过程和确认页暂不引入该依赖。

持久记录只解释保全状态。旧确认、旧授权和未决提交的有效期随原进程结束，记录不得触发续存、恢复、替换、删除、重命名或重放。外部同名项和备份继续保留。该设计等待统筹协调。
