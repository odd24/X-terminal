# P13 SSH1 正式兼容

## Windows helper 第一包（2026-11-19）

沿 [ADR-003](../decisions/ADR-003.md) 和 [P04](P04.md) 的实测路线，增加独立 Windows x64 MSVC `ssh1-helper.exe` 和 Rust 私有协议类型。构建入口 `pwsh -NoProfile -File scripts/Build-Ssh1Helper.ps1` 核对锁定的 PuTTY 0.85 源码归档 SHA-256，从自建临时目录构建未修改的 PuTTY 后端。helper 需要显式构建，未加入 Desktop 或 session-service 的普通启动和打包。记录的 P04 夹具能力充分支持推进此包，真实旧端点及分发仍另验。

### 私有边界

- 每个进程只跑一条连接。父进程先配置关闭即终止的 Job 和私有继承管道，再发版本 1 `Start`。helper 只接受显式 SSH1，启动时没有附加 argv。helper 自查管道和 Job 成员身份，父进程身份由启动边界保证。父端负责专用 Job 所有权、限制继承句柄、持续读输出，遇到阻塞或超时时关闭 Job 并 wait 回收。helper 只使用内存配置。
- `Start` 冻结显式 SSH1、host/port、用户名、初始尺寸、连接 UUID/代次和启动 UUID。仅直接连接；代理、sharing、agent、X11/转发来源和 PuTTY 注册表会话关闭。主机存储钩子仅对本连接的 RSA1 查询回复缺记录，其余拒绝，写入拒绝。每次均由 Seat 发主机挑战。主机响应必须匹配本次会话、挑战 UUID、种类及原指纹；密码响应必须匹配独立的原密码挑战。错配、格式错误、重复已消费回应都结束本次 helper，不转交其他后端，无自动重试。此包主机批准仅本次生效，算法标识仅 RSA1 主机键。
- 使用现有 `session-protocol` 的有界长度前缀和严格 typed JSON。Rust 直接读继承句柄到帧格式的临时缓冲，密码以 `SensitiveBytes` 交付，最多 8192 字节并拒绝 NUL。C 将临时拷贝交给 PuTTY 的非持久提示缓冲后擦除，原对象回调一次。密码不走 argv、env、配置、应用输出或诊断。密码拒绝后要求结束并启动新连接意图。
- 后端、Seat、输入与 resize 均在 Windows 所有者线程调用。仅在认证后且后端可输入时产生 `Ready`，启动请求 PTY；该事件仅代表输入可用，远端是否批准 PTY 需要独立证据。输入最多 16 KiB，本地未发缓冲达到限制时失败。输出按不超过 16 KiB 的应用帧和固定类别控制事件区分，stderr 应用数据有独立标记，原始后端诊断不进入任一公共帧。独立读取线程和有界写出队列确保父端堵塞时后端停止，不把部分交付当成功。
- 第一个帧由 helper 等待最多 5 秒；原生连接的就绪等待定时 30 秒，父端 Job 处理同步 OS 调用或停读等情况。显式 `Close` 或控制 EOF 释放原后端；最终 `Ended` 原因无原始异常文本。PuTTY 的结束回调可包含 EOF，因此 `backend_status` 只表述后端报告值，不能单独证明对端发出协议退出包。父端仍应区分消息、真实进程退出和 Job 强制回收。

### 实测

专用入口实际构建 PuTTY 并链接 Windows x64 Release helper。源码从锁定归档展开。链接 map 中存储查询和写入使用 `owner.obj`，Windows 默认存储对象缺席。最终本地 helper SHA-256 为 `63f00444e09b17d0db0bcbd0bba291bb09146f0450a8dcea1e1a6e1aa846a166`。早期构建在中文 CMake 工作目录、开发环境切换后找不到 Rust 工具，以及缺少 PuTTY 后端列表对象处分别停住。改用自建临时 CMake 根、在开发环境激活后进入项目工具链，并链接原后端列表后通过。普通 `cargo check --offline --locked -p transport-ssh1 --lib` 和格式检查通过，实际 helper 拒绝附加 argv 并退出 2。

在 UID 1000 的新 WSL 私有根 `/tmp/P04-ssh1.YNEG4Tvw` 复核原版 `uppity` 和 `puttygen` 的锁定哈希，生成新 0600 RSA1 主机密钥。父端示例通过自有 `127.0.0.1` 临时端口转接单个 WSL stdio 对端，Linux 运行在独立网络命名空间。复现命令为 `cargo run --locked -p transport-ssh1 --example helper_probe -- <helper.exe> <WSL私有根> <锁定源码>/unix/uppity.c`。示例每轮先分配 Windows Job，核对框架中的身份与源公开指纹，合成密码只进入原密码挑战。

- 登录轮真实核对主机指纹并批准，实际输入一次合成密码，收到 `Ready`，依次发送有界 resize 和固定输入。远端检查两端 TTY 后输出独立 CRLF 标记，父端从应用数据匹配，收到后端状态 0 和实际进程退出 0。首次运行缺少预期的独立输出行，固定命令先输出换行后使标记独占一行，复测通过。原版 WSL 夹具会忽略 resize，正式 helper 此轮只验证控制路径与后续输入正常，P04 的 wire 和应用证据分别保留。
- 拒绝主机轮在原主机挑战后返回 `host_declined`，无密码或应用帧。挑战种类错配轮到达原密码挑战后发送错配响应，返回 `invalid_control`，未启动终端。关闭轮停在主机确认，原会话 `Close` 返回 `closed`。这三轮 Windows helper 均实际退出 0，退出码代表成功交付终态，连接结果由 `Ended` 决定。
- 通过轮次的 helper stderr 均为空。原版 WSL 进程均由 8 秒期限收回，返回 124，与 helper 退出分列。已确认 Windows 与 WSL 无本轮进程残留，并移除临时私钥及空口令文件。未重跑旧矩阵。
