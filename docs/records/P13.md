# P13 SSH1 正式兼容

## Windows helper 第一包（2026-11-19）

沿 [ADR-003](../decisions/ADR-003.md) 和 [P04](P04.md) 的实测路线，增加独立 Windows x64 MSVC `ssh1-helper.exe` 和 Rust 私有协议类型。构建入口 `pwsh -NoProfile -File scripts/Build-Ssh1Helper.ps1` 核对锁定的 PuTTY 0.85 源码归档 SHA-256，从自建临时目录构建未修改的 PuTTY 后端。helper 需要显式构建，未加入 Desktop 或 session-service 的普通启动和打包。记录的 P04 夹具能力充分支持推进此包，真实旧端点及分发仍另验。

### 私有边界

- 每个进程只跑一条连接。父进程先配置关闭即终止的 Job 和私有继承管道，再发版本 1 `Start`。helper 只接受显式 SSH1，启动时没有附加 argv。helper 自查管道和 Job 成员身份，父进程身份由启动边界保证。父端负责专用 Job 所有权、限制继承句柄、持续读输出，遇到阻塞或超时时关闭 Job 并 wait 回收。helper 只使用内存配置。
- `Start` 冻结显式 SSH1、host/port、用户名、初始尺寸、连接 UUID/代次和启动 UUID。仅直接连接；代理、sharing、agent、X11/转发来源和 PuTTY 注册表会话关闭。主机存储钩子仅对本连接的 RSA1 查询回复缺记录，其余拒绝，写入拒绝。每次均由 Seat 发主机挑战。主机响应必须匹配本次会话、挑战 UUID、种类及原指纹；密码响应必须匹配独立的原密码挑战。错配、格式错误、重复已消费回应都结束本次 helper，不转交其他后端，无自动重试。此包主机批准仅本次生效，算法标识仅 RSA1 主机键。
- 使用现有 `session-protocol` 的有界长度前缀和严格 typed JSON。Rust 直接读继承句柄到帧格式的临时缓冲，密码以 `SensitiveBytes` 交付，最多 8192 字节并拒绝 NUL。C 将临时拷贝交给 PuTTY 的非持久提示缓冲后擦除，原对象回调一次。密码不走 argv、env、配置、应用输出或诊断。密码拒绝后要求结束并启动新连接意图。
- 后端、Seat、输入与 resize 均在 Windows 所有者线程调用。仅在认证后且后端可输入时产生 `Ready`，启动请求 PTY；该事件仅代表输入可用，远端是否批准 PTY 需要独立证据。输入最多 16 KiB，本地未发缓冲达到限制时失败。输出按不超过 16 KiB 的应用帧和固定类别控制事件区分，stderr 应用数据有独立标记，原始后端诊断不进入任一公共帧。独立读取线程和有界写出队列确保父端堵塞时后端停止，不把部分交付当成功。
- 第一个帧由 helper 等待最多 5 秒；原生连接的就绪等待定时 30 秒，父端 Job 处理同步 OS 调用或停读等情况。显式 `Close` 或控制 EOF 释放原后端；最终 `Ended` 原因无原始异常文本。PuTTY 的结束回调可包含 EOF，因此 `backend_status` 只表述后端报告值，不能单独证明对端发出协议退出包。父端仍应区分消息、真实进程退出和 Job 强制回收。

### 实测

专用入口实际构建 PuTTY 并链接 Windows x64 Release helper。源码从锁定归档展开。链接 map 中存储查询和写入使用 `owner.obj`，Windows 默认存储对象缺席。最终本地 helper SHA-256 为 `63f00444e09b17d0db0bcbd0bba291bb09146f0450a8dcea1e1a6e1aa846a166`。早期构建在中文 CMake 工作目录、开发环境切换后找不到 Rust 工具，以及缺少 PuTTY 后端列表对象处分别停住。改用自建临时 CMake 根、在开发环境激活后进入项目工具链，并链接原后端列表后通过。普通 `cargo check --offline --locked -p transport-ssh1 --lib` 和格式检查通过，实际 helper 拒绝附加 argv 并退出 2。

在 UID 1000 的新 WSL 私有根 `/tmp/P04-ssh1.YNEG4Tvw` 复核原版 `uppity` 和 `puttygen` 的锁定哈希，生成新 0600 RSA1 主机密钥。父端示例通过自有 `127.0.0.1` 临时端口转接单个 WSL stdio 对端，Linux 运行在独立网络命名空间。复现命令为 `cargo run --locked -p transport-ssh1 --example helper_probe -- <helper.exe> <WSL私有根> <锁定源码>/unix/uppity.c`。示例每轮先分配 Windows Job，核对框架中的身份与源公开指纹，合成密码只进入原密码挑战。

- 登录轮真实核对主机指纹并批准，实际输入一次合成密码，收到 `Ready`，依次发送有界 resize 和固定输入。远端检查两端 TTY 后输出独立 CRLF 标记，父端从应用数据匹配，收到后端状态 0 和实际进程退出 0。首次运行缺少预期的独立输出行，固定命令先输出换行后使标记独占一行，复测通过。原版 WSL 夹具会忽略 resize，正式 helper 此轮只验证控制路径与后续输入正常，P04 的 wire 和应用证据分别保留。
- 拒绝主机轮在原主机挑战后返回 `host_declined`，无密码或应用帧。挑战种类错配轮到达原密码挑战后发送错配响应，返回 `invalid_control`，未启动终端。关闭轮停在主机确认，原会话 `Close` 返回 `closed`。这三轮 Windows helper 均实际退出 0，退出码代表成功交付终态，连接结果由 `Ended` 决定。
- 通过轮次的 helper stderr 均为空。原版 WSL 进程均由 8 秒期限收回，返回 124，与 helper 退出分列。已确认 Windows 与 WSL 无本轮进程残留，并移除临时私钥及空口令文件。未重跑旧矩阵。

此步关联 `Step-ID: P13`。后续需将正式服务的受管启动、主机信任及凭据 UI、日志、重连和错误映射接到同一协议。真实旧端点、完整 resize 验收、安装分发、长期运行及完整 P13 保持开放。

## session-service 固定配置回路（2026-11-19）

Desktop 已认证 Named Pipe 客户端使用既有 `ssh::StartFixed`，仅允许显式启用的已保存 SSH1 和精确配置修订。普通 `Start` 不启用 SSH1，原 SSH2 路径和 Agent 的 SSH2 固定配置路由保持。接入复用 Session UUID、代次、启动回执、输入 FIFO 和日志捕获，公开协议结构不变。SSH1 以自己的协议标记进入连接及日志。Agent/Observer 的发票据、Agent Profile 授权、连接操作、读取和输出投影拒绝 SSH1，MCP 入口未扩大。

`pwsh -NoProfile -File scripts/Build-Ssh1Helper.ps1 -WithService` 先构建锁定原版 PuTTY 和 Release helper，审计存储符号链接，再将该可执行文件的 SHA-256 编入独立配置的 Windows 服务。本地产物成对暂存在同一自建目录。普通服务构建无此功能开关，缺少构建期 pin 时拒绝启用，没有运行时路径或 hash 覆盖。启用后仅打开当前服务同目录的 `ssh1-helper.exe`，拒绝重解析点、异常尺寸和 hash 不符，启动前持只读且禁止写入及替换的句柄。父进程只传专用管道，将 helper 放入关闭即终止的 Job 后才送启动帧。子进程清除继承环境，仅由 Windows API 提供系统目录所需的 `SystemRoot`。安装、发布与运行时许可交付仍由后续包验收。

私有 wire v2 将 PuTTY 完整 RSA1 公钥的规范串交给现有主机信任库，以 SSH1/host/port 为范围计算 SHA-256，未知或变更继续使用原主机确认和修订 CAS。helper 自身仍挑战每次连接，已知的精确键由服务信任库核对后应答。现有认证审批只接受为原挑战提交一次临时密码，Vault 已保存材料暂未接入。输入仍走原编号 FIFO，单帧 16 KiB，服务只有收到 helper 所有者线程对原编号和字节数的确认，才报告送入管线。丢失或超时仍按原编号进入未知，不重放。实际应用输出沿 Session 缓冲及录制，诊断使用白名单故障。

Desktop 编号关闭先取消原代次，再尝试发一次私有关闭帧。管道错误、EOF 或期限到达时收回 Job。只有确认未启动进程或已 wait 到进程结束且 Actor 完成，编号回执才进入 `TransportEnded`。该回执描述本机运输资源回收，未标成远端命令退出。公开的 SSH1 resize、Exec、重连、正式 GUI 和 Vault 路由留在后续包。

### 构建与实测

- 实际运行 `Build-Ssh1Helper.ps1 -WithService`。最终 helper SHA-256 为 `2e22fcf45d79f47299b508019f16ebbf50ee97b07e675c5cc252a7bdf13f4a9d`，修正后的同目录服务 SHA-256 为 `8a309e841e27001770dd7202ffe02fc0b3df65641b01ffd5695e26940d399592`。初次 IPC 正向在主机挑战前失败。相同 v2 helper 的独立探针在继承系统环境时四轮通过，清空环境时复现失败。修正为只从 Windows API 设置 `SystemRoot`，重建固定 pin 的服务后 IPC 通过。
- 定向测试 `cargo test --offline --locked -p session-service --test windows_ipc p13_ssh1_ -- --ignored --nocapture --test-threads=1` 使用 `P13_SERVICE_EXE`、`P13_WSL_ROOT`、`P13_UPPITY_SOURCE` 仅给测试父端定位产物与原版夹具。实际服务保持 `fixture=false`，在仿 Desktop 的外层 Job 中通过项目标准 IPC 握手。配置与日志写到自建中文根。WSL 用新 `/tmp/P04-ssh1.rIOWvma6`、独立网络命名空间和原版 stdio `uppity`，重新核对程序哈希及生成独立 0600 RSA1 私钥。服务只有同目录已锁定 helper 连上临时 Windows 回环。
- 正向收到协议正确的 SHA-256 主机审批，拒绝错误代次，提交原挑战的临时合成密码后连接。回执 `PipelineQueued` 匹配真实 helper 的原输入编号和字节数。远端检查两端 TTY 后输出独占标记，普通 IPC `Read` 实际读到 CRLF 输出。停止录制后核对 SSH1 元数据、非空原始数据和持久水位。负向拒绝原主机挑战得到 `HostKeyRejected`。两轮均观察编号关闭达到 `TransportEnded`，服务实际退出。错配置修订、ID-only 启动、SSH1 Agent 配置及连接票据、Observer 读取票据和暂未支持的已存密码请求均拒绝。自建不匹配 helper 目录的测试在网络连接前失败。
- 普通 `cargo build --offline --locked -p session-service --bin session-service` 实际通过。默认服务无 pin 拒绝 SSH1 且未接纳连接，原 SSH2 真实握手、审批、共享输出影响回归通过。WSL 正负两轮均独立由 8 秒期限回收并返回 124。已确认测试 Windows 服务、helper 与 WSL 进程退出，移除本轮临时私钥，未重跑旧矩阵。

## Desktop 显式 SSH1 本机预览（2026-11-19）

会话树保留同一配置读取的修订号，只有 Desktop 服务的 `pong` 宣告构建期 SSH1 能力且保存项启用 SSH1 时才提供连接。单击配置只选中。连接行动先展示保存目标和旧协议提示，用户肯定选择后才发固定 `StartFixed`。回复核对原服务、原配置、修订、启动编号、SSH1 和代次。回应丢失时只发原号 `ConnectStatus`。主机确认核对端点、RSA1、SHA-256 指纹和当前挑战，密码只进入同一代次的原挑战。退出连接窗口最多对已确认的原代次发编号关闭，尝试未知时只先查询原启动编号。

成功会话使用原终端控件、编码、输入队列和基础录制面板。标签和输入状态显式显示 SSH1。关闭标签用原代次的编号关闭。默认直连入口仍是 SSH2。SSH1 只有初始远端尺寸，视口仍可本地调整。SSH1 保存项的密码仅临时输入，工作区连接、分屏和 Agent 目标保持在支持的协议范围内。

`pwsh -NoProfile -File scripts/Build-Ssh1Preview.ps1` 先构建普通 Desktop 和服务，再用既有 `Build-Ssh1Helper.ps1 -WithService` 生成锁定配对。显式预览在同一目录复制 Desktop、锁定服务、helper 和终端 MCP 可执行文件并记录各文件 SHA-256。默认普通预览仅复制原三件，并检查 SSH1 能力缺席。两种预览均是本机开发产物且拒绝 fixture API。

实际 `desktop:build`、四件套配对及默认三件套预览均通过冒烟。用新建中文应用数据根和 `/tmp/P04-ssh1.2Jfvg6Nx` 的原版 WSL 私有 stdio 夹具执行 `node scripts/Test-Desktop-Ssh1.mjs <WSL私有根> <锁定源码>/unix/uppity.c`。从 GUI 保存显式 SSH1 项并打开。初始两处勾选均未选中，选择本次旧协议前没有 TCP 连接。实际 `StartFixed` 应答在 WebView 接收层被定向丢弃，随后只查询原号，WSL 仅收到一次 TCP 连接。用夹具公开 RSA1 键重算并匹配指纹，再在原连接代次的密码框输入合成密码。焦点进入同一代次终端，固定命令的真实 CRLF 输出同时出现在 IPC 原始缓冲和 Desktop 屏幕快照。GUI 启停录制，核对 SSH1 元数据及同步完成后的非空原始字节。实际标签关闭后本次 helper 退出。
