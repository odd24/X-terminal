# P26.32 桌面性能优化实施与复验

本步骤承接 [P26.29 执行方案](P26.29.md)、[P26.30 基线](P26.30.md) 和 [P26.31 ADB 等待优化](P26.31.md)。单机 Windows 23H2、i3-12100、平衡电源方案，WebView2 158.0.4370.33。使用同一发布构建配置与隔离数据根，原版和候选交替测量。SSH 为回环测试端，ADB 为自建模拟程序，串口为单独目录的测试服务。

## 取舍及正确性边界

- **B 快照。** 单窗也反复支付 Ping 和 List 两次往返。实施无缓存的组合请求以覆盖单窗与多窗，窗口移交时即时过滤。原生互斥锁继续串行化需要有序的操作。快照成功次数能准确换算该路径的服务请求次数；IPC 往返计时包含调度和服务处理，不能单独证明锁竞争的比例。
- **C 快捷指令。** 保留 PowerShell、固定设备、完整命令和脚本语义。独立优化与验证见 [P26.31](P26.31.md)。模拟设备的 `pwd` 真实经过 ConPTY 后回显，点击到首段内容和点击到设备可输入分别统计。
- **D 输出。** 同一快照携带匹配代次的输出游标。普通键入和活跃输出沿用快速轮询，空闲已追平时依靠游标变化唤醒并每秒做一次真实兜底读取。首绑、断开尾段、真实游标分页、输出缺口和窗口归属仍在原路径验证。详见 [ADR-100](../decisions/ADR-100.md)。

任一候选出现错投、未报告缺口、重复执行或持续超出基线波动的前台退化，需要按步骤回退并复验。回退桌面快照时桌面和服务须成对替换。本次不迁移用户配置，不注册 MCP，不覆盖已安装的正式版。

## 同机发布版结果

| 双窗口空闲 30 秒 | 原版两批 | 候选两批 |
|---|---|---|
| 两窗合计快照次数 | 539、540 | 541、543 |
| 空闲 SSH 读页次数 | 269、270 | 29、28 |
| 快照和读页对应的服务请求总数 | 1347、1350 | 570、571 |
| 独立 SSH 窗格 WebView 任务时间，ms | 2199、2381 | 1857、1716 |

快照刷新频率一致。原版每个快照两次服务 RPC，候选一次；加上真实读页后，两条路径的服务请求总数下降约 58%。CPU 采用相同进程树采样器的一组原版／候选，双窗口 Desktop 累计 313／188 ms、会话服务 1109／313 ms、WebView 子进程合计 1547／1359 ms。首次候选使用较慢的 CIM 枚举，后改为同一系统进程快照；上述 CPU 对照只取相同采样器。单次 CPU 观测不用于预测所有机器的降幅。

| 交互指标，P50／P95，ms | 原版 | 候选 |
|---|---|---|
| 单条 ADB 点击至设备提示符且已聚焦，每版 30 次 | 154／177 | 143／160 |
| 两行 ADB 点击至设备提示符且已聚焦，每版 30 次 | 193／216 | 176／215 |
| SSH 单窗格回显，每批 30 次，列两批 P95 | 45、44 | 50、41 |
| SSH 双窗格回显，每批 30 次，列两批 P95 | 52、43 | 46、41 |

两行 ADB 的中位数改善约 17 ms，P95 基本持平。首屏内容可能只是本机提示；设备可输入与随后执行 `pwd` 获得正确应答分别校验。突发场景先空闲 30 秒，再由回环 SSH 主动输出 1000 行和末尾标记，跨页共 75,010 字节，逐字节相等并见到绘制尾标。独立窗口快照只含移交目标，主窗口快照无该目标。

## 原生互斥锁测量

同一 Release 服务、真实命名管道、客户端用与桌面一致的 Tokio 互斥锁，60 轮中交替比较两次请求和一次快照。每轮同时提交两个快照与一次空页读取。以下为微秒，P50／P95。测试刻意让三个操作相遇，实际独立窗口的调度仍以端到端场景为准。

| 指标 | Ping 加 List | 组合快照 |
|---|---|---|
| 快照排队 | 15／1688 | 79／1174 |
| 快照应答耗时 | 878／1845 | 935／1412 |
| 快照持锁 | 881／1854 | 942／1425 |
| 空页读取排队 | 1869／3156 | 1817／2172 |

锁排队和持锁的高位值下降，快照中位持锁略升。实测支持先减少往返，继续保留有序客户端。复现命令为 `cargo test --locked -p session-service --test windows_ipc measure_shared_client_snapshot_contention -- --ignored --nocapture`，需先按 README 构建 Windows x64 发布服务。该测量记录为 `artifacts/P26.32-native-timing.txt`。

## 标签规模与连续日志

**E 标签。** 每版 5 次独立启动，各规模 150 次同标签切换。4 个本地标签时，原版 P50／P95 为 8.9／28.5 ms，候选为 9.0／21.0 ms。12 个本地加 8 个合成服务标签时分别为 9.4／13.3 和 9.7／13.5 ms。4 标签在双源输出场景之后测量，跨规模比较需考虑预热；同规模两版差值很小。保留排序和组件布局。首次尝试建立 20 个本地终端时触及既有 16 个上限，修正夹具为混合标签，保留容量约束。5 次启动每次核对两个进程各 480 条连续输出及末段。测试选中与焦点来自实际 WebView，位置命中和复制另用标签专项。

**F 日志。** 原版和候选各用 8 路独立合成源，每源 120 帧、间隔 50 ms，逐源核对 245,760 字节。在其中一路录制到 worker 结束且持久化，120 条、30,720 字节，零源缺口、零拒绝。屏幕标记 P95 为 56／47 ms，重新连接的代次刷新约 137／137 ms，双版本均实际移除标签并经受管理关闭，审计为 CLOSED。该负载下未出现需要调整磁盘架构的现象。维持持久化和拒绝语义；历史 E 盘特定吞吐失败与长稳边界见 [P22](P22.md)。复现入口为 [发布版多源测量](../../scripts/Measure-Desktop-Release.mjs)。

内存 UART 使用单独目录的夹具服务对比两版桌面。30 次键入录制得到 30 条、120 字节，原版及候选均持久化完成、零源缺口、零拒绝。由串口启动两行模拟 ADB，每版 15 次到可输入 P50／P95 为 198／255 和 166／190 ms；单条为 152／174 和 155／173 ms。未连接物理串口或 Android 设备。

## 验证与交付

| 层次 | 已核对结果 |
|---|---|
| 普通发布启动 | 每版另起 3 次独立普通服务，原版桌面就绪 738、726、783 ms，候选 754、768、756 ms。PowerShell 保留原交互及焦点。观测量和波动不足以判定启动提速 |
| 前端及 Rust | 145 项前端测试、121 项 session-core、57 项 session-protocol 通过。真实管道核对 Desktop 与 Ping／List 等价、Observer 和有效 Agent 被拒、缓冲覆盖游标和缺口。源码构建使用 README 的 x64 Release 配置 |
| 交互与路由 | SSH／内存 UART 的真实快捷入口、脚本成功／失败、取消、自动关闭、原窗口焦点均覆盖。额外阻塞真实快照后仍能读取新输出；刻意延迟携带正文的旧会话读页，切换后只绘制新目标内容，切回能看到原文。复现时在 SSH 快捷路由脚本后加 `--verify-reads` |
| 标签 | 普通本地标签拖动、拆分、合并、取消、独立复制专项通过。混合本地和 SSH 的 Windows 实体指针／双击复制及准确输入归属专项通过 |
| 产物 | 独立可运行目录 `artifacts/SharedTerminal-0.1.36-perf-P26.32` 中三份普通程序与发布构建逐一核对 SHA-256，使用复制后的实际桌面通过 SSH 和 ADB 路由回归。无需解压，正式安装仍使用既有版本 |

另在复制出的普通构建上单独启动隔离数据根，经 Windows 核对自建服务的 PID、父进程和映像路径后终止该子进程。桌面显示服务不可用，快照和状态请求均返回 SERVICE_UNAVAILABLE，原桌面仍存活；报告为 `artifacts/P26.32-service-loss.json`。

完整的数值汇总、采样数、原始报告文件名及哈希见[测量摘要](../evidence/P26.32-summary.json)。比较时使用相同测试层级。CIM 计数器曾超时，改用仓库已有的进程树快照采集自有进程；失败运行与后续完整批次分别记录。当前工作包已完成，后续如出现实际设备等待、日志积压或明显的标签延迟，可复用 [P26.29](P26.29.md) 对应入口做专项定位。
