## 设备身份阶段

新增 transport-serial::device：Windows SetupAPI 枚举 GUID_DEVINTERFACE_COMPORT，保留私有专用路径/设备实例/端口名，重新验证完整选择后仅通过接口打开。相同 COM 对应新设备、旧设备改号、接口改变、消失、歧义均不回退别名；旧驱动未识别名称与单项元数据失败显式报告。最多 256 项，有界 UTF-16、ABI 长度/对齐检查、集合/注册表句柄 RAII。保留 P05 原型入口；正式服务后续只能使用 open_selected。

增加已在仓库锁定的 windows-sys 0.61.2 直接依赖及特性，离线更新 Cargo.lock；不修改上游缓存、不安装驱动。首轮编译发现 HDEVINFO 是 isize，而 INVALID_HANDLE_VALUE 是指针类型，已改用该 API 的 -1 哨兵；未进行失败设备打开。

实际验证：cargo check -p transport-serial --locked、cargo test -p transport-serial --locked（原5+新增8=13项）、cargo clippy -p transport-serial --all-targets --locked -- -D warnings PASS；cargo run -p transport-serial --example inventory --locked 原生只读返回 1 个已识别接口、0 未识别名称、0 元数据失败。输出仅数量，不记录实际实例/序列号/路径，没有打开 COM、发送字节或改变控制线。测试中的 opener 为内存闭包，不冒充驱动打开。

新增测试覆盖替换/消失/改号/接口变化零打开、成功仅传入专用路径、配置/控制线归属无效拒绝、歧义接口与同实例多端口区分、未知端口显式、数量/元数据边界和 Debug 脱敏。Windows 设备实例不是硬件防伪证明，无序列号同型号换机的 OS 身份重用不能被承诺识别。

## 隔离 I/O 工作线程阶段（前置 9dd580b）

新增 worker：一个 OS 线程持有已选身份的串口句柄；全进程最多 64 个线程，命令 FIFO 16 排队+1在途，每写最多64KiB；Write/DTR/RTS/Break 串行，结果通道1项。原始输出16个4096字节块，消费者额外最多1块；慢消费者不阻塞读，显式字节 offset 缺口和 read/dropped 计数。共用短锁发布输出/计数，避免空队列与生产者入队竞争产生假缺口，具体见 ADR-024。

底层写最多1024字节一次，检查取消/已知驱动接受下界，部分失败/零写/异常计数结束连接并取消未派发尾部，绝不重放已知前缀。控制错误显式返回；Break 开启失败也视为可能已开启，退出前尝试清除，清理失败单独报告。取消一次置位并 best-effort CancelSynchronousIo，join 需在事件线程之外等待；不能用 Drop 或100ms超时设定冒充异常驱动已退出，不能伪造设备退出码。

首轮 cargo check 有 Rust1.99 fetch_update 重命名提示，改用 try_update；首轮21项测试/clippy通过后，复核补齐 Break 开启失败清理，最终22项（原13+9工作线程）PASS，包含真实 OS 线程中的内存端口，不打开真实COM。2000块并发消费验证全部8192000字节逐段只属于 Data 或 Gap，累计缺口等于丢弃字节；40块慢消费者覆盖尾部无后续数据仍显式报告缺口；部分写错误只记录ab，未派发后续never-send。队列取消、打开失败、控制错误、Break清理失败与FIFO均有断言。最终静态/格式/文档检查于提交前补充。
