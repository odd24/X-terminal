# 验证与验收计划

当前所有产品用例均为计划，未执行；文档检查不能替代功能测试。执行结果进入对应 docs/records/Pxx.md 或其引用的脱敏证据。

## 测试层次

- 单元：状态机、权限、输入队列、request_id 去重、编码边界、缓冲游标、触发冷却、配置迁移。
- 契约：IPC/MCP JSON Schema、版本不兼容、缺失/超限参数、错误类别、取消/超时。
- 集成：本地测试 SSH 服务器、隔离 SSH1、虚拟串口对、临时数据库和日志。
- 实机：用户授权的服务器/UNIX/串口设备、真实 Codex CLI 与桌面。
- 桌面：标签与焦点、复制/粘贴、多行输入、分屏、分辨率/DPI、中文输入法与键盘。
- 发布：干净 Windows 安装、WebView2 前提、升级/卸载、数据迁移、长期运行。

## 阶段门与缺陷

[CR-001](changes/CR-001.md) 将用户设备验收安排在后续，软件/协议/模拟结果必须单独标记。P03/P04/P05 未执行的真实端点、完整 SSH1/控制线项目仍开放，随 P09/P10/P13/P16/P23 补充；不降低 T01–T21 条件。P07 等独立软件可先验证状态机/ACL/IPC，不能因此将 G0 或实际协议/设备行填 PASS。

- G0：后端候选已验证，风险与许可记录，实际设备缺口单列。
- G1：基础 SSH2/串口可工作，日志与配置可恢复；Alpha 限制明示。
- G2：SSH1 与 Codex 实际闭环通过，权限负向测试通过。
- G3：效率工具全部有验收结果，Xshell 导入支持范围明确。
- G4：需求矩阵全部有证据，安装/恢复与长稳通过；无 S0/S1。

严重度：S0 凭据泄露、越权执行、不可恢复数据损坏；S1 连接/数据丢失或主流程不可用；S2 局部功能缺陷有替代方案；S3 外观/文案。S0/S1 阻断完整发布；S2 必须有范围说明和处理决定。记录缺陷 ID、复现、对应 commit、修复 commit、回归结果。
