## 1. 第一批角色与任务

采用一个统筹会话 A、两个执行会话 B/C。每个执行会话拥有独立目录、分支和可变构建产物；A 保留当前集成目录。这里的 A/B/C 是责任标识，不是新增 Step-ID，也不表示后台子 Agent。创建会话和启动开发另行执行，本次归档不创建会话。

| 会话 | 目录/分支 | 第一批任务 | 交付要求 |
|---|---|---|---|
| A 统筹集成 | 当前仓库目录，当前 `codex/execution-plan` 分支；启动时核实实际分支 | 确定共同基线、分配文件、审核提交、按顺序集成、独占服务 IPC 与桌面自动化时段 | 提交清单、集成检查、开放问题、下一批准入结论 |
| B 屏幕兼容 | 同级 `终端模拟器-reflow`；`codex/p11-reflow-extreme` | P11.7 满历史、2↔500 列/600 行容量往返差异的最小复现、原因和修复调查 | 实现或有价值的调查证据、实质测试、P11.7 记录及本地提交 |
| C 保存边界 | 同级 `终端模拟器-save`；`codex/p11-save-boundaries` | P11.4 按 ADR-033 补齐本地特殊目标的拒绝、文件保持和发布冲突证据 | 已有覆盖/缺口表、必要修复与测试、P11.4 记录及本地提交 |

P11.7 普通重排已由 `d80f5b2` 提交，原7项/新增27项匹配，另1项极限 KNOWN_DIFFERENCE 保留；这些是既有记录，不是第一批新验证。C 不重复已完成的普通/恢复另存 GUI、编码或剪贴板工作。

## 2. 启动顺序

1. A 阅读 AGENTS、台账、本手册、当前步骤记录和关联 ADR，运行 `git status --short --branch` 与近期 `git log`，核对已有修改；有其他会话写入时先明确归属，不覆盖、不清理。
2. A 确定包含本手册的共同集成提交，将完整 hash 填入本批任务单。先检查 `git worktree list`、分支及目标路径，已有 worktree 从现状继续，不重建或强制覆盖。
3. 确认路径和分支均未使用时，在集成目录执行以下 PowerShell 示例；每条成功后再执行下一条。`$parallelBase` 是已核对的本批基线。

```powershell
$parallelBase = git rev-parse HEAD
git worktree add -b codex/p11-reflow-extreme ../终端模拟器-reflow $parallelBase
git worktree add -b codex/p11-save-boundaries ../终端模拟器-save $parallelBase
```

4. 在各自目录创建 B/C 会话，发送本手册第4/5节任务单，写明角色、绝对目录、分支、基线、文件范围和交付条件。核对会话实际 cwd/HEAD 后才开始开发。
5. B/C 分别执行 `. ./scripts/Enter-Toolchain.ps1`；需要前端依赖时在各自目录执行 `npm ci --ignore-scripts`，记录真实结果。各自使用 worktree 默认 `target`、`node_modules`、`artifacts`，不得设置为共享可变目录。脚本若硬编码集成路径，先由 A 处理，不用共享二进制绕过。
6. A 将本批分工、基线、目录/分支、状态及资源时段作为带时间的追加记录写入台账；B/C 在各自步骤记录登记开始状态。执行状态必须是实际已发生的事实。

只分派既有 P11.7/P11.4 范围内的后续子产物，提交沿用对应 Step-ID。若需另立子编号，先由 A 更新计划和台账，不由执行会话临时发明编号。

## 5. C 会话启动任务单

> 在指定 save worktree，从 A 提供的共同基线继续 P11.4。先读 AGENTS、执行台账、P11.4记录、ADR-032/033/035和已有selected_save测试，建立“场景—已有用例—缺口—本次证据”表，已覆盖项引用现有证据，缺口才新增。按现有策略补本地特殊目标拒绝、文件保持和发布失败验证，发现缺陷则在所有权范围内修复。不得扩展网络保存、自动恢复授权或调用者任意路径接口；跨重启任务恢复留待独立分包。只用自建中文前缀临时目录，清理仅自己的对象；沿用 Step-ID: P11.4，仅本地提交，不把拒绝通过解释为特殊目标保存已支持。服务IPC/原生选择器和桌面验证由A排队。

| 检查场景 | 期望与证据 |
|---|---|
| 目录或只读目标 | 明确拒绝，原对象保持 |
| 父目录/目标 junction、reparse | 按既定策略拒绝，不越界访问或清理；只创建和解除自己的链接 |
| 应用数据目录及子树 | 拒绝，源日志、数据库、受管理导出保持 |
| 流语法、尾点/尾空格等非法名称 | 拒绝，不悄悄改名；优先文件库构造，不能向公共RPC增加路径入口 |
| 私有暂存/备份/发布名称冲突 | 不覆盖已有条目，报告实际结果 |
| 备份后发布失败/原名被占用 | 核对原对象、backup和staging实际状态，RECOVERY_REQUIRED不虚报回滚 |

最低检查：

```powershell
cargo test -p terminal-log --locked
cargo clippy -p terminal-log --all-targets --locked -- -D warnings
cargo fmt --all -- --check
```

修改原生宿主时追加 `cargo test -p shared-terminal-desktop --locked` 和该包all-targets严格clippy；修改前端时追加 `npm run lint`、`npm test`。测试只补行为缺口，不能用镜像实现的测试充数。需要特殊文件系统能力而环境不具备时仅该行标未执行/阻塞，不强改用户环境，不将跳过计通过。

## 6. 共享资源与验证时段

B/C 可同时编辑、跑屏幕差分和各自不启动外部服务的库测试。真实服务IPC、WebView、桌面构建与自动化由A统一串行安排，第一批不假设现有脚本支持多实例隔离。

A每次运行前在台账追加角色/提交/专项/开始时间，状态RUNNING；确认此前自己的测试进程退出且服务普通二进制恢复后才开始下一项，结束时追加结果和结束时间。其他会话此期间不启动测试应用、不改测试二进制，不操作系统剪贴板、选择器或窗口焦点。不得关闭用户的其他窗口或进程。中断时登记尚存的自建进程和资源，交接后再继续，不按猜测解除占用。

构建完成后才运行专项，检查实际Finished/Built及退出码。每次验证记录准确源码提交和构建；产品源码变化后重新构建。串口专项finally恢复普通服务须检查真实成功，失败先修复/记录，不能直接跑依赖它的下个专项。
