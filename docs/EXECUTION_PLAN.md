### S1 用户流程与完成条件

目标流程：**打开软件 → 连接服务器 → 填写地址/用户名/认证 → 必要的指纹确认 → 进入终端**。

- 主界面和空状态始终看得到“连接服务器”主入口，键盘可达；不要求先建配置、理解Profile/Connection/Agent或切换多个工具面板。一个连接表单包含服务器、用户名、密码或密钥，端口默认22；编码、超时和其他参数按需展开。
- 点击连接后，连接中、主机身份确认、认证、成功或错误在同一流程展示；必要指纹确认不省略，指纹变化默认阻断，认证不明或拒绝不自动降级。成功后焦点进入终端，目标和状态看得见。
- 保存连接可选且不作为首登前提；“保存连接”和“记住凭据”分开，记住凭据默认关闭。临时密码/密钥口令不持久化、不进入日志或审计；明确保存的秘密仍由Windows保护存储管理，配置只含引用。明确保存后能够再次直接连接。
- 第一次试用者无需先读长说明即可找到入口并完成SSH2登录；正常密码、常用密钥/带口令密钥按所测方式成功，错误密码、不可达/超时、主机指纹变化给出易懂原因和恢复动作；不得把“已提交请求”显示成“已连接”。交互认证沿用同流程，其他服务器/算法兼容继续S5逐项追踪，不冒称全认证矩阵通过。
- 在新流程建立的同一连接上验证文本输入/中文、复制与粘贴、终端尺寸、断开、显式重连及保存后再次连接；不误发到其他目标，重连不重放命令，关闭/取消/迟到应答不恢复旧秘密或自动重连。原代次、request_id与统一队列仍在服务内部保持，不要求普通用户理解内部编号。
- 实际桌面构建后运行受影响SSH/终端专项并核对新表单/整条登录流程，不能只引用旧服务或旧面板测试。新流程必须有实际使用证据；合成回环用于自动覆盖，授权服务器试用由使用者在本地自行输入凭据。若缺少目标端点，仅明确阻塞对应真实验证，不索取用户密码、不虚报通过，其余S1独立实现/验证继续；未达S1门前不展开S2。
- Apple Mac方向以内容优先、清晰层级和统一控件落实，保留Windows/Xshell熟悉操作。基础连接和终端优先；Agent/MCP/审计/日志维护等高级入口默认收起、按需进入，保留已有能力及安全，不以“隐藏入口”代替权限。只收敛本阶段涉及界面；全局DPI/输入法等完整矩阵继续追踪，不为精修拖住可用SSH2交付。
