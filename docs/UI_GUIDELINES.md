### CR-022 桌面常用流程

以下是 CR-022 初期界面的阶段快照。工具与标签同排、旧菜单分屏、旧配色和反馈布局的后续调整见[现行桌面交互基线](#现行桌面交互基线)。

会话标签置于终端工作区顶边。活动标签和终端表面连续，标签可横滚。新建、日志、更多和连接库开关在同一行。底栏保留一行状态，详情以浮层展开。xterm 预编辑用浅蓝底、深色字和轮廓，沿用光标定位。连接库保存最近一次手动开合，工作区打开时可以恢复该布局的侧栏状态。新配置库采用浅灰界面和深色终端，主题与终端配色可分别保存。共享控件使用 14 px 正文、12 px 辅助文字、18 px 标题和 8 px 圆角。浮层使用共享阴影，日志进度与剪贴板反馈浮在终端上方。

连接表单在出错字段旁给出修正方法，连接期间在主按钮位置显示进度。必要的身份核验和当前挑战仍在原流程完成。日志菜单第一项保存保留缓冲，打开菜单时明确标示活动或点击的窗格。有选区的右键复制选区，顶部日志始终可从活动窗格进入。保存成功仅在原匹配目标短暂显示文件名与目录入口。

P15/v3仍用原MCP共享配对区，仅明确14工具/字节与显式控制说明；不新增默认动作、脉冲、自动控线或新的授权表单。配对不执行操作，WRITE/CONTROL独立，未知只查原编号；新结果connection须标明native请求绑定，不能作为服务/硬件独立证明。普通串口界面/控制线打开策略与原安全Break清理保持。

P15/v2保持原MCP配对共享details/fieldset/tokens，只更新固定12工具、独立exec/本人任务及未知只查说明。绑定不取租约、不发送或执行exec，不把配对快照说成实时许可；不增加模型自签或通用请求界面。任务工具的输出保护/状态/取消沿既有服务，正常连接/日志不依赖这些高级能力。

P22原生关闭回执沿共享Dialog/Panel/Field/tokens与原非模态反馈。保持活跃连接退出确认和原关闭时序；只有上次可用回执中的明确异常提示“上次本地服务关闭有需查看的信息”，正常不通知。详情从“更多工具→上次关闭信息”主动打开，单列原服务ID/北京时间、ACK/实际进程退出/强退请求及审计水位，缺失诊断只说未知。旧回执不冒充当前服务状态或最近崩溃，存储不可用不要求删除文件、不阻止连接、不恢复授权。

P21原生导入沿共享Dialog/Panel/Field/config-diff/tokens：默认冲突拒绝，选择系统文件不等于同意应用；新建无凭据醒目说明，三策略/源目标ID/完整字段/控制线均可核对，共享目录和凭据身份限制用明确兼容报告，不能混称库坏。目录null显示根目录，仅RTS null显示硬件管理；错误仅安全白名单，不回显任意解析异常/文件正文。关闭/重载只恢复原服务编号，不恢复策略/文件/同意，查询恢复的PREVIEW禁Apply。当前会话保留，关闭重读导航，无独立配色/字体。

P21批量修改沿共享Dialog/Panel/Field与tokens，精确ID选择不隐式全选，默认保持字段和无同意。差异以可换行的共享config-diff表格呈现字段/修改前/修改后，改变文字和加粗同时说明，保留字段单独概述；不把新旧值藏在同一限高JSON滚动区。恢复只显示原编号查询/取消，不恢复同意或启用应用；保存结果不明明确显示，不沿用“预览未写库”旧状态。关闭后重读会话树，活跃会话不重连。

P20窗口触发器复用共享Dialog/Panel/Field与tokens，四动作独立且默认全关；来源匹配与自动发送各有未默认勾选的独立同意。预览明确服务/真实来源/完整代次、有限正则跨度、冷却/次数及固定发送正文/目标。高亮只用共享selection token标记有来源证明的摘录，不按屏幕同名行冒认；旧命中保留自身完整来源。通知使用原非模态反馈样式，在当前dialog顶层可见；命中记录内存限额/不落盘和一次自动发送限制显著说明，错误在原共享ErrorNotice内显示。不新增色板、字体、历史重放入口或隐式启用。

P18连续同步从“更多工具→连续同步键盘”进入共享Dialog/Panel。默认无目标/许可，真实地址或端口/协议/编码与完整代次可核对，单独确认后才出现独立输入区；活动范围紧邻键盘区持续显示。使用原xterm字体/主题及tokens，无本地正文回显，进度只认服务回执。停止/Esc不群发该键、失焦/粘贴/关闭停尾；重启须新选择/预览。固定目标及逐目标计数/原编号沿共享details/状态文字，无新配色。

P19逐行节奏仅在原基础撰写的“发送节奏”折叠区提供原Field数字输入，默认0整批。预览显示本次间隔/片段数及保留草稿、可能仅发前缀；在途就地显示可信回执计数/停止尾部，复用现有控件与状态文字，不新增配色。明确不代表远端执行、不能撤销已发内容；关闭/切换不续发。

P17受管理分屏沿原“工作区”单弹窗保存/打开，不增加复杂编辑器；保存时明确临时/变化目标略过分屏，选中布局显示方向/活动项。打开只在原待连接条提示等待、可取消；两个指定项明确连接后一次恢复，焦点只在本意图仍有效且实际渲染就绪时切至保存活动项，不能反复抢焦点。手动布局/标签操作取消待恢复，缺失目标保持明确禁用，不猜同地址连接。实际弹窗/待连接/双SSH/混合截图已查看，旧“暂不保存分屏”为前一子包历史范围。

以下 P17 双窗格段落保留当时的菜单、样式与验证范围。现行分窗、重排及拖出操作见[标签与窗格基线](#现行桌面交互基线)，工作区双窗格恢复见上一段。

## 布局与操作

### 2026-11-07 全局 Apple Mac 设计方向

用户要求：“UI，视效和布局我希望能贯穿Apple Mac的风格和理念”。按 [CR-004](changes/CR-004.md) 将 macOS 风格与设计理念设为全局视觉方向，覆盖主窗口、导航、标签、工具栏、设置、任务、日志、授权、菜单、提示及弹窗；与 D04.1 的 Xshell 熟悉操作结构结合。现有实现和历史测试保留，是否符合新方向由后续实际桌面验证确定。

| 设计方面 | 全应用执行要求 |
|---|---|
| 内容优先与层级 | 终端保持视觉中心；以对齐、间距、字重和表面层级区分导航/内容/辅助操作。工具区紧凑，避免每个区域都用厚边框、大卡片或高饱和背景争夺注意力 |
| 布局与熟悉度 | 延续左侧可折叠会话树、顶部多连接标签、中央终端及底部状态；工具与设置按任务分组、按需展开，减少常驻多排按钮，常用动作保持可见或一步可达 |
| 配色与控件 | 全局采用协调的中性色表面和节制的强调色；圆角、分隔、阴影、图标尺寸/线条、控件高度与交互状态使用同一套共享变量和组件变体。深浅主题均保持文字/焦点/选中/错误的清晰对比 |
| 材质与视效 | 可在导航、工具区和浮层适度使用柔和层次/半透明材质；必须有清晰的不透明回退。模糊、透明或玻璃效果不作为完成条件，不叠加到终端正文，也不得造成高输出时输入或滚动退化 |
| 字体与细节 | 以稳定的字阶、字重、行高和留白实现精细排版，继续统一 Windows UI 字体链与终端等宽字体链；不为实现 Mac 观感要求安装或分发 Apple 字体/图标资源 |
| 动效与反馈 | 动效短促、连贯且服务于展开/收起/焦点变化；遵循减少动效偏好，无动效时功能等价。当前目标、连接/日志故障、授权范围和危险操作不因视觉简化而隐藏 |
| 交互与平台适配 | 保留 Windows 原生窗口操作、系统选择器、键盘/输入法和终端 Ctrl+C 语义；Mac 视觉方向不改变平台范围、快捷键约定或服务安全行为。所有页面使用相同的主次操作/取消/关闭及状态反馈规则 |

实施沿用现有 tokens.css、style.css、terminalAppearance 与 Panel/Field；先调整共享基础，再逐一核对既有页面，避免只改首页或某个面板。P12 收敛视觉基线，P14 及后续所有 UI 变更沿用；T22 验证操作效率与目标隔离，T23 追加全局 Mac 风格一致性检查及原主题/DPI/中文输入法矩阵。具体数值/材质方案由实施阶段的实际截图与交互验证确定，不在文档阶段伪造视觉验收。

设计依据：[Apple 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles/) 与 [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)（2026-11-07 核对）。其简洁、一致、熟悉、层级与细节原则作为参考；上表是在 Windows 终端应用中的项目约定，不代表改用 macOS 原生技术栈或已通过 Apple 平台认证。原 Windows 设计参考继续用于平台适配，视觉方向以本节为准。

- 采用现代桌面工具的清晰层级、克制配色和统一留白；终端是主要工作区。推荐左侧会话导航、顶部连接标签、中央终端、按需展开的辅助区域与底部状态栏；P12 按实际窗口尺寸落地，不增加新的功能承诺。
- 默认显示高频操作和当前任务所需信息。高级参数、诊断、独立 exec 任务及低频维护按需展开，不能同时堆叠挤占终端。连接与配置管理入口分工清楚，文案统一使用用户能理解的动作。
- 查找配置、连接、切换、输入、断开形成连续主流程；常用动作直接可达，避免同一动作多处含义不同或重复确认。身份/主机密钥/危险操作的必要确认保留。
- 当前连接名称、协议和状态清楚可见；发送前明确目标，切换/重连不把草稿或排队输入偷偷转给其他连接。SSH exec 与交互终端执行环境明确区分。
- 空状态给出下一操作；连接中、认证、失败、断开、输出缺口、日志故障和权限状态有文字说明及可用恢复入口。状态不只靠颜色区分，不用动画掩盖失败。
- 关闭辅助面板不隐式断开已连接会话，未完成登录可取消；点击会话标签关闭直接关闭原代次，不确认。程序退出及配置/日志删除保留各自既有规则。Agent 接管/撤销、广播范围等继续遵守统一服务约束，简洁交互不削减安全语义。

## 全局样式与字体

- P12 建立单一共享设计变量入口：语义颜色、字体族、字号/字重/行高层级、间距、圆角、边框、阴影、控件高度、焦点和动效。页面引用共享定义，禁止随意散落新的颜色值、字体和尺寸。
- 统一按钮、输入框、选择框、标签、列表、菜单、对话框及提示的外观和行为；同类控件各页面一致，主次操作和禁用/悬停/聚焦/选中/错误状态一致。
- UI 使用同一套全局字体族与中文回退链，候选为 Segoe UI、Microsoft YaHei UI / Microsoft YaHei、sans-serif；终端及需要等宽对齐的内容使用同一套等宽配置，候选为 Cascadia Mono、Consolas、中文回退、monospace。最终选择由 P12 的实际字形、宽字符和回退验证确定，不依赖用户额外安装字体。
- “字体统一”指有规则的全局字体体系：界面正文、标题、辅助信息各有固定层级；终端等宽字体独立于界面字体，所有终端实例一致。不得因页面不同任意换字体、字号或字重。
- 主题与字体设置统一作用于所属全局范围；深浅主题共享语义变量并覆盖所有面板/弹窗，终端 ANSI 色板保留可读性。避免仅换背景却遗漏文字、控件或焦点色。
- 采用统一间距尺度（建议以 4px 为基础）和有限字号层级；圆角、阴影和动效克制使用。实现时在共享定义内固定数值，不能让每个页面各自解释“现代”。不强制使用模糊、透明或玻璃效果，不以装饰降低终端可读性或输入性能。

## 可用性与执行证据

原生文件选择器使用Windows公共系统组件，由系统管理主题、字体和平台交互，不为单个窗口增加自定义配色或字体；此例外用于保持系统路径导航与可访问性。选择前后及覆盖确认、任务状态、错误/恢复路径仍使用应用共享控件与变量。P11.4原生另存见ADR-033；P12/T22/T23仍须记录系统组件与宿主在系统主题、DPI及字体设置下的实际表现，不能从默认系统选择器存在推断全局矩阵通过。

- 键盘焦点始终可见，Tab 顺序符合布局，图标按钮具有可访问名称，主要动作有可理解的文字或提示。长文本可换行、截断后可查看全文或滚动，不能盖住主要操作。

- 确有协议/状态语义需要特殊样式时，以共享语义变量或组件变体实现，记录用途与规范变化。不得通过隐藏错误、权限或目标信息来简化布局。

## P12共享实现入口（2026-11-05）

apps/desktop/src/tokens.css为唯一设计变量入口，style.css引用语义色/尺寸/层级及状态；appearance.ts从同一CSS读取xterm主题和字体，禁止新增JS独立色板。原生HTML按钮/输入/选择/文本域使用公共基样式，ui.tsx的Panel/Field用于统一面板标题/关闭入口与表单布局；新增导航、标签、提示继续复用。UI字体链Segoe UI→Microsoft YaHei UI→Microsoft YaHei；终端/快照/正文编辑器/指纹使用Consolas优先或Cascadia优先并系统中文回退，未安装Cascadia不安装字体。深浅/系统主题共用所有变量，焦点覆盖select/textarea/summary/链接，禁用悬停保持禁用状态，减少动效遵循系统偏好。

首步外观仅窗口暂态；当前按ADR-042在数据目录中保存主题/终端字体字号/复制粘贴习惯，编辑立即应用，明确保存后重载/启动读取并纳入配置备份。读取会丢弃未保存的窗口调整，失败/应答未知先查询不重发；正文/草稿/同意不保存。实际WebView和有限CSS viewport证据见[P12](records/P12.md)，不是完整T22/T23或真实DPI验收。当前首步仅显示基础；终端优先布局、会话树/标签/按需辅助区域、基础撰写和习惯选项持续落实，不能以共享变量存在替代主流程验收。


P12桌面壳采用ADR-040：全窗口终端优先grid、可折叠调宽会话树、可滚动/键盘切换基础标签、独立滚动辅助区和精确活动状态栏；全部沿用共享tokens。Profile选中与活动连接分离，隐藏视图不forget，close/退出确认保持服务语义。1100px以下打开辅助区时收起导航，850px以下采用侧栏/辅助覆盖区；这是CSS适应策略，真实分辨率/DPI和全部状态矩阵仍须T22/T23验证。工具栏水平溢出时可滚动/键盘到达，快照可显式关闭。实际证据见P12，不从布局代码推断完整验收。

P12偏好面板复用公共Panel/Field/fieldset，保存/读取及状态文字与全局样式统一。Ctrl+C选区复制可关闭；无选区保留终端中断，Ctrl+Shift+C/V始终可用，可选Ctrl+V/右键仍走受控粘贴；编辑偏好取消未发送预览。实际18入口及专项结果见P12，不能从偏好重载/服务重启通过推断P17工作区、全部UI状态或升级故障恢复通过。

P19活动连接常用命令使用更多工具中的共享Dialog/Panel/Field，不新增侧栏或常驻编辑器；Ctrl+Shift+K只打开。分组选择、变量填写、准备到原基础撰写、原预览确认逐步显示。已有草稿替换默认不勾选；保存、读取、选中和准备不发送。变量临时填写，模板持久化说明内联；关闭后不恢复变量或同意。


P18多目标发送作为独立共享Dialog/Panel/Field按需打开，默认无目标/正文/同意；按勾选顺序冻结并预览完整地址、协议、编码、代次/ID。人工接管影响明确且必须另勾选，不能继承单目标或常用命令同意。每目标显示独立编号/接受层级/未发/未知，取消只停未开始项，窗口内只保留末批结果；正文和许可不持久化。目标列表/正文/预览/回执依次排列，沿公共滚动与焦点，不另造私有色板。


P19选区发送仅扩原基础撰写：明确选择正文后显示可用的“预览选区发送”，无选区禁用，不替代全文入口。预览说明仅选片段/未选内容保留，不在用户流程显示内部UTF-16索引。改选区撤销对应同意；取消不改草稿，入队后仅移除该片段，未知不自动回填。共享字体/颜色/控件和原精确目标状态保持。


P19常用命令“准备到多目标”只转交文本/末尾/来源，和单目标准备并列但不自动扩目标或继承同意；接收方明确显示来源，默认空目标，再走原多目标预览确认，不新增重复确认弹窗。关闭清临时seed、普通重开空白；单目标目标/草稿替换及基础SSH/UART流程不变。
